## 1. 动因：R90 §9①

R90 交给本轮的建议是：

> **`--callgraph-max-edges`** —— 焦点子图**边数仍无上限**且比 R87 更严重：
> 内核默认根 **34 节点 / 19,469 边**、`hit_node_cap=false`。节点有上限、**边没有**
> ⇒ 「有界投影」只对上了一半。（R90 顺带证实：`truncated` 块里 `fan_in/out` 有
> `shown/total`，而 `focus_subgraph` 没有对应的边上限参数。）
> ⚠ 红线：**不给开关时产物逐字节不变**，否则会破坏 R90 刚建立的跨轮回归。

⚠ 那条红线**本身就是本轮的第一个缺陷**（见 §3.4）。

## 3. 修法（以及**不许**怎么做）

### 3.1 只裁边、不动节点

截断点选在**边收集那一步**（`if a in keep and b in keep` **之后**）—— BFS 一个字不改。
于是 `nodes` / `nodes_shown` / `hit_node_cap` 与「不设上限」时**逐位相同**。
判据 F10m 的 ③ 半边与两个变异体都钉着这条（M16c 会连带把节点也改掉吗？不会 ——
这正是它的价值：它证明「只裁边」是有**具体**半边守着的）。

### 3.2 `edges_total` 必须与 `edges_shown` **同源**

新增的 `edge_total` 是**收集计数**（两端都在 `keep` 里的边数），**不是**另算一个数。
不设上限时它恰好等于 `edges_shown` ⇒ 「丢了多少」永远不必从第二个、口径不同的数里读。
F10m 的 ② 半边直接断言 `edges_total == ed_def`（= 不给上限时的边数），
坏样本里专门有一条「分母不同源（另算一个数）= 4」。

### 3.3 三个键是**条件键**，不是「漏写」

`max_edges` / `hit_edge_cap` / `edges_total` **只在 `max_edges > 0` 时**才进 `truncated`。
理由写在代码注释里且是**可反对的**：不设上限时它们只能是常量（`0` / `False` / `== edges_shown`），
带上去纯属噪声，却会把 R90 建立的**跨轮回归**当场作废 —— 那是**刻意**的条件键。

### 3.4 计划里那条红线**不可能成立**，于是换成更强的

```
计划：不给 --callgraph-max-edges 时产物必须**逐字节不变**。
冲突：CALLREL_VERSION 按「形状版本：键的增删改都要 +1」必须 3 → 4，而 version 在产物里。
```

三条路只有一条能走：

| 选项 | 为什么不行 / 行 |
|---|---|
| 不涨版本 | **不行**：违反既有的形状版本规矩，等于把「键变了」这件事藏起来 |
| 把红线删掉 / 装作没写 | **不行**：那是**悄悄放宽**（R90 的教训：「改正量具」与「放宽判据」必须能分开） |
| **换成更强的判据** | **选它**：差必须**逐字节定位在 `version` 上（恰 1 字节）**，其余一个字节都不许动 |

具体化为**两向**装置 `_r91/verify_default_byteeq.py`：
折掉 `version` 后逐字节相等 **且** 原始字节**必须不等**（否则「折掉后相等」是空判据）。
外加第三态：负值上限 ⇒ `rc=1` 且**不产出文件**。
⚠ 这条红线**同时改进了可证伪性**：原来的「逐字节不变」在**任何**产物改动下都红，
而现在它精确到「只许动那一个字节」—— 更强，不是更弱。

### 3.5 CLI 三态语义（与 `--lib-resolve` / `--callgraph-identity` 同源）

* **不给** `--callgraph` ⇒ 仍是**无操作** ⇒ 新校验**刻意放在** `if not out` 那条
  early-return **之后**（这是一句写在 docstring 里的承诺，不该被新开关悄悄改掉）；
* 非整数 / 负数 ⇒ `[ERROR]` + **非零退出** + **不产出文件**（不静默当 0）；
* 合法值 ⇒ 原样传下去。

## 4. 判据 F10m：四个半边 + **自维持**

夹具（`CG_EDGE_FIXTURES`）：**1 个 `hub` 扇出 6 个叶子**，深 2 ⇒ **7 节点 / 6 边**。

| 半边 | 断言 | 对应的坏样本 |
|---|---|---|
| ① 默认形态**不许变** | 不给开关 / 显式 `0` 时 `truncated` 键集**恰好**是 R90 那四个，且 6 条边一条不少 | 「默认形态就多出上限键」「显式 0 被当成真上限」「默认形态收不全边」 |
| ② 给了 `N` 必须**显式上报** | `len(edges)` 恰为**先遇到的** `N` 条；`hit_edge_cap=true`；`max_edges` 回显；`edges_total` **同源** | 「静默不截断」「不上报 hit_edge_cap」「不给分母」「分母不同源」 |
| ③ **只裁边、不动节点** | 节点数与节点名**逐位相同**，`hit_node_cap` 不许被顺带点燃 | 「上限把节点一起裁了」 |
| ④ **开关在册** | **AST 现读** `matlabc.py` 的 argparse 首参（注释里写开关名骗不过） | 「CLI 上没有这个开关」 |
| ⑤ **判据不许变空断言** | 夹具读数拿不到时由 F10m 自己报红 | 「拿不到边上限夹具读数」 |

**自维持**（R90 的教训，本轮第二次用）：手推的「7 节点 / 6 边」不是写在判据里的常量，
而是由 `judge_fixtures` 的**夹具完备性**守着 —— 叶子定义**恰好 6 份** + 枢纽把每个叶子**各调一次**。
夹具一改（多一个叶子、少调一次），F10m 里那几个手推数字**当场变红**，不会变成谎话。

⚠ 子判据循环里加了 `"F10m"`（覆盖不许**静默缩水**）⇒ `--selftest` 计数
**130 → 140**（+10 = 新增的 10 条坏样本）。

## 5. 变异体 M16a / M16b / M16c：三条决定各一个

| 变异体 | 拆掉的决定 | 注入方式（**语义错误，不制造异常**） | 证人 |
|---|---|---|---|
| **M16a** | 「给了上限就必须**真的**截断」 | 只翻一个符号：`if cap > 0` → `if cap < 0`（`max_edges` 键**照样**出现，只是**一条边也不裁**） | F10m ② |
| **M16b** | 「分子与分母**同时在场**」 | 删掉 `hit_edge_cap` / `edges_total` 两行（产物仍合法，只是「截掉了多少」无从判断） | F10m ② / ⑤ |
| **M16c** | 「默认形态**不许变**」 | `if int(max_edges or 0) > 0:` → `if True:`（值全对，**只有键集**错） | F10m ① |

实测：**3 条全部「注入即红（红只落在 F10m）且还原即绿」**，基线副本先证绿，总用时 143.5s。

⚠ M16a **刻意不去动** `int(max_edges or 0) > 0` 那半边 —— 否则 `max_edges` 键会一起消失，
M16a 就同时踩了 M16b 的地盘，证人**不再专一**（装置判「红在别处 = 失败」）。

## 6. 实测

### 6.1 合成夹具（R91a · **先于产品**）

`_r91/measure_edgecap.py` **不 import 产品新代码**（R82b：两本账共用一个错口径会永远对得上），
预登记了六条期望。改动**前**（`_r91/preregister_r91a_dev1.log`，rc=1）：
`--callgraph-max-edges` **不在册**、B/C 退出码 2；而 A 形态已是 **7 节点 / 6 边**
—— **手推值在实现之前就命中**（这正是预登记的意义）。
改动**后**（`_r91/measure_edgecap_r91post.log`，rc=0）：
`[B] 上限 3 rc=0 7 节点 / 3 边 trunc={... "max_edges": 3, "hit_edge_cap": true, "edges_total": 6}`
⇒ `PREREGISTER OK`。

### 6.2 默认产物 vs R90：**折掉 `version` 后逐字节相等**（两向）

`_r91/verify_default_byteeq.py` 用 `git archive HEAD` 物化 R90 定稿（**不动真树**），
两条臂跑同一夹具同一 argv：

* `R90 产物 8343 B / R91 产物 8343 B`；`version: R90=3 → R91=4`；
* **折掉 `version` 后逐字节相等**（8343 B）；
* **原始差：第一处偏移 41**（落在 `version` 上下文中），长度差 `+0 B`；
* `[负值上限 -1] rc=1 产物存在=False`；
* 装置自己的两向自证：`SELFTEST COUNTS {"bad": 4, "good": 1}`。

⚠ 一条**被否证的预测**：我原以为「差恰 1 字节」意味着**长度差 1**；实测长度差 **0**
（`3` → `4` 是**同位数**替换）。⇒ 「差 1 字节」与「长 1 字节」是两件事，
前者才是判据要的那条。

### 6.3 内核整树：跨轮回归（只差 `version`）

R91e 重跑整棵 Linux 6.19.14（被测物 `matlabc.py` sha16 `f01fff25077ec23e` / HEAD `92394012a3f4`）：

| 项 | R91（本轮） | R90 | 结论 |
|---|---|---|---|
| `kernel_c_summary.json` 读数 | 62,704 文件 / 743,509 函数 / 7,060,966 边 / 1,295,143 未解析 / 1,262,817 启发式 | 同 | **逐位相同** |
| `kernel_c_summary.json` sha16 | `9a6bd04cfd6c7341` | `9a6bd04cfd6c7341` | **逐字节相同** |
| `kernel_callgraph.json` | 4,358,990 B / `c426096624900f81` | 4,358,990 B / `23dddd8b2552a0a0` | 见下 |
| c 臂 `peak_mb` | **13,143.6** | 13,143.6 | **逐位相同** |
| c 臂 `seconds` | 1,879.7 | 1,293.1 | **不可裁决**（见下） |
| asm 臂 | 1,369 文件 / 3.0 s / 486,229 B | 同 | **逐字节相同** |

**红线的正面读数**（与 `_r91/verify_default_byteeq.py` 的 `calc_byteeq()` 同一条判据，现算）：

```
R90 快照 : 4358990 B  sha16=23dddd8b2552a0a0
R91 产物 : 4358990 B  sha16=c426096624900f81
```

**`4 / 7060966`** —— **五档之和逐位不动，动的只有 version**。这就是「只加限、不改分析结果」的图面证据。

⚠ **墙钟 1,879.7 s ≥ R90 的 1,293.1 s，不归因**：本轮跑批的 22:15–22:47 期间，同一台机上

可比的量是 `peak_mb`（内存峰值不受同机 CPU 负载影响）：**13,143.6 MB 逐位相同**。

⚠ **顺带记下生成器的一处既有代价**（本轮**未改**它）：`KERNEL_RUN.md` §1 那张「三个都对的口径」表

### 6.5 最不起眼、也最危险的一条：**装置第二次抓到同类自伤**

`_r91/patch_gate_f10m.py` 把 F10m 那一整段注释**插在** HEAD 里

```

```

那一行的位置，**却没有把它重新写出来** ⇒ F10j 的标题行、连同它上面的 `# ---…---`
分隔线一起被吃掉。三件「看起来够用」的手段**全都看不见**：

* `ast.parse` 抓不到（注释不进 AST）；
* 门的真跑读数**逐位不变**（`--selftest` 仍是 `{"bad": 0, "good": 140}`）；
* `git diff` 也不是工具（它按同一套规则把两侧都归一化）。

只有**逐行对账**（`_r91/verify_patch_shape.py`）看得见。修法 = 把那两行**原样补回**，
于是本轮 `tools/check_c_frontend_shapes.py 注释失 0`。

| # | 判据 | 为什么 |
|---|---|---|
| ① | 未登记的被删注释 ⇒ 红 | 装置原本的功能 |
| ② | **陈旧登记**（登记了但当次并没有被删）⇒ 红 | 它让覆盖**看起来**还在，与「忘了登记」是同一件事的两面 |

—— 又一次「**先问量具错还是对象错**」：这次是**量具错**（符号写反），对象（`judge_records`）是对的。

## 7. 手一滑就会踩的五条（本轮新增）

1. **「默认不变」这类红线，先看仓库自己有没有跟它冲突的规矩**。
   本轮的冲突是 `CALLREL_VERSION`；下次可能是产物里的 `schema` / `mtime` / 计数。
   冲突时的正确动作是**裁决 + 换成更强的判据**，不是删红线，也不是偷偷涨版本。
2. **量具的尺度必须与门的口径一致**。`_r91/measure_help_r91.py` 第一版把 **80 列**那次
   读数拿去折规范形，于是 `matlabc_flow.py` 读出 **1703**（快照 1701）——
   真相是门对臂 ③ **另起一次** `COLUMNS=10000` 的运行，而 80 列下 argparse 会**在词内硬断行**
   （`_CANON_WS_RE` 把那段换行折成一个空格 ⇒ 规范形反而变长，正是 R89 登记过的那条边界）。
   数字自己报了警 ⇒ 修法：**两条臂各跑一次**。
3. **子串包含会让「负向判据」假绿**。验证「抠掉 `--callgraph-max-edges` 后判据必须红」时，
   我把文本替换成 `--callgraph-max-edgesX` —— 而 `"--callgraph-max-edges" in "...X"` **为真**，
   于是判据**照样绿**。改成**整行删除**后才真的红。教训与 R90 的「收尾核验只认整行」同源。
4. **手写的清单一定会腐烂**。`tests/test_matlabc.py` 里那条「GUI 帮助正文必须提到这五个开关」
   是**手写**的 —— 于是新增第六个开关时**谁也没记得回来加一行**（R91 就是这么发现 GUI 少一格的）。
   改成**从 CLI 现读**（AST 读 argparse 的真实首参）⇒ 新开关**自动**产生一条界面义务。
5. **「折掉某个字段后相等」必须配一条「它真的变了」**。否则那个判据在**两版完全相同**时
   也成立 —— 它退化成「文件没变」，什么都没证。

## 9. 下一轮（R92）候选，按价值排序

1. **被调侧的「同文件」消歧** —— R89 的 rung 1 只解**调用者**侧；`resolve_calls` 取的是
   `func.name`、**没取** `file.rel` ⇒ 被调侧多定义时判不出（内核 **72.9%** 的 `ambiguous`
   卡在这）。这是唯一能让那个数**真正**掉下来的路。判据**两向**：`ambiguous` 下降
   **且** `edges_total` **逐位不变**，并同时报出「有多少条是同文件可消歧的」
   （否则「减少了多少」没有对手方）。
   ⚠ **先问口径**：`edges_total` 逐位不变这条在 R89 已经用过一次，别把它当成新证据。
2. **R87i 的归属修复** —— `decl_start` 被钉住 ⇒ 一个根因三症状（`typedef` 误判已修 /
   `line` 错位 / `ret`+`calls` 归属被撑大）。修它要先把「归属从函数体 `{` 起算」
   设计成**判据**，否则就是又一次「改完所有读数一起动、且都自洽」。
3. **整条 argv 进 `docs/KERNEL_RUN.md` 登记表** —— 现在登记了 `cwd` 口径与 provenance，
   但**没登记**那一串 `--callgraph …`。R90 正好证明 argv 会改变产物（多一个 `--callgraph`
   就让 `cwd` 敏感度**可见**）；本轮又添一个同类证据（`--callgraph-max-edges` 会改变
   `truncated` 的**键集**）。⚠ 登记 argv 意味着**产物可复现性**多了一个维度。
4. **`--callgraph-max-edges` 的 GUI↔CLI 双向** —— 现在只钉了「CLI 有的 GUI 帮助里必须提」；
   反向（GUI 能填的键必须是 CLI 认的）还没有对手方。
5. **`js/await` → `join`**（2,039 条 = 78.2%）—— 两向断言：`join` 上升 Δ **且** `async` **不变**。
6. **`truncated` 的「分子/分母」在顶层补齐** —— 顶层的 `fan_in/out`、`cycles` 已有
   `shown/total` 对；`nodes_shown` 有「分子」但**没有**顶层的「分母」（`nodes_total` 在
   `call_relations` 那一层，不在 `truncated` 里）。把两处口径**并成一份**是有价值的收口。
7. **REA 能力族继续外挂化**（ELF 重定位 / GOT / PLT → EVM selectors → .NET CIL →
   JS/Electron → HAR）—— D 修地基 → B 外挂化 → C MCP 联邦。
8. **`KERNEL_RUN.md` §1 留下历史读数**（本轮实测到的**装置层**代价）：那张表只保留**最近一次**，

   禁止归因版本」—— 只留一行**没有**交替可比，纪律就没有落脚点。修法：改成**追加式**行（带轮次标签），
   W5 断言改成「至少两行、且相邻两轮口径列一致」。
