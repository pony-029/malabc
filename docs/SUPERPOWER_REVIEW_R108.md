## §1 为什么这两件事必须**合轮**（不是省事，是被判据逼出来的）

R107 §9 项 1 已经点明：`matlabc.py` 帮助正文是唯一被 **W2** 卡住的改动 ——
改它任何字节 ⇒ `check_kernel_snapshot` 的 `provenance.matlabc_sha256` /
`matlabc_bytes` 当场对不上 ⇒ 必须重跑整树。

**推论（本轮把它立成结构性约束）**：
> **凡是动 `matlabc.py` 的一轮，必须与「整树重跑」同轮；反过来，不动 `matlabc.py`
> 的事（台账入库、文档口径、判据加严）应当单独成轮。**

于是本轮把 R107 留下的两件事**合并**：

| 项 | 内容 | 为什么能合 |
| --- | --- | --- |
| 项 1 | `--callgraph` 帮助正文写「MATLAB 也产出」 | 只动**文案**（字符串字面量） |
| 债 ③ | `_SITE_DESC` 写死 MATLAB 措辞 | 只动**文案**（常量 / docstring） |

两者都**对分析产物惰性** ⇒ 一次重跑就能给出「产物逐字节不变」的强结论；
拆两轮 = 白跑两个 51 分钟。

## §2 白帽读数：缺陷是**双重**的（这一段改变了整轮的实现方案）

按纪律「**先量清楚再动**」，本轮先用只读探针量了一遍。
探针**复用门的夹具**（`tools/check_parity_registry.py::FIXTURES` + `run_fixture`）——
不人工挑候选集（㉛）。

修前实测：

| 语言 | 有 description 的页数 | 措辞 |
| --- | --- | --- |
| MATLAB | **55/55** | **全部含 MATLAB 措辞** |
| C | **0/26** | — |
| Python | **0/22** | — |
| JavaScript | **0/22** | — |
| **合计** | **55/125** | |

⇒ 读出来的是**两个**缺陷，而不是一个：

1. **错误的措辞**：`_SITE_DESC` 是一个全局常量，写死 `MATLAB 代码静态分析站点…`。
2. **缺失的覆盖率**：`_finalize_site_html` 的**唯一**调用点在 MATLAB 的
   `render_browse_site` 里 ⇒ `_emit_lang_site`（C/Py/JS 的站点出口）
   **一次都没调** ⇒ 三语言站点**一页都没有** description / OG。

> ⚠ 这是本轮最重要的一条读数：**只改常量一个字都修不好**。
> 如果按直觉「把 MATLAB 换成语言名」就交差，覆盖率仍是 55/125。
> 这正是「**先量后改**」在实处的价值 —— 直觉判断错了，而且错在**方案**上，不是错在细节上。

修后实测：**125/125**，措辞逐语言对上是 `MATLAB …` / `C …` / `Python …` / `JavaScript …`。

## §3 实现：把横切收尾路径接到三语言**自己的站点出口**上

### 3.1 `matlabc.py`（14 块改动）

**描述按语言给**：

```python
_SITE_DESC_FMT = "%s 代码静态分析站点：函数索引、调用关系、依赖与质量全景"
_SITE_SHORT_FMT = "%s 静态分析站点"
_SITE_DESC_NEUTRAL = "代码静态分析站点：函数索引、调用关系、依赖与质量全景"
_SITE_SHORT_NEUTRAL = "静态分析站点"
_SITE_DISPLAY = {"matlab": "MATLAB", "c": "C", "py": "Python", "js": "JavaScript"}
_SITE_DESC = _SITE_DESC_FMT % _SITE_DISPLAY["matlab"]      # 兼容既有引用

def _site_meta(lang=None, display=None):
    name = _SITE_DISPLAY.get(lang) or display
    if not name:
        return _SITE_DESC_NEUTRAL, _SITE_SHORT_NEUTRAL
    return _SITE_DESC_FMT % name, _SITE_SHORT_FMT % name
```

**两个设计期预警（都在落盘前改掉了，未触发）**：

* `_d = desc or _SITE_DESC` **必须**放在函数体顶部、遮蔽 `<script>`/`<style>` **之前**。
  放进 description 分支的 `if` 里 ⇒ 「description 分支没进、OG 分支进了」会 **NameError**。
* `lang == None` **不退回 MATLAB 措辞**（那正是本轮修掉的错），退回**中性**措辞 ——
  由新用例的五个负样本钉住。

**逐页收尾钩子**：

```python
def _finalize_site_page(path, desc, short):
    """对**单个**已落盘页面补横切元信息（幂等）。返回是否改动（0/1）。
    ⚠ **按字节读写**，不显式指定换行：这一支可能落在 `_write_text` 写出的
    **LF** 站点页上，也可能落在那份 `io.open(..., "w")` 写出的旧单页上
    （Windows 下是 CRLF）。指定任何一种换行都会静默改写另一种。
    """
```

**接线**：`_emit_lang_site` 里按 `lang` 取描述、构造 `_fin_page` 钩子并透传给
`render_c_site`；**MATLAB 侧改从 `_site_meta("matlab")` 取** ⇒ 四语言走**同一条代码路径**
（不再有一支例外 —— 这是本轮真正的结构性收益，不只是修好一个字符串）。
旧单页 `c_report.html` 不经过钩子，单独补一次；薄索引**不补**（`render_c_site` 会覆盖它）。

### 3.2 `renderers/csite.py`（3 块改动）

```python
def render_c_site(..., skip_index=False, src_subdir=u"src", finalize_page=None):
```

`_emit` 在 `_write_text` **之前**收尾。理由：`n_bytes += _emit(...)` 就是本模块对外的
「站点多大」，事后补会让它**少算几百字节/页**，而且**没有判据看得见**。
不给 `finalize_page` ⇒ 逐字节等于 R107 的产物（本模块**不** import `matlabc.py`，避免反向依赖）。

## §10 我自己的错（先问量具错还是对象错）

### 第 31 次量具错：解析别人的表格前没读表头

数对等表还有几格 `no` 时，直接 `awk -F'|' '/^\| `/ && ($4==" no " || …)'`，
**假定表有 5 个语言列**（脑里带着「asm 也有一列」的旧印象）。实际表头是
`| 能力 | MATLAB | C | Python | JavaScript | 怎么测的 |` ⇒ **4 个语言列**，
于是列号含义全错，捞出 4 行并报「只有 4 行」，而记分牌写的是 **7 格**。

* 纠正：**读一次表头**即对上 7 格 = **JS 4 + MATLAB 3**。
* 教训：**解析表格先读表头**；数量与记分牌不一致时，**先怀疑自己的列口径**，
  而不是急着解释「为什么是 4 不是 7」。
  「门自己报的数」是现成的对手方 —— **我没先用它**。

  报红先看「是不是我喂错了」，而不是先去解释对象为什么「这么严」。

### 第 34 次量具瑕疵：跨轮比较用 `zip()`，长度不等时**整体错位**

回证脚本第一版在 NEGCTRL 段打印「逐文件不同 **274** 条」—— 而这个数字是
`zip(上一轮条目表, 本轮条目表)` 在 **322 vs 323**（本轮新增了复盘文档）时的
**错位产物**：长度不等 ⇒ 从新增点起逐位配错，计数**没有任何含义**，却长得像读数。

* **先问量具错还是对象错** ⇒ **量具错**。④ 那一处 `zip` 之所以**合法**，是因为它比的
  是**本地 vs 远端**两张**同长**表（且上一行刚断言过同长）；这里比的是**跨轮**两张
  **不同长**的表 —— 换个场景就必须换口径。
* 纠正：跨轮一律走 **map 差集**（`entry_map` 的键差集）⇒ 11 条 ≡ 变更集合 11 个；
  并在 ④ 的 `zip` 旁写清「合法前提：同长 + 有序」。
* 教训：**比较的两个集合必须可比** —— 这是 R104 ㉝「两个操作数必须同量纲」的**集合版**。
  一个**看起来像读数**、但推导链里藏着「长度相等」假设的数字，比没有数字更危险。
* **派生教训（同一条判据的第二次修）**：给新判据配的构造样本，要选**任何轮次都能触发**
  的形式。第一版 NEGCTRL4 靠「去掉一个真实的新增路径」制造不符 ⇒ 在「本轮一个文件都
  没新增」的轮次里**只能 SKIP**，判据等于没被执行。改成在**真读数**上人为 +1
  （与有没有新增无关）⇒ 每轮都能跑。
