> 本轮靶子 = R66 §8 的 **C16-1**（最高优先三条之一）：
> 「给 py / js 扫描器加**字符串与注释状态机**，杀掉**过度识别**
> （docstring / 块注释里独占一行的 `def` / `function` 被当成真函数），
> 并在第 16 道门里加一条判据钉住它。」
>
> R66 自己量出这条缺陷（**2/6 泄漏**）、用 `git worktree` 对照确认**基线就有**、
> 但**没修** —— 它把修法留给了下一轮。R67 就是那一轮。
>
> ⚠ 本轮**不是零产品变更轮**：`matlabc.py` 的两个词法扫描器各前置了一层状态机
> （+7 个新定义 / +3 个助手函数），用户可观察行为有变化（原本被误认的假定义消失了）。

**机理**：扫描器**按行锚定**（定义必须落在行首、且行首是「代码」）。单行字符串与 `//` / `#`
行注释天然只影响本行 ⇒ 定义落不进行首；而**三引号字符串**、**跨行块注释**、**模板串**
在 R66 里**没有任何人跟踪**，于是它们内部独占一行的 `def` / `function` 直接命中行首。

> ⚠ 口径提醒：R66 §1.5 记的是 **2 / 6**（它只测了 6 个用例）；R67 的 12 个用例是**更大的一台装置**，
> 所以这里是 **7 / 12**。两个数**都对**，分母不同；不要拿 7/12 去「纠正」2/6。

### §1.2 根因：R66 的扫描器只做「括号配平」

R66 的 `_scan_py_defs` / `_scan_js_defs` 是这样起手的（逐字）：

```python
while i < n:
    s = lines[i].strip()
    if not s or s.startswith("#"):        # ← 只看「行首是不是 #」，不看「是不是在字符串里」
        i += 1
        continue
```

`_scan_js_defs` 的等价写法是 `s.startswith(("//", "/*", "*", "#"))` —— 它排除了
**以 `*` 起手**的续行，但排不掉「块注释内部那些不以 `*` 起手的行」。
一句话：**判据是「这一行长什么样」，而正确的问题是「这一行在不在代码里」**
（与 R66 的 D1「把函数头当成一整行」同源：都是**把行当成语义**）。

## §2 黑帽：这一版**不解决**什么（诚实列表）

1. **状态机只认三类跨行构造**：Python 的三引号、JS 的块注释与模板串。
   它**不认**：Python 的显式行连接（反斜杠续行）、JS 的**正则字面量**（`/…/` 里含 `/*`、
   `//` 会误判）、JS 的**标签模板**、以及「默认值本身就是跨行三引号」这种畸形定义。
   这些都是**已披露边界**，不是遗漏（C17-1 立一条「必须红」的坏样本钉住）。
2. **只处理「行首在不在字符串里」**：定义必须落在行首，所以「同一行里字符串之后又写 `def`」
   不构成风险；但**行内**的字符串/注释对**调用收集**的影响只通过「整行跳过」间接解决。
3. `ret` 仍是常量（Python 恒 `None`、JS 恒 `void`）—— 与 R66 相同，本轮不碰（C16-3）。
4. `complexity` 仍只是关键词计数，不是 CFG（C16-3 同源）。
5. `matlab` 路径（默认语言）**仍没有形态门**（C16-7）。
6. **形态集合仍是我挑的**（py 8 / js 10 / c 6）——它自己**没有对手方**（C16-2）。
7. 本轮**没有**给探针加自证（C16-13）—— `probe_r67_overrecog.py` 依旧是「我写的、我信的」。
8. **B 类永久红**（`check_known_red` 里 6 件从未提交的产物）本轮**无决策**（C16-6，要用户拍板）。
9. **`node_modules` 仍会被走**（只跳隐藏目录）—— 真实大仓上的表现没量过（C16-4）。
10. **签名命名空间没有登记**：「两道门各取 `G1–G7`」这件事只有 **P5 的『完全相同』判据**
    能抓；`G0–G3`（patch_ops）与 `G1–G7`（import_graph）**族名重叠**却**放行**（C17-2）。

## §3 落地物（全部真实现，无占位符）

### §3.1 产品：一层「行首是否在代码里」的状态机（`matlabc.py`）

| 新定义 | 职责 |
| --- | --- |
| `_skip_str_span(s, i, quote)` | 从 `s[i]` 起跳过一段**单行**字符串（处理反斜杠转义）；未闭合返回 `len(s)` |
| `_py_code_mask(text)` | 逐行返回 bool 表：该行**起始处**是否在三引号字符串**之外**。只认成对的三个引号（单/双）与成对单行引号；`#` 之后视为注释 |
| `_js_code_mask(text)` | 同上，JS 侧跟踪跨行块注释与反引号模板串；行注释只影响本行 |

接线（**四处**，都是「加一层面具」而不是改逻辑）：

| 位置 | 改动 |
| --- | --- |
| `_scan_py_defs` | 循环开头 `if not mask[i]: i += 1; continue` |
| `_scan_js_defs` | 同上（JS 版 mask） |
| `_parse_py_source` | 逐行循环加 `if not _mask[idx]: continue` —— 落在字符串里的行既不是定义、也不该贡献调用 / 复杂度 |
| `_parse_js_source` | 同上 |

> 「**新写一个判断，而不是改老判断**」是这里的关键：四处的**主逻辑一行未动**，
> 风险面被压到「面具错判」这一件事上，而它由 §1.4 的两向读数直接照着。

同时把 `_scan_py_defs` / `_scan_js_defs` 的两段**披露**改写 —— R66 的原文是
「只做括号配平，不做字符串状态机……这是**已披露边界**」；R67 改成
「已加状态机，守它的是 **G7**」。**改产品却漏改披露，就等于承诺与行为分叉。**
