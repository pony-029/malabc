# 突破性方向分析（基于当前真实基线）

> 方法：六顶思考帽 → 头脑风暴（6 个候选）→ 收敛矩阵 → 三期路线
> 日期：2026-10-19
> 基线：0.8.1，33 道门 / 206 条判据 / 60 个场景 / 16 个变异；单文件分析器零依赖

---

## 0. 先诚实列出当前基线（白帽）

| 维度 | 现状 | 意味着什么 |
| --- | --- | --- |
| 分析能力 | 调用图、字段流、全局变量、跨语言（C/mex/DLL/ELF）、诊断、热点 | **广度已经够**，不是瓶颈 |
| 速度 | 1676 文件全量约 **70 秒**；增量已有一致性门 | **即时感的天花板** |
| 入口 | CLI / LSP / MCP(19 工具) / HTML 报告 | 入口够多，但**彼此独立** |
| 写能力 | propose→apply→undo，批量事务 | **只有 AI 能触发**，人用不上 |
| 自证 | 33 门 + 206 判据 + 变异抽样 | 工程纪律是强项 |
| 知识沉淀 | 每次全量重算，结论不落盘 | **没有"积累"** |

**一句话**：这个项目的强项是「把代码读准」，弱项是「读完之后呢」。

## 1. 六个候选方向（头脑风暴，不做筛选）

| # | 方向 | 一句话 | 用户为什么会要 |
| --- | --- | --- | --- |
| A | **增量内核**（stamp 数据流） | 每个函数有指纹，只重算受影响的子图 | "我改一行，为什么要等 70 秒" |
| B | **可执行知识库** | 分析结论落成可查询、可版本比较的图 | "上周这个依赖关系变了吗" |
| C | **事务化 Agent 工作流** | 把 19 个工具组合成带校验/回滚的"任务" | "让它帮我重构，但我要能审" |
| D | **证据分级与可反驳性** | 每条结论带证据级别 + 一条命令可复核 | "这个结论凭什么" |
| E | **跨语言语义等价检查** | 检查 MATLAB 侧与 C 侧的数据布局/ABI 是否一致 | "改了 C 结构体，MATLAB 那边会不会炸" |
| F | **活文档编译器** | 每次提交生成"这周工程发生了什么" | "新人入职三天看不懂这个库" |

## 3. 结论：一条主线的三期

单点最强的是 D，但它**单独不构成突破**（它只是把已有能力说清楚）。
真正能改性质的是 **C（事务化 Agent 工作流）**，而它**依赖 A（增量）**才不难受。

```
一期（地基）  A：增量内核 —— 把 70 秒拆开，先量后改
二期（差异化）C：任务化 —— 从"19 个工具"到"5 个可审计任务"
三期（复利）  B+D：结论落盘 + 可反驳 —— 知识开始积累
```

### 3.1 为什么不是"再做更多分析能力"

广度已经足够：调用图、字段流、跨语言、诊断、热点都有。
**再加一类分析，用户不会因此换工具**；而"改一行要等 70 秒"和"AI 改了我不敢信"是**会让人放弃**的两件事。

### 3.2 一期（增量内核）的具体第一步

**不是先改代码，而是先加计时。** 现状只有"70 秒"这一个数字，没有分解：

```
扫描文件 / 解析 AST / 建调用图 / 字段流 / 跨语言 / 诊断 / 落盘
```

每个阶段单独计时并打印（`--timing`）。**没有这一步就动刀，等于在黑暗里猜哪个阶段该优化。**

### 3.3 二期（任务化）的形状

现在 Agent 要做的"重构"是这样拼的：

```
impact → outline → propose_edits → apply_edits → （自己挑测试跑）
```

二期把它变成**一个任务**：

```
task: rename-function old=new
  prepare   影响面 + 需要改的文件清单（人可审）
  validate  改完后再分析一遍，diff 零新增告警
  apply     原子写入
  rollback  任一步失败自动回滚
```

**关键差异化**：每个任务都**自带验收条件**（用已有的 206 条判据/33 道门那套思路），
而不是"改完你自己看"。这是别的工具给不了的 —— 因为别人没有这套自证体系。

### 3.4 明确不做

| 不做 | 理由 |
| --- | --- |
| 再扩语言支持 | 广度已够，边际收益低 |
| 自研编辑器 UI | VS Code 扩展已足够，做 UI 是另一个产品 |
| 云端服务 | 违反"零依赖、离线优先"的定位 |
| 大模型微调 | 与"确定性分析"的定位冲突 |

---

## 4. 风险（黑帽）

| 风险 | 缓解 |
| --- | --- |
| 增量算错但更快 | 已有 `check_incremental_parity`（增量 vs 全量逐项相同）—— 这是先决条件，必须保持绿 |
| 任务化把简单事情做复杂 | 任务只包"已经有人手工做过三遍"的流程，不发明新流程 |
| 证据分级变成文字游戏 | 每条等级必须能被一条命令复核，否则不许标 |

---

## 5. 一句话

> **这个项目的下一个台阶不是"看得更多"，而是"改得更敢"。**
> 而"敢"来自两件事：**快**（增量）与**可回滚**（任务化）。
