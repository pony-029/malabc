## 1. 黑帽 · 风险（测试会以哪些方式失效）

1. **判据数量不可数** → 「我们有多少条判据」只能靠估，而估错了没人知道。
2. **判据 id 可重名** → 出红时无法定位是哪一条（本轮实测抓到 1 处：同一 id 在 3 个符号上各跑一次）。
3. **新门会漏登记** → 本轮两道新门 `check_tour.py` / `check_version_scheme.py`：
   - 没有 `--selftest`（runner 要求每道门两向自证）
   - 没进 `GUARD_CONTRACT`（退出码无人核对）
   - 没进 `check_all.py` 的 ASCII 树（H2e）
   三者都不会让已有的门变红 —— **它们只是不存在**。
4. **散文里的数字会腐烂** → 「30 道门」五处，全靠 N1 抓。
5. **判据可能恒真** → 目前没有机制发现「这条永远为真」，而恒真判据和没有判据等价。

## 4. 蓝帽 · 一句话结论

> **这套测试的弱项不是「判据太少」，而是「判据的存在与否、数量、是否还活着」缺少可观测的入口。**
>
> 本轮把「有多少条」（`--list`）、「新门有没有真正接入」（自证 + 契约 + 树）、
> 「文档里的数字对不对」（N1）这三件事补齐；剩下 15 条里，**第 6、7 两条最重要** ——
> 它们决定这 200 条判据里有多少是真的会红的。
