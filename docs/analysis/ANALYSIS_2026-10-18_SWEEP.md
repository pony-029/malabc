## §2 判据写错的 3 条（我的错，不是产品的错）

我写了「空目录也必须 rc=0」，但实际：

| 语言 | 空目录 rc | 输出 |
| --- | --- | --- |
| `py` | **1** | `未找到任何 py 文件` |
| `js` | **1** | `未找到任何 js 文件` |
| `asm` | **1** | `未找到任何汇编文件` |
| `matlab`（默认） | **1** | `未找到任何 .m 文件` |

**「没有输入」返回非零，是合理约定** —— 它让 CI 能发现"路径写错"这类配置问题。

**我的判据假设了"空目录是合法的 0 结果"，那是错的。** 已记入本文件，判据要改成 `rc == 1`。

## §3 真实不一致：`--lang c` 的空目录返回 **0**

```
$ matlabc.py empty --lang c --json out.json
===== C 语言前端分析摘要 =====
C 文件 0 | C 函数 0 | 调用边 0 | 未解析 0 | include 依赖边 0
rc=0
```

**四个语言分支里，只有 `c` 把"0 个文件"当成成功。**

### 为什么这是问题

| 场景 | `--lang c` | 其它三个 |
| --- | --- | --- |
| 路径写错 | **rc=0**（静默通过） | rc=1 |
| CI 里拼错目录名 | **绿** | 红 |

**它会把配置错误伪装成"分析成功，只是没有文件"。**

### 为什么本轮不改

改 `c` 的退出码会**影响现有 CI**（如果有人在空目录上跑它并依赖 rc=0）。
**这需要单独评估 + 一条 `--help` 说明**，不是顺手能改的。

**已记录为已知不一致**，下一步要么统一成 rc=1，要么在帮助里明说 `c` 的特殊约定。
