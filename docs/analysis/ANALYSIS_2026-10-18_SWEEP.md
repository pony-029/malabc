## §3 真实不一致：`--lang c` 的空目录返回 **0**

### 为什么这是问题

| 场景 | `--lang c` | 其它三个 |

**这需要单独评估 + 一条 `--help` 说明**，不是顺手能改的。

**已记录为已知不一致**，下一步要么统一成 rc=1，要么在帮助里明说 `c` 的特殊约定。

## §10 第 6–7 轮：`--from-json` 健壮性与并发

### §10.1 `--from-json` 只做解码检查，不做 schema 校验

| 输入 | rc | 说明 |
| --- | --- | --- |
| 非法 JSON（`{ this is not json`） | **≠0** | 会报错 |
| **UTF-8 BOM** | **1** | `Unexpected UTF-8 BOM (decode using utf-8-sig)` |
| `{}`（合法但空） | **0** | **不校验** |
| 缺 `files` 键 | **0** | **不校验** |
| `version: "0.0.1"`（不符） | **0** | **不校验** |

**⇒ 它把「能不能解析成 JSON」当门槛，不把「像不像一份快照」当门槛。**

**这不是崩溃，是宽松**：`--from-json` 的设计意图是"读回自己产出的快照"，
而 `schema` 校验在别处（`--json-contract-check`）。

**风险**：喂它一个 `{}`，它会产出**空快照**并返回 0 —— 下游拿到的是一份
"什么都不含"的报告，**而没有任何提示**。

**建议（未做）**：至少在缺 `version` / `files` 时打一行 stderr。
**但那会改变现有宽松行为**，需要单独评估 —— 和 `--lang c` 一样，
**先记录，别顺手改**。

### §10.2 并发：两个 `--json` 进程跑到 180 秒超时

```
pa = spawn([... "--json", c1.json]); pb = spawn([... "--json", c2.json])
ra = pa.wait(timeout=180)   → TimeoutExpired
```

**但这次测量不干净**：探针（62,704 文件的 C 臂）**正在同时运行**。
三个进程抢 CPU/IO，180 秒超时**不能直接归因为"并发 bug"**。

**⇒ 结论只能是"待验证"**，不能写成"并发会死锁"。

**验证方式**：探针结束后，在**空闲机器**上重跑这两个进程。
判据：两者都应在 5 秒内返回，且 `--json` 内容（去时间戳）相同。

### §10.3 本轮没有覆盖第 8–10 轮

我原本计划 10 轮。**实际做到第 7 轮**，第 8 轮（LSP 边界）在第一次尝试时

**待验证**：用带超时的客户端发 `workspace/symbol`，看它是否在 5 秒内回复
`{"error": {"code": -32601}}`。
