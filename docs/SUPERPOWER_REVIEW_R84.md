# R84 复盘 — 把「内核全树跑了什么」从口头事实变成有对手方的登记表

> 判据来源：白帽**以实测为准**（两次真跑 + 一次生成期自检 + 一次门当场开火）。
> 本轮范围：**只加一道门 + 一张登记表**，产品侧（`matlabc.py` 的分析逻辑）**一行未动**。

## 0. 一句话

在真实 Linux 内核语料（**62,704** 个 C 前端文件 / **63,051** 个源码档文件 /
**1,315.8 MiB**）上**重跑全树分析**，用**两次独立跑**证明读数**逐位可复现**；
并把「那张表还成立吗」做成第 **19** 道登记制护栏 `tools/check_kernel_snapshot.py`
（判据族 **W1–W5**）。

### 1.2 与 R81 冻结基线的对照

**与时钟无关的计数器逐个相同**：C 臂 10/10 个字段全等、ASM 臂 4/4 个字段全等，
`diff == {}`、`key_presence_diff == []`。**两次独立跑都是这个结果。**

⇒ 分析器在真实内核语料上是**确定性的**；`matlabc.py` 自 R81 起只有纯文档改动，
这一次是**实测确认**，不再是我读 diff 之后的推断。

### 1.3 同一次对照顺带量出一件事：墙钟不可裁决（§4c-1）

| 读 | 值 | 比值 |
|---|---|---|
| R81（`cwd=CORPUS`） | 793.4 s | 1.51× / 1.26× |
| R84 第一次（sha `5d327816`） | 630.8 s | 1.20× |
| R84 第二次（sha `f414e252`） | 526.3 s | 1.00× |

**被测逻辑完全相同**（两次的 sha 只差一个 docstring 数字）而墙钟差 **1.20×**；
与 R81 差 **1.51×**。若按「墙钟变快 ⇒ 版本更快」去归因，本轮会得出一个
**完全虚假的结论**。这就是 W5 把 `seconds` / `peak_mb` 排除在对照之外的实测依据。

### 1.4 新增护栏：判据族 W1–W5

`tools/check_kernel_snapshot.py`，两向自证 `SELFTEST COUNTS {"bad": 24, "good": 12}`。

| 判据 | 拦什么 |
|---|---|
| **W1** | 登记表的形状：开/闭标记各**恰好一次**、块内数据行 `键 \| 值`、**键不得重复**（重复会静默折叠）、值为空必红、必需键缺一必红、直方图键**不许是空集**（空集上恒等式恒真） |
| **W2** | 出处**与口径**钉住：`matlabc.py` 的 sha256 / 字节数必须等于**当前盘上**那一份；`provenance.cwd_convention` **必须非空** —— 见 §1.5 |
| **W3** | **三档分母并列**：C 前端档 / 源码档 / 本仓+OSS 档，都要 > 0、**互不相等**、不得反向；`corpus.path` 必须**指名子树**（含 `linux-` 且含 `corpus`） |
| **W4** | **恒等式**：`arm_c.files == corpus.files_c_family`；`Σ启发式类别 == heuristics`；`rc == 0`；`json_bytes/funcs/edges/lines/asm.files > 0` |
| **W5** | 与 R81 在**与时钟无关**的键上**逐位**相同 **且** 启发式分解**逐类**逐位相同；两侧 README 必须指向唯一事实源；跨文档分母必须一致 |

### 1.5 本轮最值钱的一段：**三个都对却互不一致的读数**

仓库里同时躺着：

| 读数 | 来源 | 差别在哪 |
|---|---|---|
| `661 s / 10.8 GB` | R75（`cwd=REPO`） | 记录的路径退化成 basename |
| `793.4 s / 13.1 GB` | R81（`cwd=CORPUS`） | 真相对路径 |
| `630.8 s / 12.8 GB` | R84 第一次 | `cwd=CORPUS` |

**三者都不是错的**，错的是「混着引用而不写出口径」。所以 W2 登记的第一件东西
不是数字，是**口径**（`provenance.cwd_convention = cwd=corpus (target=.)`）。

### 1.6 门真的开火了三次（这才是它存在的证据）

1. **W2 当场抓到我自己**：我为了门数级联改了 `matlabc.py` 的一个 docstring 数字
   （`18 道登记制护栏` → `19 道`），字节数**没变**（同位数），但 **sha 变了**。
   门立刻报：「登记表记的 sha256=5d327816…，当前=f414e252…」。
   ⇒ 处置：**重跑整棵树**（不重跑就是「把一个没跑过的数写成跑过的」），
   顺带得到 §1.3 那条墙钟证据。
2. **生成器的生成期自检抓到量具自己**：第一版 `parse_kinds` 按**逗号**切，
   而摘要行的分隔符是 **` | `** ⇒ 切出 0 类，`Σkinds == heuristics` 当场报
   `0 != 1262829`。**错的不是判据，是量具在解析上的口径**；若没有这道生成期自检，
   错的口径会直接落盘成一张看起来正常的表。
3. **读一遍自己写的文档抓到一个「一个量两份实现」**：生成器第一版自己定义
   「全部扩展名 = 树里所有文件」，算出 **92,190**，而仓库既有口径
   （`probe_kernel_chunks.EXT`）是 **63,051** —— 差的正是
   `.rst/.txt/Makefile/…` 这些非源码文件。已改为**直接复用既有装置的常量**
   （§4x-5：一个量只许有一份实现）。

## 2. 红帽 —— 直觉

第一次跑完看到「10/10 相同」时，我并没有松口气，反而先怀疑**量具**：
是不是 `AGG` 合并把上一次的记录覆盖成了「相同」？直到确认

## 4. 黄帽 —— 价值

* **从「跑过一次」到「每次都能证明还是同一个结果」**：内核是这套工具最大的真实
  语料，此前它的读数只活在提交信息和记忆里。
* **把一条纪律条文变成实测**：§4c-1 原先是一句告诫，本轮有了 1.20× / 1.51× 的读数。
* **第 19 道门自带对手方**：它不是「再写一句」，而是给一个**只写不校**的三方事实
  配了三台仪器（出处、口径、基线）。

## 5. 绿帽 —— 别的做法与为什么没选

1. **把重跑塞进门禁**：13 分钟 × 每次 `check_all` ⇒ 没人会跑，门会变成摆设。
   ⇒ 取「门**不重跑**，只钉出处与口径」。
2. **W2 放松为「允许一组 sha」**：等于给「分析无关改动」开一条无判据的旁路。
   ⇒ 不取；宁可重跑。
3. **改 `_kernel/rerun_kernel_r81.py` 复用**：它的 `OUT` 写死 `r81` 且按 label 合并
   ⇒ 会**就地吃掉对照的另一半**。⇒ 另写 `probe_kernel_r84.py`（对基线只读）。
4. **把 `661 s` 那一行"修正"掉**：那是**历史引用**，它写下时是真的。
   ⇒ 保留，并让口径字段承担分辨责任。
