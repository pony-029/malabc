### 3.5 `tools/check_baseline.py`：新增判据 **T1**（被 `--full` 的**第一次**读数倒逼出来的）

第一次真跑 `--full`（R62 没跑过它）拿到：

```text
BASELINE COUNTS {"regressions": 0, "fixed": 5, "common": 122}
```

**零回归**，但 4 条 `fixed` 被 **B2** 判成「未解释」。逐条查下来它们**不是一类**：

| nodeid | 真因 | 正确处置 |
| --- | --- | --- |
| `test_r62_gate_row_signatures_two_way` | 它 spawn **每一道**护栏，其中 `check_baseline.py` 默认模式需要 `.git`，而 before 侧永远是 `git archive` 导出树 ⇒ 必然红（与已登记的 `test_r30…` **同根同源**，只是 R62 没跑过 `--full` 才迟迟没露面） | **登记**（永久：before 侧永远是导出树 ⇒ 不会陈旧） |
| `test_r61_gate_registry_mentions_the_new_guard` | 本轮把它从 `MIN_GUARDS == 14` 改成 `== 15` | **不能登记**（见下） |
| `test_r63_known_red_guard_two_way` | 需要本轮**新增**的 `tools/check_known_red.py` | 同上 |
| `test_r63_gate_registry_mentions_the_new_guard` | 需要本轮的 `MIN_GUARDS == 15` / 新门进 `GUARD_CONTRACT` | 同上 |

后三条的共性是：**它们在本轮被新增或改动过，并且断言了本轮新增的产品事实**。
`--full` 的前提是「同测试集」—— 把**当前** `tests/` 复制进导出树，而树里的
`tools/` 还是**上一个提交**的 ⇒ before 侧**构造性**地红。

于是 **`KNOWN_BASELINE_NOISE` 在这里是错的工具**：

* 登记它 ⇒ 提交之后导出树就带上产品了 ⇒ 下一轮它不再出现在 `fixed` 里
  ⇒ **当场变成陈旧登记（B3）**；
* 不登记 ⇒ B2 报「未解释」⇒ `--full` 的 **rc 恒为 1**；
* 而把 B2 静默掉 ⇒ 就再也分不清「本轮改动的测试」与「真被修好的测试」。

⇒ 新增判据 **T1**：用「HEAD 自己那份 `tests/`」与「当前 `tests/`」逐测试比对
**函数源码片段**（按行首 `def test_` 切分，与 `check_known_red.py::test_spans` 同口径；
读文件一律 `newline=""`，否则 CRLF 被静默翻译成假阳性），把「本轮新增/改动过」的
nodeid 单列一类 —— **打印**出来（信息性），**不判红**。

这是 R63 顺手挖出的**门自身的缺陷**：`check_baseline --full` 在**任何**
「新增或改动测试」的轮次里都无法通过 —— 而那样的轮次是**常态**。
**一条常态就红的门等于没有门**（本仓自 R41 起反复写下的那句话）。

## §7 已知盲区（不藏）

1. **本门是「静态登记」，不是「实测」**：`RED_TESTS` / `SKIP_TESTS` /
   `GREEN_REFS` 是**实测**得出的，但它们落地后就是**字面量**。门**不跑 pytest**
   （跑一次要秒级到分钟级，不能进 `check_all`）。因此一条红测试**改名**会被 K1 抓住，
   但**行为**从红变绿（名字不变）**抓不住** —— K4 只覆盖「跳过」那一桶。
   这是本门第一个、也是最大的盲区，见 §8 C13-1。
2. **README 表行里的数字（47 / 8 / 4）本身没有对手方**：P5 只证「那一行含本门签名」，
   不证「那一行里的数字也是真的」。见 §8 C13-2。
3. **K1 按 basename 扫全文（含注释与 docstring）** ⇒ 在文档里点名一个已登记产物
   就等于一条登记义务。取舍写在 `scan_refs` 的 docstring 里（宁可多登记）。
4. **`JOIN_ROOT_RE` 只认单段写法**：`os.path.join(ROOT, "sub", "x.ext")` 与跨行
   `os.path.join(` 都**不在网内**（K5 因此可能漏掉新缺口；K1 仍然兜住**已登记**产物）。
5. **B 类 6 个产物仍然是「不做」**：本轮只把「不做」**登记在册**，没有伪造它们
   （伪造空壳 = 占位符代码，用户明令禁止）。47 条红因此**依旧是红的**，
   只是从此**可见、有主、只许缩**。
6. **T1 的「本轮改动」是按**函数源码片段**判的，不比行号、不比空白**：改一个字符
   也会被算作「本轮改动」。取舍是**宁可多算**（多算只是打印一行），**不可少算**
   （少算就退回「B2 恒红」那个坑）。副作用是：一条**真的被修好**的测试若同时被改过，
   会被归到 T1 而不是「修复」—— 所以 T1 只打印、不下断言。
7. **只扫 `tests/test_matlabc.py` 一个文件**：与本仓「单文件测试集」的事实相符；
   将来拆测试文件必须同步扩这里的输入。
8. **帮助体积的读数与「怎么量」有关**（R63 收尾时实测）：同一个 `matlabc.py`，**Python 3.10 → 50481 B（558 行）/ Python 3.13 → 50451 B（557 行）**；3.10 下再设 `COLUMNS=200` → **45827 B**。
   差值来自 argparse 的折行（随版本变）与终端宽度（随环境变）。所以 `HELP_BYTES_SNAPSHOT = 50451` 只是**3.13 的读数**，而 `HELP_DRIFT_MAX = 0.30` 允许 ±15,135 B ⇒ 30 B 的漂移**整个被吞掉**。
   本轮的实质结论（两侧 559 行 / 50481 B，diff **只有一行**）不受影响，但正文里写「50451 未变」不诚实 —— 见 §8 C13-9。
