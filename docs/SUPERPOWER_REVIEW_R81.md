# SUPERPOWER 复盘 · R81 —— 整棵 Linux 6.19.14 内核语料实测

> 本轮不改产品代码，只把**当前版本**
> 跑到整棵内核上，看效果并把读数留成证据。
> 所有数字均来自 `_kernel/r81/` 下的实跑产物。

## 1 · 六顶思考帽

| 帽子 | 视角 |
| --- | --- |
| 白 | 语料 92,190 文件 / C-family 62,704 文件 / 36,155,901 行；整树 C 793.4 s、峰值 12.83 GB；整树汇编 2.4 s；站点 679.4 s、62,920 页 |
| 红 | 瞬间想把「661 s → 793.4 s」说成版本回归——这是本轮最危险的冲动 |
| 黑 | 本机同时有多个 python 进程；同一臂相邻两次可差 3 倍 ⇒ 时间类读数不能单次定论 |
| 黄 | `--json-level summary` 在整树上给出 10.83 MB 的 JSON，使大语料可进 CI；汇编前端 2.4 s 扫完 1,369 个 `.s` |
| 绿 | 把「墙钟归因」变成**交替轮次取最小值**的受控对照（六臂），并用「旧新站点逐文件对照」作旁证 |
| 蓝 | 结论只同意两类：**确定性体积类**（可复现）与**量级类时间类**（带波动区间） |

## 7 · 本轮自造缺陷

| # | 现场 | 修法 |
| --- | --- | --- |
| D1 | 差点把「661 s → 793.4 s」归因为版本回归 | 用旧新站点**逐文件对照**证伪（渲染未变），并改为受控交替对照 |
| D2 | `cwd` 臂首次跑出 -27.2% | 干净环境复测为 -1.0% / +0.7%，判定为干扰 |
| D3 | D 臂出现 11.82 s 异常值 | 改成**交替轮次**并输出「波动」列，不隐藏噪声 |
| D4 | 报告脚本读 `inventory.json` 用错字段名 | 改用 `files` / `c_lines` / `per_ext`（真实字段） |
| D5 | 报告脚本漏 `import json` | 补上；每次改完先 `ast.parse` 自检 |
| D6 | 站点脚本锚点命中 0/次数不唯一 | 源码里标题是字面 `\uXXXX`，且出现 2 次（title + brand）⇒ 锚点必须带标签 |
