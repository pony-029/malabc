### 1.2 三条独立复现（不靠自报）

1. **口径实修是真差别，不是改名** —— 同一批样本，旧口径 vs 新口径：

| 样本 | 旧（子串形状） | 新（词界+驼峰） | 说明 |
|---|---|---|---|
| `await x` / `async function` / `task.run` | **0 / 0 / 0** | 1 / 1 / 1 | 旧口径**看不见裸关键词** |
| `signal` | **0** | 1 | 同上 |
| `pthread_create` | **1** | 0 | 旧口径把**已登记原语**也当未知 |
| `__future__` | 1 | **0** | 新口径正确排除 |

⇒ 旧 `unknown = 112` **既漏又错**：漏掉全部裸关键词，又把已识别原语算进缺口。
新口径下 `unknown = 2,607`（**23 倍**）。这不是「变多了」，是**第一次真的在看**。

2. **回归清单可复现**：`gen_unknown_registry.py --check` 与盘上**逐字节一致**。

3. **环路真跑**：`SKIP 0–6 → RUN 7（0.09s ACCEPTED）→ RUN 8（0.09s ACCEPTED）→ SKIP 9–12`。

### 1.3 本轮两个**真发现**（都不是润色）

**发现 A —— 匹配器看不见 `_` 包裹的小写词干。**
`mutex_lock` / `pthread_mutex_lock` / `spin_lock_irqsave` 两条分支都不认
（左边界被 `_` 挡住、又无驼峰形态）。**后果**：`mutex_lock()` 是内核 C 最常见的写法，
所以**同步桶必然偏少** —— 实测 `sync_primitives` 只有 **27 条（1.0%）**，与这条边界一致。
**难处**：`__future__`（要排除）与 `pthread_mutex_lock`（要收）**形状完全同类**，
任何纯形状规则要么放过前者、要么漏掉后者。⇒ 不能靠继续调形状，要**并列报第三条口径**。
本轮把它**登记成断言**（`probe_r83_caliber_source.py`）：将来修好会**变红**，强制同步文档。

**发现 B —— 帮助契约的 rc=2 文本漂移。**
它还写着「导不到 unified_graph 或 binhops 或 concurrency」，而 `_load()` 实际已要**五个**
模块（多了 `site_matching` / `translate.rules`）。**没有任何门看得见它** ——
G2 只比退出码的**键集合**，不比文本。本轮一并修掉。

## 二、红帽（直觉）

- 直觉一：**口径类缺陷比功能类缺陷危险得多**。功能错了会有测试红；
  口径错了**所有读数一起错、而且全都自洽** —— 这是本轮全部工作的动机。
- 直觉二：**`await` = 2,039 条（78.2%）** 这个数字让我停了一下。
  它不是「缺口很大」，而是「**模型的登记表漏了一个语言**」——
  `await` 只登记在 `py`，而语料里 `await` 全在 JS 文件里（`py/await` 命中为 0）。
  一个登记项的疏漏，会伪装成整个缺口。
- 直觉三：`join = 0` 看上去像坏了，其实是对的 —— 它是「没有识别到汇合点」的
  **诚实读数**（`await` 全被算成未知，自然没有 join）。

## 三、黑帽（风险）

| # | 风险 | 严重度 | 现状 |
|---|---|---|---|
| B1 | **`unknown` 清单是快照、无门禁** ⇒ 会静静陈旧 | 高 | 本轮只做到「可复现」（`--check`），**没有**做成「陈旧即红」 |
| B2 | **`declared_source` 只在图上，没进报告/清单** ⇒ 报告读者看不到分母的来源 | 中 | 本轮未做 |
| B3 | **同步桶 1.0%** 会把「互斥同步不多」说成结论，而它其实是**量具缺陷** | 高 | 已登记成断言，但**读数本身仍不可用** |
| B4 | **U8 现在的「差」只断言 `delta>0`，没断言 delta 的构成** ⇒ 差从 9 变 900 也不会有门红 | 中 | 未做 |
| B5 | **新一轮的 `await` 登记若做成「把 unknown 数字压下去」，会得到假收敛** | 高 | 需在下一轮把「`join` 上升」也做成断言（不能只看 unknown 降） |
| B6 | 环路 `--max-rounds` 仍是**全局**计数，不按线路 ⇒ 长线路会吃掉预算 | 低 | 本轮未做（线路停已缓解） |

**黑帽最重的一条**：B5。`unknown` 下降**不是**收敛证据 ——
把 2,039 条 `await` 从 unknown 挪进 `join` 会让 unknown 掉到 ~568，
但如果没同时断言「`join` **上升** 2,039 且 `async` **不变**」，
一次「把 unknown 换个桶」就能伪装成巨大进步。

## 四、黄帽（价值）

1. **判据族从 U1–U7 扩到 U1–U8**，且 U8 的形态是「**并列报两种口径 + 断言它们真的不同**」——
   若两个读数相同，说明对手方退化成了同一把尺子。这是**可移植的形状**：
   任何「用同一个口径算出来的两个数」都可以照这个模子加对手方。
2. **`declared_sites` 现在必须带来源标签**，且三种拒绝（缺来源 / 未登记 / 非独立）
   + `from_dict` 侧门也在守恒器里能红。**「拿派生量当独立分母」这种写法写不出来了。**
3. **U8 第一次开火就抓到真缺陷**（`.then(` 前面天然跟着对象 ⇒ 套标识符左边界必然失配）。
   这是本轮**唯一由对手方（而非我自己的探针）抓到**的缺陷 —— 说明新判据是真判据。
4. **环路有了线路轴**：Phase A 未落地不再拖停 Phase 0 的地基工作。
   台账是事实（`halted_lines=['t1'`），其余线路继续 —— 360 轮预算不再被一次停机浪费。
5. **回归清单**给了「缺口收敛」一个**可对照的对象**：下一轮加完原语重跑，
   同一张表逐行对比，降了多少条一目了然。
