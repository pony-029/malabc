# 版本线：引擎与 VSIX 是两条线

本仓库有两个**独立**版本号，不要用其中一个去推断另一个：

| 版本 | 位置 | 当前值 | 用途 |
| --- | --- | --- | --- |
| 引擎 | `matlabc.py` 的 `VERSION` | `1.16.72` | Python 分析器 / CLI / LSP / MCP |
| VSIX | `vscode/package.json` 的 `version` | `1.7.0` | VS Code 扩展市场包 |

## 规则

1. `tools/bump_version.py` 只负责 **VSIX** 线；引擎版本是手工维护的。
2. `tools/check_version_scheme.py` 的 `VS1–VS2` 只审计 VSIX；它**不**要求
   引擎版本与 VSIX 相等。
3. 发布说明必须同时写出两条线；只说“1.7.0”而不说引擎版本，会造成
   “扩展版本 = 分析器版本”的误读。
4. 如果未来要把两条线绑定，必须先新增一条门禁并给旧版本迁移方案；
   不要靠约定。

## 为什么不是缺陷

`1.16.72` 是分析器第 116 个次版本，`1.7.0` 是扩展第 7 个次版本；两者
发布节奏不同。当前 `check_version_scheme` 的注释也明确写了“当前版本”
指 VSIX。把两者强行对齐，反而会让扩展市场版本跳变。
