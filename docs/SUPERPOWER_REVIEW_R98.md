`probe_kernel_r84.scope()` 的 `raw.count(b"\n")`），**再**决定判据该断言什么。

## 3. 本轮的交付

### 3.1 语料无关的生成器（`_r98/build_corpus_doc.py`）

**一份生成器 · 两种入口 · 三种语言**：`--lang py|js|c|matlab`。
语言差异**不散落在代码里**，全部收在两处：

```python
LANGS = {"py": {...}, "js": {...}, "c": {...}, "matlab": {...}}   # 一句话口径 + 能力
def recompute_py(files):      # 名字级：命中即扇出
def recompute_matlab(files):  # 限定名级：照 matlabc.py:32498-32531 重建
```

**生成期恒等式 C1–C11**（每份产物都过）：

| 判据 | 说的是什么 |
|---|---|
| C1 / C2 | `Σfiles[].n_funcs == len(funcs)` / `Σfuncs[].n_calls == 调用点总数` |
| C3 / C4 / C5 | 调用点 == 已解析 + 未解析 / `Σ已解析目标 == len(edges)` / `Σfuncs[].n_in == len(edges)` |
| C7 / C8 | 文件级 `call_out` 合计 == 跨文件边 / `Σheur_stats.by_kind == len(heuristics)` |
| **C9** | **独立复算 == 产物**（py/js **逐条**；matlab **多重集**；c **不等式 + 说明**） |
| C10 | 引擎 cg 产物若在：`Σresolution == edges_total`（**只对产物自己**，不跨口径混算） |
| **C11** | **行数口径 == 引擎**：`Σloc == Σfiles[].lines`。引擎公式 `len(scrub_source(text).split("\n"))` = 「换行符个数 + 1」且**空文件算 1**（§3.7 实测）。⚠ 只有 **matlab** 逐文件给 `lines` ⇒ 这条在 py/js/c 上是**如实说明**分支，**不是**三语料同口径 |

**紧凑存储是「显式」的**：邻居表截断到 `--max-nb`，但**计数在截断前记下**
（`target_total` / `in_total`），页面上写「只列前 N 个」。**截断不上报 = 把「看不全」伪装成「全部」**（R84 的老账）。

### 3.3 口径发现 ①：同一关系的两种序（**量具错**）

引擎的两处写点**故意不同序**：

| 出处 | 序 | 原文 |
|---|---|---|
| `matlabc.py:32498-32531` | **源码调用点序** | 注释：「按首次出现顺序去重…使调用图按代码中的真实调用时序展示（**而非过去的字母序**）」 |
| `matlabc.py:13988` | **字母序** | `"calls": sorted((f"{c.mfile.rel}:{c.name}" …) for c in f.calls)` |

而 `call_sites`（源码序的原始载体）**不进 JSON** ⇒ **只用 JSON 不可能复算顺序**。

**实测（cobratoolbox）**：同一集合 **40,298** 条，顺序不同，**首个不同 @0**：

```
我   : ('.artenolis/generateTutorials.m:generateTutorials',
        'external/analysis/mptoolbox/@mp/length.m:length', True)
产物 : ('.artenolis/generateTutorials.m:generateTutorials',
        'external/base/utilities/findjobj/findjobj.m:ischar', True)
同集合 = True   同顺序 = False
```

**处置**：C9 对 matlab 改成断言**多重集**，并把「顺序不同（产物=源码调用序，
JSON 只给 `calls` 的字母序投影）」**写进明细文本**。
⚠ 关键：**降级的地方要同时把事实升级** —— 不能只是「把断言改松然后闭嘴」。

### 3.4 口径发现 ②：限定名**不唯一**（**量具错**）

真实 MATLAB 里 `classdef` 的属性访问器 `set.X` / `get.X` 是**两个不同成员**，
但派生字段 `name` **都是 `X`**：

```
rel = external/base/utilities/violinPlots/Violin.m
  name=EdgeColor  line=182  kind=method  sig='function set.EdgeColor(obj, color)'
  name=EdgeColor  line=186  kind=method  sig='function [color] = get.EdgeColor(obj)'
```

⇒ `"rel:name"` 撞车。引擎的边是**标签级**的（`edges = list(dict.fromkeys(edges))`
按 `(caller, callee, cross)` 元组去重）⇒ 两条不同的边**塌成 1 条**。

**量化**（cobratoolbox）：

| 读数 | 值 | 说明 |
|---|---|---|
| `label_dup_defs` | **8** | 定义级重复的限定名（**全在 `Violin.m`**） |
| `label_ambiguous` | **1** | 其中**真被调用点引用到**的（两个调用点） |
| `label_overcount` | **2** | 若按**索引级扇出**会多出来的边数 |
| 复现 | `40298 + 2 = 40300` | 与修复前实测的 **40,300 vs 40,298** 逐位吻合 |

⚠ **两个数都必须报**：只报 `1` 会被误读成「全语料只有 1 个不唯一」。

**这一条与 R88「节点身份 = 定义落点」同族**，列为**下一轮候选修复**（改 `functions[].name`
让 `set.` / `get.` 可区分 —— 属**口径类**，须走 R88 的「**边一条不删**」判据）。

### 3.5 `files_located`：把「静默」变成「拒绝落盘」

我第一版把 `--root` 给成了**上一层**（`corpus/sympy` 而不是 `corpus/sympy/sympy`）。
后果**不是报错**，而是：

```
   files              1570
   loc                71        ← 1,570 个文件被数成 71 行
== 自检 9 条，失败 0 条 ==       ← 恒等式全过，因为「数字自洽」（当时 C11 还没加）
```

**「数字自洽」正是口径类事故的典型形状**（R83 老账：口径错了所有读数会一起错且全都自洽）。

**修法**（不是「把 LOC 修成 0 就算完」）：

```python
if _loc_n < _n:
    print("!! 源文件定位 %d / %d —— 检查 --root 是否与引擎那次分析的 root 一致")
    if _loc_n == 0:
        print("!! 一个源文件都定位不到 ⇒ 拒绝落盘（改对 --root 再来）")
        return 1
```

**退出码契约同时成文**（每个码都必须有真实代码路径，R96 ⑨ 的账）：
`0` 正常 · `1` 拒绝落盘 · `2` 参数错 —— 三码**两向自证**跑过：

```
=== rc=2：参数错（缺 --out）===            rc=2
=== rc=1：源一个都定位不到（--root 给错）===  rc=1
=== rc=0：正常 ===                        rc=0
```

### 3.6 三语料对照页（`_r98/out/compare_three.html`）

**一个数字都不手写**：内核那份来自 `kernel_dashboard_data.json`（看板自己的恒等式计数当对手方），
另两份来自生成器落盘的 `*.summary.json`。页面上显式写出**四条不可比**：

1. **C** 的边经过**两级解析阶梯**（同文件优先 + include 闭包）⇒ 「未解析」不是 py 的那个词；
2. **Python / JS** 是**名字级**：一个调用点命中 N 份同名定义就产 N 条边（**扇出，不是覆盖**）
   —— sympy 的边数高得离谱，主因是它内部有大量同名函数；
3. **MATLAB** 无 `--callgraph` 汇总产物 ⇒ 「解析档位」一栏是**不可用**而不是 **0**（「我没算」≠「它是 0」）；
4. **同一关系的两种序**（§3.3）；
5. **「总行数」这一列每一格都带口径标记**（§3.7）—— 三行**必须**同口径，
   而它**一开始并不是**。

**「别的工具验过了」不等于「这一页被验过了」**：`C11` 住在**生成器**里，
所以对照页曾经只能把「C11 钉住了」抄进注释 —— 那是**越权声明**。
本轮给对照页补上它**自己**能重算的 3 条判据（写在页面「六、本页自检」里，
`rc=1` 就**不落盘**）：① 三行口径标记必须恰好 `['engine']`；② 内核行的引擎式值必须与冻结读数
双向对账；③ 三语料数据齐备。另有 `_r98/verify_compare_page.py` 对**产物文件**做结构核验
（七个卡片标题各一次 / 三行 × 7 格 / 数字与口径文件逐位相等 / 不出现 `POSIX·冻结` 标记）。

### 3.7 口径发现 ③：**同一张页面上混了两种行数口径**（**量具错，而且是「修错了另一半」**）

这一条是本轮**最后一次**、也是最值得记的一次抓错 —— 因为它发生在**我刚刚宣布修好**的地方。

**起点**：cobratoolbox 站点跑完，日志里引擎报「代码行总数 **445,807**」，而我复算是 **444,006**。
逐文件比对 ⇒ **1,801 个 CRLF 文件每个恰好差 1** ⇒ 引擎用
`len(text.split("\n"))`（`matlabc.py:4420`，即「换行符个数 + 1」），我用 POSIX 口径。

**第一次修**（当时认为是全部）：把生成器的 `count_lines()` 改成引擎口径，新增判据 **C11**，
并在对照页写了一句注释：**「本页统一用引擎口径，内核那一列用的是引擎自己的 `stats.total_lines`」**。

**⚠ 那句话是错的。** 三枚探针把它推翻：

| 探针 | 问题 | 实测 |
|---|---|---|
| `_r98/probe_py_lines_field.py` | py/matlab 产物**逐文件**给行数吗 | **MATLAB 有** `files[].lines`（2,438/2,438 覆盖，Σ = 445,807）；**Python 只有** `rel/path/functions/imports`，**没有** |
| `_r98/probe_c_lines_field.py` | 引擎的 **C** 路径给行数吗 | **两个都没有**：跑 2 个 C 文件 ⇒ 无 `stats.total_lines`、无 `files[].lines`、stdout 也不打印「总行数」 |
| `_r98/probe_kernel_lines_src.py` | 那 `arm_c.lines = 36,155,901` 是谁算的 | 引擎自己的 C 产物（r81/r84 的 `kernel_c_summary.json`、`kernel_callgraph.json`）里这个整数**出现 0 次**；只有冻结记录 `KERNEL_RUN.md` 有 |

**真出处**：`_r82/probe_kernel_r84.py:100-113` 的 `scope()` ——
`ln += fh.read().count(b"\n")`，**runner 的 POSIX 口径**。

⇒ **内核那一列从来不是引擎口径**，我上一步只修了 py/matlab 那一半，
却把「已统一」写进了注释 —— **这比原来没修更坏：原来只是混口径，修完是混口径 + 一句担保。**

**第二次修（这次修对了）**：

| 动作 | 内容 |
|---|---|
| 钉死引擎公式的**边界** | `_r98/probe_engine_lines_formula.py` 6 个边界样例（空文件 / 无尾换行 / 只有换行 / 含转义 / …）**6/6 OK** ⇒ 引擎 = `len(split("\n"))`，**空文件 = 1**（不是 0），且 `scrub_source()` **不改变**换行个数。**生成器里那句「空文件 0」当场被这条实测判为错**，已改 |
| 让内核列的**口径可对账** | `_r98/probe_kernel_lines_two_semantics.py` 重扫 62,704 个 C 族文件、1.376 GB：**files 62,704 == 冻结**、**POSIX 36,155,901 == 冻结**、**引擎式 36,218,605**；`wc -l` 抽样 **60/60** 对拍一致；0 字节文件 **24** 个 |
| 把「统一」变成**判据** | 对照页 3 条自检（口径标记 / 双向对账 / 数据齐备），**不过就不落盘**；`verify_compare_page.py` 再对产物做结构核验 |
| 只改**一处口径**，不改**任何判据强度** | C11 仍是 `Σloc == Σfiles[].lines`；py 侧仍走「如实说明」分支 —— 因为 **py 产物真的没有这个字段**，「无法比对」是事实，不是让步 |

**副作用是可观测的（这正是它可信的原因）**：`count_lines` 由「空文件 0」改成「空文件 1」之后 ——

| 语料 | 空 `.py` 文件（实测） | `loc` 变化 |
|---|---|---|
| sympy/ntheory | **1**（`tests/__init__.py`） | 12,321 → **12,322**（+1） |
| sympy 全量 | **81**（全是 `__init__.py`） | 804,497 → **804,578**（+81） |

⇒ **口径改动是否真的落地，由「差多少」这个可现算的数来证明**，不靠「我改过了」。

**三次修法的同一形状**（与 R90/R95/R96 同）：**先把口径的事实量出来 ⇒ 再决定判据该断言什么**。
反过来（「让断言先通过」）在本轮一次都没发生。

## 4. 六顶思考帽

### ⚪ 白帽（事实）—— 四次「先问量具错还是对象错」

## 5. 与卡帕西四原则对照（用户指令：这是第一原则）

| 原则 | 本轮的具体体现 | 反例（我差点犯的） |
|---|---|---|
| **① 写码前先想清** | `--lang` 差异先收成 `LANGS` 表；先量吞吐（2 s / 47 s）再决定要不要做全量 | 差点**直接**写「一个语料一个生成器」——那就是把 C/Py/MATLAB 的差异复制三遍 |
| **② 极简优先** | 只有**一份**生成器；邻居表用**小数组** `[target_i, line]` 而不是 dict；载荷瘦身只删**空键** | 差点为「通用性」做一个插件式 renderer 注册表 ——**没有被要求** |
| **③ 手术式改动** | `matlabc.py` **零改动**；所有修改都只动 `_r98/` 里的仓外脚本（生成器 / 对照页 / 5 枚探针 / 核验器）；路线图**只追加**、不重排既有槽 | 差点顺手「把 `functions[].calls` 改成源码序」—— 那是**引擎口径类改动**，牵动 edges/checks/GUI 多处 |
| **④ 目标驱动执行** | 先定 G1–G5 五条判据；能写成判据的都写了（生成期 10 条 + 冒烟 12 条 + 对照页自检 3 条 + 退出码 3 条 + 门数 20）；**循环到验证通过**才落盘 | 差点在 `loc=71` 那版「目测没问题」就收工 —— **「数字自洽」不是「数字正确」**；更险的是 §3.7：**「我修好了」也不是「修好了」** |

**③ 的边界值得单独说**：本轮四次面对「要不要动引擎」——
- `--callgraph` 对 MATLAB 静默无产物（R96 已登记的**真缺口**）：**不动**，呈现层标 `source=layer` + 「不可用」；
- `calls` 的字母序 vs `edges` 的源码序：**不动**，C9 断言多重集 + 把事实写出来；
- `set.X`/`get.X` 同名：**不动**，照产物口径取首个定义 + 两个数都报，**列为下一轮**；
- 「C 路径不产行数」：**不动引擎**，用**同公式重扫**把对照页的口径补齐，并复核对上冻结读数。

四次都选了「**先如实描述，再另起一轮去改**」。这不是保守，而是 R88 定的规矩：
**口径类改动必须走「边一条不删」的判据**，夹带在呈现层轮次里做，两边都做不干净。
