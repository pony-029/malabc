# SUPERPOWER 方案 R77 —— 从「统计信息」到「看懂的源码」：三视图贯通

> 作者：malabc 项目组（冯磊）
> 方法：六顶思考帽（superpowers）× 苏格拉底式头脑风暴（brainstorming）
> 对象：C 语言前端 + `--browse` 站点的**产品形态**，而非某个 bug
> 结论先行：把**解析层下沉**（汇编 + 注释进模型），在渲染层新增**源码视图**，
> 再挂**可插拔译文层**；三视图共用一个数据源，逐行双向锚点。

## 0. 一图看懂

```
   用户今天看到的                              用户想要的
   ─────────────                              ──────────
   ┌──────────────┐                          ┌──────────────────────────────┐
   │ KPI 卡片      │  只有"多少"              │ 打开一个文件页：              │
   │ 条形/环形图   │  ───────────────►        │  行号 │ 源码（全文，可滚动）   │
   │ 23 行明细表   │  没有"是什么/为什么"      │   12  │ /* comment … */  [译] │
   │ 告警单行快照  │                          │   13  │ asm volatile(… )  [ASM]│
   └──────────────┘                          │   14  │   : "=r"(x)            │
                                             │   15  │   : "r"(y)             │
                                             │  ─────┴───────────────────────│
                                             │  行内徽章 → 跳到 asm 卡片      │
                                             │  注释 → 术语高亮 + 译文        │
                                             └──────────────────────────────┘
```

**一句话**：让读者**在一个页面里、从第一行读到最后一行**，每一行都可能挂着三样东西——
**源码本身 / 内联汇编的结构化展开 / 英文注释的译文**。

## 1. 【白帽】事实与数据（全部实测，2026-10-11）

### 1.1 解析层：汇编「零解析」、注释「被丢弃」

| 事实 | 证据（可复现） |
|---|---|
| C 前端**完全不解析内联汇编** | `matlabc.py` 全文搜 `__asm__` / `asm` → **0 命中** |
| 词法器**主动丢弃注释内容** | `_c_lex()` 文档串：「跳过注释与字符串**内容**」（`matlabc.py:7160-7183`）；`/*…*/` 与 `//…` 两个分支直接 `continue` |
| 汇编文件**不在分析范围内** | `_C_SOURCE_EXTS = (".c",".h",".cc",".cpp",".cxx",".hpp",".hh",".hxx")`（`matlabc.py:7001`）——**不含 `.S`** |
| 内核里 `.S` 有 **1,358 个**、`.asm` **11 个** | 遍历 `linux-6.19.14` 实测 |
| 内联汇编规模不小 | 仅 `arch/x86` 就有 **162 个文件 / 686 处** `asm(...)`（正则含 `volatile`/`goto` 修饰） |

### 1.2 注释的语言构成（「翻译模块」的必要性依据）

抽样四棵子树 `arch/x86` + `kernel` + `mm` + `drivers/gpu`：

| 指标 | 实测 |
|---|---|
| 总行 | 8,996,412 |
| **注释行** | **1,110,409（12.3%）** |
| 其中**含英文单词** | **905,488（81.5%）** |
| 纯中文 | **0（0.00%）** |
| 中英混合 | **0（0.00%）** |
| 样本文本量 | 577.6 MB |

⇒ 全树外推：**约 445 万行注释，几乎全是英文**。这不是"顺便翻一下"，而是一个**独立的功能面**。

### 1.3 渲染层：页面是「统计视角」，没有「源码视角」

`renderers/csite.py`（665 行 / 32,498 B）当前产出三类页：

| 页 | 内容 | 缺什么 |
|---|---|---|
| `index.html` | KPI + 告警构成 + 规则汇总 + 目录分组 | 无源码入口 |
| `file/<名>.html` | 函数表 / include / **告警（单行快照）** / 调用边 | **没有源码全文**；快照只有告警那一行 |
| `rule/<kind>.html` | 每规则 TOP 50 + 有界明细 | 无 |

### 1.4 规模上限（决定"单文件全文"可不可行）

62,697 个 C/H 文件：

| 统计 | 值 |
|---|---|
| 中位数 | **5,601 字节（≈200 行）** |
| 均值 | 21,947 字节 |
| p99 | 152,088 字节 |
| 最大 | **23.9 MB / 222,948 行**（`drivers/gpu/.../dcn_3_2_0_sh_mask.h`） |

⇒ **中位数文件全文渲染毫无压力**；top 0.1%（`*_sh_mask.h` 自动生成的寄存器定义，前 10 名全是它）**必须分块**。

### 1.5 硬约束（不可协商）

| 约束 | 来源 | 含义 |
|---|---|---|
| **零依赖** | 项目定位 / README | **不能引 `libclang`**（`inline-asm-fact-extraction` 那套 ctypes 直连方案在本项目**不适用**） |
| **Python 3.6.5 兼容** | `tools/check_py36_clean.py` + `--check-py36` | 禁 `list[str]`(3.9) / `from __future__ import annotations`(3.7) / 海象(3.8) / `match`(3.10) |
| 行尾 CRLF | `.gitattributes * -text` | 仓库 blob 全 CRLF，`bare_lf==0` |
| `renderers/` 子模块禁止模块级 `from matlabc import` | `check_import_graph.py` | 新渲染模块必须**零耦合**（只吃入参） |
| 新增 `.py` 会影响门禁计数 | `check_py36_clean` / `check_all` | 当前 59 个 `.py`，每加一个要同步 |

## 2. 【红帽】直觉与情绪

- 用户的原话是「**仅仅是生成了一些统计信息**」「**需要从源头一次就可以看到尾部就可以看懂**」——
  这是**挫败感**，不是技术报错。它指向一个真相：**我们把"能分析"当成了"能理解"**。
- 站点的 62,921 个页面 / 2.46 GB，**信息量巨大但可读性为零**：点进去看到的是表格，
  而读者想知道的是"这段代码想干什么"。
- 「连带着把 asm 也解析了」「加一个翻译模块」——用户其实在描述**同一个渴望**：
  **我要读得懂这堆代码**。汇编是"机器视角的注释"，中文译文是"语言视角的注释"，两者都是**降低阅读门槛**。

## 3. 【黑帽】风险与批评（这一节最该认真读）

| # | 风险 | 论证 | 缓解 |
|---|---|---|---|
| **R1** | **零依赖下不可能做"准确翻译"** | 无本地 MT 引擎；引第三方库违反零依赖 | 只做**术语级提示译 + 可插拔后端**（缺席降级），**不假装能整句翻** |
| **R2** | **零依赖下不可能做"语义级 asm 验证"** | 没有编译器/约束求解器，无法判断 clobber 是否真漏 | 只做**结构级提取**（模板 / 操作数 / 约束串 / 绑定），**明确标注"不做语义判定"** |
| **R3** | **规模爆炸** | 62,697 个源码页 × 全文 → 站点从 2.46 GB 涨到 **10 GB+**；`drivers` 单目录 `c_report.html` 已 457 MB | ① 源码页**按需**（只对有告警/asm/注释的文件）；② 大文件**分块**（>256 KB 截断 + 跳原文）；③ **不入库**（生成物，沿用 R76 决定） |
| **R4** | **污染现有 8 类规则** | 改 `_c_lex` 可能改变行号/偏移，C 规则全线受影响 | 注释保留走**独立函数 `_c_comments()`**，**不动 `_c_lex` 的现有行为**；asm 走**新增 pass** |
| **R5** | **译文缓存失效判定** | 源码一改，译文过期 | 缓存键 = `sha1(注释原文)`，**内容寻址**，天然失效 |
| **R6** | **`_rel_of()` 的 basename 退化**（R76 已记） | 目标在 cwd 之外时 `rel` 退化成 basename ⇒ 源码页文件名冲突 | 源码页一律用 `pf["path"]` 相对 `root` 重算（R76 已有先例） |
| **R7** | **门禁反咬** | 新模块 → `.py` 计数、import 图、I1 写点登记、README 门表 | 每步跑 `check_all`，先想它会不会反咬（既有纪律） |
| **R8** | **`.S` 前端是"半个解析器"，容易过度承诺** | 完整汇编语义（宏展开/条件汇编）不可能做对 | 只做**符号/标签/指令族统计 + 注释**，**不做控制流语义** |

**最坏情况**：我们造出一个"看起来什么都有、其实都没做对"的页面——这正是**黑帽要守住的红线**。
所以本方案的每条能力都必须带**"诚实边界"**标注。

## 4. 【黄帽】价值与收益

| 价值 | 为什么成立 |
|---|---|
| **数据层下沉，三处同受益** | asm/注释进模型后，**CLI 输出 / JSON / 站点**同时拿到，不是给站点打补丁 |
| **真审计价值** | 内联汇编的 clobber 列表是内核审计的经典雷区（`arch/x86` 686 处）；结构提取能**一眼看全** |

## 5. 【绿帽】头脑风暴：三个候选方案

### 方案 A —— 源码视图（Code Lens）
把文件页升级为**带行号的全源码页**，告警/注释以**行内徽章**锚定。
- ✅ 直接命中"看得懂"；改动集中在渲染层
- ❌ 不解析 asm、不翻译 ⇒ 只解决 1/3 诉求

### 方案 B —— 审阅稿（Walkthrough）
不进站点，为每个文件生成一份**技术说明书式**的 Markdown/HTML：按函数组织，函数下依次是
「注释(含译文) → 签名 → 源码 → asm 展开 → 告警」。
- ✅ 可读性最高，天然"从源头到尾部"
- ❌ 与现有站点**双轨**；36M 行不可能全出；读者丢失"跳转/索引"能力

### 方案 C —— 双视图 + 数据层下沉（**选定**）
在 A 之上，**先把 asm/注释/译文做进解析层**，再让渲染层长出**源码视图**，同时保留统计视图。
- ✅ A 的超集；"源头"（解析层）与"尾部"（页面）同时改
- ✅ 可切成 4 个独立可验收的阶段
- ❌ 工作量最大 —— 但它是唯一**不被推翻**的方案

**苏格拉底式追问（关键 Q&A）**：

| 追问 | 回答 |
|---|---|
| 「看懂的**边界**在哪？」 | 单文件级别**全文可读**；树级别用**索引导航**。不承诺"全树一页看穿" |
| 「asm 要"解析"到什么程度？」 | 结构：模板原文、GCC+LLVM 两套方言、操作数表（约束/表达式/读写方向）、clobber、volatile/goto。**不判对错** |
| 「翻译要什么质量？」 | 术语级 + 可选整句（外接后端）。**未译就显式写"未译"**，绝不静默留空 |
| 「如果只能做一件事？」 | **C-1 数据层下沉** —— 它让 CLI/JSON/站点三处同时受益，是唯一"不做就白做"的部分 |
| 「会不会做成第二个"统计信息"？」 | 判据明确：**页面里必须出现源码行本身**（而不仅是它的计数） |

## 6. 【蓝帽】选定方案 C 的架构

### 6.1 三层结构

```
┌──────────────────────────────────────────────────────────────────────────┐
│ L3 渲染层  renderers/                                                     │
│   csite.py（统计视图，保留）        sview.py（新增：源码视图）              │
│   i18n.py（新增：译文层，可插拔）                                          │
│   产出： index / file / rule /  ★src/<flat>.html（行号+徽章+锚点）        │
└───────────────▲──────────────────────────────────────────────────────────┘
                │ 只吃入参（零耦合，禁 from matlabc import）
┌───────────────┴──────────────────────────────────────────────────────────┐
│ L2 翻译层                                                                │
│   glossary.json（术语词典，纯数据）  cache/<sha1>.json（内容寻址缓存）     │
│   backends: builtin（术语级）｜cmd（stdin/stdout JSON 行协议，可选）      │
└───────────────▲──────────────────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────────────────────┐
│ L1 解析层  matlabc.py（C 前端）                                          │
│   新增 pass（不动 _c_lex 现有行为）：                                     │
│     _c_comments(path)      → file.comments[]                             │
│     _c_inline_asm(toks)    → file.asm[] / func.asm_refs[]                 │
│     _asm_bind(template,…)  → 操作数 ↔ 约束 ↔ C 表达式                     │
│     _asm_file_model(txt)   → .S/.asm 极简前端（符号/标签/指令族/注释）      │
│   扩展 _C_SOURCE_EXTS：+ ".S"（新增 asm 前端，与 C 规则隔离）             │
└───────────────▲──────────────────────────────────────────────────────────┘
                │
            源码（.c/.h/.S）
```

### 6.2 新增数据结构（精确到字段）

**`file` 级**（C 模型 / JSON `files[]`）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `comments` | `[{line, col, style, text, block_end}]` | `style ∈ {"line","block"}`；`text` 为**已剥壳**的原文（保留换行） |
| `asm` | `[{line, kind, qualifiers, template, outputs, inputs, clobbers, has_goto}]` | `kind ∈ {"asm","__asm__"}`；`qualifiers` 含 `volatile`/`goto`/`inline` |
| `asm_ops` | `[{idx, dir, constraint, expr, name}]` | `dir ∈ {"out","in","inout"}`（`+` 前缀判 `inout`）；`name` 来自 `%[name]` |
| `asm_file` | `{symbols, labels, macros, insn_hist, comments}` | 仅 `.S`/`.asm` 文件；**无控制流语义** |

**`func` 级**：新增 `asm_refs: [line…]`、`comment_ref: line|None`（函数头注释行号）。

**JSON 顶层**：新增 `asm`（汇总）、`comment_stats`（行数/英文占比）——**新增键不删旧键**（兼容）。

### 6.3 页面形态（"从源头看到尾部"的落点）

**`src/<flat>.html`（新增，核心交付）**

```
┌ 面包屑：总索引 › drivers › gpu › drm › amdgpu › amdgpu_device.c ─────────┐
│ 函数大纲（侧栏，锚点）         │  源码（行号 + 行内徽章）                 │
│ ▸ amdgpu_device_init  L823     │  1012 │ static int amdgpu_early_init(…){ │
│ ▸ amdgpu_device_fini  L1140    │  1013 │   /* Init the hardware */ [译]   │
│ ▸ …                            │  1014 │   asm volatile("mfence" ::: "m") │
│                                │       │        └─[ASM] 点开 ↓           │
│                                │  ┌───────────────────────────────────┐  │
│                                │  │ ASM @1014  mfence                 │  │
│                                │  │ 模板   "mfence"                   │  │
│                                │  │ 输出   —                          │  │
│                                │  │ 输入   —                          │  │
│                                │  │ clobber: "memory"  [⚠ 影响可见性] │  │
│                                │  │ volatile: 否  goto: 否            │  │
│                                │  └───────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────┘
```

- **行内徽章**：`[译]`（有译文/术语命中）、`[ASM]`（该行起有内联汇编）、`[⚠ n]`（该行有告警）
- **双向锚点**：告警行 → `#L1014`；`#L1014` → asm 卡片；asm 卡片 → 绑定的 C 变量行
- **函数锚点**：复用现有 `body_start`/`body_end`/`funcs`
- **零 JS / 零外链**（沿用 R76 教训）：折叠用原生 `<details>`，跳转用 `#fragment`

**`asm.txt`（新增，`.S` 文件专用页）**：行号 + 注释（含译文）+ 标签/符号高亮 + 指令族直方图（服务端 SVG）。

### 6.4 降级与规模策略

| 场景 | 策略 |
|---|---|
| 单文件 > 256 KB 或 > 8,000 行 | **分块**：只渲染"有徽章的行 ±40 行"的窗口 + 段落跳转；顶部注明「超大文件，已按洞察窗口分块」 |
| 无洞察文件（无告警/无 asm/无注释） | 只生成**一行索引链接**，不复制源码 |
| 无译文后端 | 页面显示 **术语高亮 + `未译` 标注**，绝不静默留空 |
| `.S` 文件 | 只出 `asm.txt` 页；**不参与 C 的 8 类规则** |

## 7. 分阶段实施与验收判据

| 阶段 | 内容 | 硬判据（两向自证） |
|---|---|---|
| **C-1 解析层下沉** | `_c_comments` / `_c_inline_asm` / `_asm_bind`；模型与 JSON 新字段；`_C_SOURCE_EXTS += .S` + `_asm_file_model` | ① 现有 8 类规则在**内核样本上逐位不变**（回归对照）；② 新字段在最小样本上**值与手算一致**；③ `--check-py36` rc=0 |
| **C-2 源码视图** | `renderers/sview.py`；`src/<flat>.html`；行号 + 徽章 + 锚点 + 分块 | ① 页面含**源码行本身**（反例：只含计数即红）；② 零 `<script>` / 零外链；③ 两次运行**逐字节一致** |
| **C-3 译文层** | `renderers/i18n.py` + `glossary.json` + 缓存 + 可选后端 | ① 后端**缺席**时页面仍可读（降级判据）；② 缓存内容寻址，改源码后译文**自动失效**；③ 词表命中率可度量 |
| **C-4 贯通导航** | 告警 ⇄ 源码 ⇄ asm ⇄ 译文 双向锚点；总索引新增 `src/` 入口 | ① 每个 asm 卡片有回跳；② 索引可达全部源码页 |

每阶段：**变异体两向验证**（副本，不动真树）→ `check_all` rc=0 → 精确路径提交 → fresh-clone 远端复核 → 记忆更新。

## 8. 诚实边界（写在方案里，防止过度承诺）

1. **asm 是结构提取，不是语义验证**：我们能告诉你"这行汇编读了哪些约束、绑了哪个变量、声明了哪些 clobber"，
   **不能**告诉你"clobber 声明是否充分"——那需要编译器/约束求解器。
2. **翻译是术语级 + 可选整句**：内置词典保证**离线可用但覆盖有限**；高质量整句翻译**依赖可选后端**。
3. **`.S` 只做浅层**：符号/标签/指令族/注释；宏展开与条件汇编**不做**。
4. **"一次看穿全树"不存在**：单文件全文 + 树级索引，是能力上限。
5. **生成物不入库**：`src/` 站点与译文缓存都是**生成物**（沿用 R76 决定），只入库生成器与词典。
