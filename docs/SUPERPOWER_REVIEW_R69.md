> 本轮指令：*「首先根据当前项目更新下 readme，作者冯磊，侵权必究，更新下 readme 和 license，
> 每一次都可以使用 superpower skill，联动的必要的 skill 深度思考，按照下一步建议实现保证
> 每一次都是真正的实现，并且持续规划 30 轮，60 分钟不断修复和改进，完成后进行下真实的测试，
> 并且最后完整后给出下一次建设性的意见」*。
>
> 决策点（用户当场拍板）：**授权模型 = 双轨（代码 MIT + 品牌必究）**；
> **署名写法 = `冯磊 (Feng Lei)`**。

本轮一问到底，量出 **7 个真缺陷**，其中最刺眼的一个是：**README 的版本徽章写着
`1.16.71`，而 `matlabc.py` 的 `VERSION` 早已是 `1.16.72`**。这不是笔误，
是「文档可以比源码旧而无人报警」这个**结构性空缺**。于是本轮不满足于"改一遍文案"，
而是把「许可与署名」本身做成**第 17 道登记制护栏**（判据族 `L1–L7`），

**为什么它必须是一道独立门，而不是"顺手改一遍文案"**：这三类失效**各有各的
失效机理**，而且旧装置一个都碰不到 ——

1. **「读正文的人才在乎 MIT」**：MIT 的授予段是 licensee 识别的唯一依据。
   双轨模型最危险的误操作是「为了让必究条款显眼，动一下正文」——
   把 `Permission is hereby granted…` 挪个位置、或改写 `OUT OF OR IN CONNECTION…`
   末句。**读者看不见，licensee 的识别却掉了。** ⇒ `L1` 的**前置断言**。
2. **「两份许可互相矛盾」**：`LICENSE` 与 `LICENSE_CN` 描述**同一份**授权。
   改附录只改一侧 ⇒ 两份文件在编号小节上分叉，谁是真的？⇒ `L6`。
3. **「文档比源码旧」**：版本徽章、版权人、必究标记都可能在一次合并里被
   **单侧**改掉。这是**真实的、本轮量到的**缺陷 ⇒ `L4` / `L5` / `L2`。

| # | 缺陷 | 为什么真实 | 旧装置的管辖范围 |
| --- | --- | --- | --- |

### 2.1 本轮的边界（诚实披露）

1. **`L1–L7` 只覆盖"在册的 5 个文件 + `VERSION` 常量"**。仓库里还有别的
   会说许可/署名的地方（例如 `flow/` 图册、`docs/analysis/`），本轮**不论**。
2. **`L5` 只认 `badge/version-<值>-<色>` 这一种写法**。如果将来把版本改成
   动态徽章（shields.io 的 `github/v/tag/...`），`L5` 会退化成「找不到 version
   徽章 ⇒ 红」—— 那是**缺输入**语义，不是放行，但要重做。
3. **`SECTION_SPAN = 2600`** 是许可证节的取样窗口。它够本轮的写法用；
   若某天许可证节被写成 3000 字，`L7` 会**静默丢尾**。这是已知的
   **窗口假设**，不是"已解决"。
4. **`L2` 只比"版权行以登记署名开头"**，不比整行。这是**故意的**：
   两份版权行在人名之后本来就不同（EN 用 `—`，CN 用 `——` 且把项目名括起来）。
   代价：`Copyright (c) 2026 冯磊 (Feng Lei)` 后面接什么，`L2` 不关心。
5. **本轮 7 个缺陷里，只有 5 个是"文档与代码分叉"**；#1/#2/#3 是
   **从零建立**（此前根本没有这个事实）。这两类东西混在一张表里时要看清。

## §3 黄帽：落地的装置

### 3.1 第 17 道门 `tools/check_legal_parity.py`

`ROW_SIGNATURE = "L1–L7"`（**真 en 破折号**，不是转义 —— 见 §4.1-5）。
`COPYRIGHT_HOLDER = "冯磊 (Feng Lei)"` 是**单一事实源**。

| 判据 | 问的是什么 | 失败意味着 |
| --- | --- | --- |
| `L1` | `LICENSE` 首行 == `MIT License` **且** 4 段 MIT 正文标记逐字在场 | licensee 识别可能已掉 |
| `L2` | **每一条**版权行（EN `^Copyright \(c\) \d{4}` / CN `^版权所有 \(c\) \d{4}`）归一后都以登记署名开头 | 两份许可在说"不是同一个人" |
| `L3` | 两份许可**同时**含 `侵权必究` 与 `ALL RIGHTS RESERVED`；三个读者入口（两份 README + CONTRIBUTING）**各含至少其一** | 承诺写在对话里、没写进仓库 |
| `L4` | 两侧 README 的 shields.io 徽章 URL 集合**相等**；`license` 徽章必须写 `MIT` | 单侧加删徽章 ⇒ 读者看到两份不同的说明 |
| `L5` | 两侧 README 的 `version` 徽章 == `matlabc.py` 的 `VERSION` | **文档比源码旧**（本轮的真缺陷） |
| `L6` | 两份许可的编号小节集合**相等且非空** | 附录只改一侧 ⇒ 两份文件互相矛盾 |
| `L7` | 两侧 README 的许可证节里同时看得到 `MIT` + 必究标记 + 登记署名 | 只把双轨写进 `LICENSE`，读者仍以为"随便用" |

退出码：`0` = L1–L7 无违规；`1` = 任一红；`2` = 缺输入（任一在册文件缺失/读不到，
或读不到 `VERSION`）。**缺输入按红处理** —— 没有可检查的对象 ≠ 可以放行。

`--selftest` 造 1 个"全对"的好样本 + 7 个各打断一条判据的坏样本 + 真树一跑：
**`SELFTEST COUNTS {"bad": 8, "good": 2}`**。

### 3.2 「双轨」落成什么样

```
LICENSE（7,168 B / 126 行）                         LICENSE_CN（6,745 B / 102 行）
├─ 第 1 行：MIT License            ← L1 前置，一个字未动   ├─ 同名译本
├─ MIT 授予段（4 段正文逐字不变）  ← licensee 读这个      ├─ 同名段落（逐字对应）
├─ 版权行：Copyright (c) 2026 冯磊 (Feng Lei) — …       ├─ 版权所有 (c) 2026 冯磊（Feng Lei）（…）
├─ Appendix 前言：区分"两类文本"                        ├─ 同一区分
├─ §1–§5（§1 点名持有人）                               ├─ §1–§5
└─ §6 NAME, BRANDING AND ATTRIBUTION — ALL RIGHTS RESERVED
     6.1 署名强制（MIT 本来就要求）+ 侵权必究
     6.2 不得冒充 / 不得暗示背书
     6.3 无商标许可 / 不得抢注
     6.4 仍然**完全允许**的（含**出售**）
     尾行：Copyright (c) 2026 冯磊 (Feng Lei). 侵权必究. ALL RIGHTS RESERVED
```

**关键设计**：MIT 正文**一个字未改**（`L1` 的前置），本项目自己的说明全部
挪到正文**之后**的 Appendix，且附录明文声明「不修改 MIT 条款」。
这样 `6.4` 能同时说清「你可以卖」和「你不能把品牌也卖了」。
