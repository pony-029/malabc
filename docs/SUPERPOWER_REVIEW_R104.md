> 起因：R103 §9 第 1 条 —— `test_p77_incremental_perf_benchmark`（1.72×）与
> `test_c28_uninit_performance`（当时报 1.4×）**通过时什么都不打印**，
> 余量可以在**没人知道的情况下**翻面（R103 ㉜）。
> 本轮**没有改任何阈值**，只补「可见性」；顺序按 R103 §9 的要求：
> **先让它们报数并跑一轮，再谈调阈值**。

## §1 白帽先查一件事：`print` 到底可不可见？

查源码（`tools/check_all.py:378`）：测试门用

```
python -m pytest tests/ -q -rf --tb=no
```

调 pytest —— **没有 `-s`**。pytest 默认捕获 stdout，**通过用例的被捕获输出直接丢弃**。
⇒ 「在通过路径上加 `print`」是**假修**：写了个没人看得见的读数
（与 R100 ㉑「声明改了、diff 里没有」同族）。所以必须走**机器可读侧信道**。

  读到上一次的陈旧读数（R83 ④）。
* **环境变量没设时测试侧一个字节都不写** ⇒ 直接 `pytest tests/` 无副作用、不污染工作区。

  写进量具；㉛：候选集要能推导，不许手写）。当前 **3 处**（p77 预算 / p77 宽限 / c28）。
* **判据四条，条条对应一种静默失效**：源内 0 个调用点 ⇒ 红（空集 ④）；坏记录 ⇒ 红；
  **有调用点却 0 条记录 ⇒ 红**（㉜ 要防的那一种）；**一条 `budget` 记录都没有 ⇒ 红**
  （否则「有记录」能被宽限记录单独满足 ⇒ 判据退化成空判据，R102 ㉖）。
* **与基线判据独立结算**（R102 ㉔）：两条问题**拼在同一个返回值里**，任一条红都不挡住
  另一条的读数（§4 的 A 样本就是这条的实测证据）。
* **只接了两条真预算 + 一条宽限**：`p77`（`dt_first` vs `0.075 × n_pages`）、
  `c28`（`dt` vs `5.0`）、`p77` 的增量宽限（`dt_inc` vs `dt_first + 0.8`，`kind="tolerance"`）。
  ⚠ **其余 8 条绝对阈值候选（`c22`/`c25`/`p210`/`r31`×2/`p150`/`p161`/`r32_entry`/`r33_guard`）
  尚未接入** —— 这是本轮**明确声明的缺口**（不假装覆盖全，R98 ⑮）。

### §2.1 一条**被实测推翻**的设计决定（如实记下来）

第一版**故意不报** `p77` 的第二条断言，理由是「它的比值恒在 1.0× 附近
（增量本来就该≈全量），报出来只会制造**新的误读**」。

**实测直接推翻了这个理由**：本轮红的**正是它**（§3b）。
「怕误读」不是不报的理由 —— 正确做法是**带标签报**：`kind=budget` 是真预算门，
`kind=tolerance` 是宽限断言，读者自己分辨。于是有了 **R104b**。

> 这条与 R103 ㉛ 同族：**候选集（这里 =「该报数的断言集」）要能推导，不能人工挑** ——
> 一挑就挑掉真凶。

## §3 ⚠ 新仪表第一次实测，把本仓一个数照翻了：`c28` 的「1.4×」是**口径错**

`c28` 接上侧信道后的**第一次**读数：`measured = 0.0151 s` / `limit = 5.0 s`
⇒ **余量 330.9×**，不是 1.4×。四次复测：

| 跑 | `_detect_uninitialized` 的 `dt` | 余量 |
|---|---|---|
| 1 | 0.015111 s | **330.86×** |
| 2 | 0.016155 s | **309.51×** |
| 3 | 0.017089 s | **292.59×** |
| 4 | 0.017139 s | **291.73×** |

而 `pytest` 报的**整条用例时长**是 2.37–2.52 s。R103 §4.1 那张表填的正是这个
「整条用例时长」（3.41–3.63 s），再拿 5.0 去除 ⇒ 「1.38–1.47×」。

**错在口径，不在算术**：阈值管的是**一次 `_detect_uninitialized` 调用的 `dt`**，
而「整条用例时长」绝大部分是 `parse_file`（3000 行巨函数）+ 建临时文件 ⇒ 两个量纲
不同的量被除到一起了。

* 这是 R83 ①「口径类缺陷比功能类危险」的**新变种**（㉝）：所有读数一起错，而且**自洽**
  （3.5 s 与 1.4× 互相印证，读起来毫无破绽）。
* **机制层结论**：这类错之所以能活过一整轮，正因为**绿灯什么都不打印**。
  ⇒ 「先让它们报数」这条顺序**不是形式主义**；本轮把它落实了，它当场就还了本。
* 已按「补正假声明」（R100 对 R99 的先例）处理：`docs/SUPERPOWER_REVIEW_R103.md`
  保留原表并就地标注 + 新增 **§12**。

## §3b ⚠⚠ 新仪表**抓到一条真红**：`p77` 的**宽限断言**翻面（余量 0.9994×）

`p77` 单条真跑（约 18 分钟、8 次子跑）**rc=1** —— 但红的**不是**那个预算门：

```
_emit_perf_margin("p77_incremental_perf_benchmark", dt_first, _budget)
    ⇒ measured 82.006 s / limit 182.325 s ⇒ 余量 2.22×            ← 预算门，很宽
_emit_perf_margin("p77_incremental_perf_benchmark/inc", dt_inc, dt_first + 0.8,
                  kind="tolerance")
    ⇒ AssertionError: 增量运行不应显著慢于首次（dt_first=82.006s dt_inc=82.859s）
    ⇒ 超出 +0.8 s 容差 **0.053 s** ⇒ 余量 **0.99936×**            ← 真翻面的这条
```

**根因分析（可推导，不是猜）**：这条断言是 R34「去抖动」时加的**宽限**断言，容差是
**绝对值 `+0.8 s`**，而代码注释自己写着它标定于「`dt_first=2.12s dt_inc=2.16s`」的年代
—— 那时一轮 ≈2.1 s，0.8 s 相当于 **38%** 的相对带。而现在：

| 量 | R34 标定时 | R104 实测 | 倍数 |
|---|---|---|---|
| 一轮墙钟 | ≈2.1 s | ≈82 s | **≈39×** |
| 容差 | +0.8 s（=38%） | +0.8 s（=**0.98%**） | 没跟着涨 |

⇒ **同一个「绝对阈值没跟着分母涨」的缺陷，R102 只修了第一条断言（60 s ⇒ 75 ms/页），
第二条一直没修**。这与 R102 ㉖ 记录的那次是**同一形状**（分母过期 ⇒ 判据退化成噪声探测器）。

空机复跑（本轮同代码、同一台机、**期间不再跑任何别的东西**）：

```
rc=0（1 passed, 507 deselected；≈19 min）
预算门   dt_first =  98.257 s / 上限 182.325 s ⇒ 余量 1.856x
宽限断言 dt_inc   =  85.691 s / 上限  99.057 s ⇒ 余量 1.156x
⇒ **第一次的红未复现**（这轮 dt_first 比 dt_inc 高，稳过）；但也只证明「这一次没翻」
   ⇒ 按 R103 §9 的顺序：先积累读数，下一轮再动阈值。
```

⚠ **无论复跑结果如何，「+0.8 s 标定于 2.1 s 年代、而分母涨了 ≈39 倍」这条算术事实都成立**
—— 复跑只用来分辨「这 0.053 s 是不是我并行负载造成的一次性扰动」。

## §7 诚实边界

1. **只接 3 条**（2 预算 + 1 宽限）：其余 8 条绝对阈值候选未接入 ⇒ 现在的余量表**不是**全集。
2. **`--with-tests` 全量重跑（≈35 分钟）本轮未做**：门的端到端由**桩探针**证明，
   测试侧的写入由 `c28`/`p77` 真跑证明 —— 两半各有真证据，但**没有一次真跑同时覆盖两半**。
   这是**有意保留的缺口**（说出来，不假装已端到端验证）。
3. **§3b 第一次的红受并行负载污染的可能性**：已用空机复跑分辨（结果见 §3b）——
   但即使负载是诱因，「+0.8 s 是过期绝对容差」这个**缺陷本身**仍然成立。
4. **没有改任何阈值**（按 R103 §9 的顺序要求）—— 包括这条已经翻红的：**先让它稳定报数，
   下一轮再谈**。
5. **`p77` 的读数受机器负载影响**：MEMORY 硬纪律「同臂相邻两次可差 3 倍」⇒ 82.0 s 与
   R103 的 106.06 s 差 1.3 倍，单次读数只当量级。
