### 已否决的目标（附测量依据，避免重复踩）

| 目标 | 表面数字 | 实测结论 |
|---|---|---|
| **`global X`** | 按“最后一条未映射”分组时有 11 个函数 | **假的**：那些函数大多有 45~209 条未映射（`bnb_branch_and_bound` 209 条），`global` 只是**最后**一条。做完一个也翻转不了 |
| `zeros(n,1)` | 30 条 | 几乎全在拼接内部（`[P(:);ones(...)]`），真阻塞是拼接 |
| 「调用作操作数」51 条 | 51 条 | 多数被 `diag`/`sparse`/`rand_hash` 等未实现库函数挡住 |

**教训**：按“最后一条”分组会系统性地把**最长**的函数排到前面（它们的最后一条正好是某种常见形态）。
正确的分组单位是「**只剩这一条**」的函数，且要同时看该函数的总未映射数。

### blockmarker（489）的根因：`if` 条件不支持，不是 `else` 配对出错（R669）

采样（YALMIP 全量）：`blockmarker` 只有两种词 —— `else` 1386、`otherwise` 337，**没有 `end`**。

最小复现（4 例，全部失败在 `if` 那一行）：

| 条件形态 | 结果 |
|---|---|
| `if s.v > 0`（struct 字段） | `unmapped: if s.v > 0` |
| `if isa(x,'function_handle')` | `unmapped: if isa(...)` |
| **`if a >= 0 && b <= 1`（`&&`）** | `unmapped: if ...` ← **唯一便宜可修的** |
| `if isa(s.f,'function_handle')` | `unmapped` |

机制：`if` 那一行没被降级 → **块没打开** → 后面的 `else` 无处归属 → 被记成 `blockmarker`。
所以 `blockmarker` 是**症状**，不是病；真正的病因在 `cond`（822 条）里。

⇒ 下一轮做 **`if` 条件里的 `&&` / `||`**（逻辑与/或），它能同时消掉 `cond` 与 `blockmarker` 两批。

### R681（局部 struct 展开）翻转 **0** 个函数 —— 按设计规则必须解释（R682）

**测量方法**：分别用 R681 之前/之后的 `mir.py` 扫三个真实库，统计
"unmapped 条数 = 0"的函数集合，取差集。

| 库 | 函数数 | 无未映射（改前） | 无未映射（改后） | 翻转 |
|---|---|---|---|---|
| jsonlab | 204 | 6 | 6 | **0** |
| export_fig | 78 | 2 | 2 | **0** |
| YALMIP | 1206 | 65 | 65 | **0** |

语句级确实减少了（unmapped 24564 → 24471，`why:struct` 11221 → 11037），
但**没有一个函数因此跨过"能转"的门槛**。

**为什么**：YALMIP 里"只差 struct"的 115 个函数，struct 几乎都是**参数**
（例如 `function anys = any(x)` 里的 `x.basis`）—— 而 R681 展开的判据明确要求
"名字不是参数/返回值"。所以这 115 个一个都不在展开范围内。

⇒ **参数 struct 才是阶段 3 真正的杠杆**，而它必须改 C 签名，
因此需要一份**显式声明**（`% @m2c fields s.a s.b` 或 `m2c.project.json`）。
局部展开只是把它的一半（118 个"只用 .field"的局部函数）扫了一遍，
而那些函数本来就还有别的卡点。

**这条记录的作用**：避免下一轮又去优化"局部 struct" —— 那条路的翻转数是 0。
