### F3b `unknown` 桶的**误报**（有分母，别把 112 当纯缺口）

`HINT_RE` 是**子串**匹配（形似并发的标识符），所以它会误收两类：

| 类型 | 例子（前 25 名内） | 条数 |
|---|---|---|
| 只是**名字里含**子串 | `__future__`（含 `future`） | 4 |
| **测试名 / 字符串** | `test_p50_end_index_callbacks_and_reproducible`（含 `callback`） | 2 |

⇒ 前 25 名里可辨识的误报 = **6 条 / 112 ≈ 5%**（只统计了前 25 名，**全量的误报率未测**）。
这不影响「`unknown` 首次非零」这个结论，但**影响把 112 当缺口规模去用**：
下一步应当把 `HINT_RE` 从「子串」改成**词界/驼峰界**匹配，并把误报率也做成带分母的读数。

### F3c 在**内核树**上，同一个病放大到不可用（这一跑跑完了，18.2 分钟）

| 项 | 读数 |
|---|---|
| 分母（**混口径**的 `_kernel`，仅作对照） | 66,003 文件 / 1,456,028,231 B |
| 双账 | declared 134,008 == 结局轴 134,008 ✓（**复式记账在 13 万量级仍成立**） |
| 结局 | async 6,310 / callback 15,883 / join 426 / **unknown 111,389** |

两个**独立**的污染源：

**(a) 子串计数**：`c signal` **15,551**、`c fork` **5,824**。
`low.count(tok)` 是**子串**计数 ⇒ `signal_struct` / `signaling` / `assert_spin_locked`
里的 `signal`、`forked` 里的 `fork` 全被算进「原语命中」。
（算术仍自洽：`callback` 15,883 = `signal` 15,551 + js 332；`async` 6,310 =
`fork` 5,824 + `pthread_create` 417 + js 62 + matlab 7 —— 所以**双账照样绿**，
这恰恰说明**「恒等式成立」救不了「口径错」**。）

**(b) 概念错位**：`unknown` 前 25 名里大量是**锁/信号量**，它们**不是异步站点**：

```
raw_spin_lock_irqsave 1156   conf_mutex 817   rw_semaphore 515
raw_spin_lock 457            assert_spin_locked 401   raw_spinlock_t 372
su_mutex 344   io_mutex 301   state_mutex 286
```

互斥/同步（锁、信号量）与「异步站点」（产出边）**不是一回事**。
把它们收进 `unknown`，等于把分母从「并发站点数」**悄悄换成了「并发相关词频」**。
另有纯误报：`datasync`（含 `async`）320、`nthreads` 429、`pthread_t` 385（类型名非调用）、
`current_thread_info` 342、`put_task_struct` 316（只是名字里含 thread/task）。

⇒ **结论**：`unknown = 111,389` **不能**当作「并发缺口规模」使用。它是一个词频分母。
真正诚实的缺口读数是仓 + 对标 OSS 那一档（339 文件）的 **112**。

## 黑帽 · 风险

### B1（高）H2 解了，但同族风险被搬进了探针

`declared_sites` 的**唯一约束**是 docstring 里一句「不得用 `all_site_count()` 当参数」。
**没有任何门能拦**。若将来有人在探针里写 `g.set_declared_sites(g.all_site_count())`，
A1b 立刻退化成恒真式，而**八道门全绿**。

> 本轮实测已踩到同族的三个变体：
> ① `declared = sum(by_outcome.values())`（探针里 A1b 恒真）；
> ② 双账口径只数已登记、不数 `unknown`（差 112）；
> ③ 护栏「退出码」段折行 ⇒ G2 只收到 `{0}`。

**建议**：把「谁提供 declared」变成**必填的来源标签**（`set_declared_sites(n, source=...)`），
并在 U6 里断言 `source` 属于白名单（如 `{"lexer-per-file", "header-include-graph"}`）；
`source` 缺失 ⇒ 红。这样「拿派生量当独立分母」这种错**写不出来**。

### B2（中）探针不是护栏

双账抓的是「分组丢/重」，抓不了「词法本身漏」。这条边界**写在输出里**，
但探针跑在仓库外、不进 `check_all.py`，所以它**不会在别人改代码时报警**。
→ 至少把 `--selftest` 的那 3 条反例纳入环路动作（已做：`ledger_problems`），
但 `per_file` 那条仍只靠人工跑。

### B3（中）内核那一跑被宿主掐过，而且第一次跑的是**错口径**

第一次整树扫描跑了十几分钟被 SIGTERM 掐掉，**输出 0 字节**（全丢）；
重跑时才发现 `_kernel` 顶层混着克隆与生成物 ⇒ 那一跑的宇宙本身就是错的。
新驱动 `_r82/probe_kernel_chunks.py` 按**子系统分块（217 块）**、每块单独落盘、
重跑自动跳过已完成的块 ⇒ 被掐只丢当前块。**分母必须指名到 `corpus/linux-6.19.14`。**

### B4（低但会积累）硬轮号撞车只能改计划

本轮已发生一次：台账里 round 3 是 `R82-A1`（历史 blocked），
所以 0b 两项**只能顺延到 4/5**。将来若频繁插轮，计划表会变得难读。
→ 需要「区段」概念（0 / 0b / A / B / C ...）而不是纯硬轮号。

### B5（高，本轮新发现）分母被两件事**悄悄换掉**，而门禁全程绿

① **子串计数**：`signal`/`fork` 这类短词在内核头文件里到处都是；
② **概念错位**：锁/信号量被收进 `unknown`。

两者都**不会让任何门变红** —— 因为双账比的是「同一个扫描的两本账」，
两本账用的是同一个错的匹配规则 ⇒ 它们**永远对得上**。
这是 H2 的更高一层：H2 是「两个量同源」，B5 是「**两本账共用一个错口径**」。
⇒ 只加更多「对账」没用；必须给**口径本身**配对手方（例如：同一段语料上，
词界匹配与子串匹配各自的读数必须在报告里**并列**，差异超过阈值就要有解释）。

### 新增纪律两条

1. **写含引号的散文/注释时用 `「」`** —— 写入工具会把中文弯引号规范化成 ASCII 引号，
   若落在字符串字面量里就会**静默**把一个「看起来完全正常」的源文件变成语法错。
2. **「退出码」段每个码各占一行** —— 折行续行会截断 `parse_exit_section`，
   而它只在对手方门禁里才现形。
3. **分母必须指名到具体子树，并写清「它是什么」** —— 拿一个顺手的工作目录
   （`_kernel`）当语料分母，会把克隆与生成物一起数进去：数字对、口径错。
4. **长扫描要分块落盘、可续跑** —— 单块长任务被掐后输出为空，前面全丢；
   分块后最坏只丢当前块。

   不修的话，112 这个「缺口规模」会被系统性高估，而**高估的方向恰好看不见**。
8. **把「锁/信号量」从 `unknown` 里分出去，单独成桶**（白帽 F3c、黑帽 B5）：
   互斥/同步 ≠ 异步站点。现在的 `unknown=111,389` 是**词频**不是**缺口**。
   至少分成 `unknown_async` / `sync_primitives` 两桶，并各自报分母。
9. **给「口径」本身配对手方**（黑帽 B5）：同一段语料上**并列**报
   「子串匹配」与「词界匹配」两个读数；差异必须能被解释，否则红。
   只加对账不够 —— 两本账共用一个错口径时会永远对得上。
