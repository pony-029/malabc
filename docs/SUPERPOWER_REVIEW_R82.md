## 【黑帽】风险与缺陷

> 按"最坏情况"排序。以下每一条都是能在代码里指到具体位置的，不是泛泛而谈。

**H1（结构性）Phase 0 是纯骨架，护栏绿 ≠ 能力有。**
新增 7 个文件里，**没有一行做识别**。`unified_graph.py` 自己不读源码、不发边、不解析二进制（模块 docstring 第 40–41 行明说）。今天任何"R82 有进展"的宣称，都必须限定为"判据的形状有了"。

**H2（最严重）A1 会在 Phase A 上线后自动变弱。**
A1 是 `Σ(产出边的站点) == |edges|`。如果 Phase A 的识别器写成"先造边、再顺手 `add_site`"，这条恒等式**永远成立**，A1 立刻从判据退化成恒真式 —— 而它的绿灯看起来和现在**一模一样**。
更糟的是 `add_edge()` 已经在构造期强制"端点必须已登记"，所以写识别器的人会自然而然地按"造边"的思路写，而不是按"报站点"的思路写。
**判据的方向（谁先谁后）没有写在任何地方，也没有门守着。**

**H3 `A2` 在正常路径上不可能被触发。**
`add_edge()` 构造期就拒绝未登记端点，所以 A2 只有 `from_dict()` 这条后门能触发（这是刻意设计，见 `UnifiedGraph` docstring）。结果：A2 是一个**几乎永不触发的分支**。自证里它被真触发过一次（`_injection_probe` 的 `A2` 子探针），但那是探针造的，不是真实数据造的。按 R82 自己的判据 3「一个从未被触发的分支不是判据」，A2 目前靠自证活着。

**H4 `U2b` 只钉住了 20 条映射里的 1 条。**
`concurrency.py` 里 5 语言 × 4 原语 = 20 条 `(token, outcome)`。护栏 U2b 断言的只有**一条**：`await` 必须是 `join`。其余 19 条改错（例如把 `pthread_join` 挪进 `async`、把 `std::future` 记成 async）**不会有任何东西变红**。而"把 join 记成 async"正是这份表存在的全部理由。

**H5 `HOP_DEVICES` 可以登记不存在的装置。**
11 条是**字符串常量**。没有任何判据要求 `gpu.fatbin` 这个名字背后的代码真的存在。这张表今天是一份**愿望清单**，而不是一份**实装清单**。

**H6 `verified_by` 可能永远空着。**
`translate/rules.py` 4 条规则的 `verified_by` 全为 `""`，而 B1/B2/B3 三条判据只看"命中/未命中/重复 ID"，**不看 `verified_by`**。没有分母、没有门 ⇒ 它是一个会一直空下去的字段。

**H7 "360 轮"目前不是机制，是数字。**
`_r82/evolve_loop.py` 的 `PLAN` 是**硬编码的 5 轮**。第 3 轮就 `blocked` 停机了 —— 这是**对的**（诚实停机优于假装推进），但也说明：**没有任何东西能自动把 360 轮推下去**。路线图 `docs/EVOLVE_ROADMAP_360.md` 与实际环路里的 `PLAN` 是**两份**东西，会漂移。

**H8 悬挂的 `??`。**
`.workbuddy/` 既没进 `.gitignore` 也没入库，会长期出现在每一次 `git status` 里。危害不大，但它会训练人"忽略 git status 里的噪声"，而那正是不该被训练的习惯。

## 【黄帽】价值与收益

**V1 真撞出过一次缺陷，而且是"免费"的。**
建这道门时，`binhop` 只写在 `EDGE_KINDS`、没进 `SITE_OUTCOMES`，于是 `add_site("binhop")` 抛 `GraphError` —— **A1 对 binhop 边结构性为假，而全仓没有一处会报**。
这个洞是先写护栏才暴露的。如果顺序反过来（先写 T2 的识别器、后补护栏），它会**埋在数据里**，等到有人真的去数边才会发现。这是"Phase 0 先行"这个决策拿到的第一笔实付回报。
修法也值得记：**没有补一行数据，而是把 `SITE_OUTCOMES` 改成派生量**（`EDGE_KINDS + NON_EDGE_OUTCOMES`），再加判据 `U1` 断言两者相等。**两张手抄的表迟早漂移** —— 这条现在有门守着了。

**V2 `unknown` / `join` 是一等状态，带分母。**
`site_census()` 对**每一个**结局都给读数（哪怕 0）。于是"没识别到"是**可见的**，不是一个不存在的键。这一条会在 Phase A 上线那天立刻产生价值：`unknown` 非零的时候，我们知道自己不知道什么。

**V3 把"我说我做了"变成"别人能验"。**
- 门数棘轮：`MIN_GUARDS` + 自证项断言它等于目录里真实的护栏数。
- 级联七处：门数一变，7 个地方必须同改，漏一处即红。
- 台账哈希链：**改 metric / 删中间行 / 插伪造行三种篡改全部当场变红**（已实测）。
- 远端复核：`HEAD` / `tree` / 274 个 blob sha256 / NEGCTRL，**证据不依赖本地工作区**。

**V4 诚实停机已经生效过一次。**
第 3 轮记 `blocked` 并停机，而不是补一个"看起来在推进"的动作。数据集里的 `blocked` 行是一份**可被问责的记录**：它写着"这里没做，因为没实现"。

**V5 帮助体积棘轮逼出了一次"显式批准"。**
术语补丁让 `--help` 涨了 261 字节，棘轮立刻红。处理方式是把两只快照更新为**实测值**，**没有放宽** `HELP_DRIFT_BYTES=64`。走的是设计者原本想让人走的那条路。

## 【绿帽】替代方案与改进点

> 每一条都对应上面一个 H，且都能落成一句可执行判据。

**G1 → 针对 H2（最高优先）**
把 A1 拆成**两条方向相反的等式**，并要求识别器按**站点先行**写：
- `A1a`：`Σ(产出边的站点) == |edges|`（现状，会变弱）
- `A1b`：`all_site_count()` 必须等于**解析器报出的候选站点总数**（第二个、独立的分母）
只要 §2 里那个"分母缺失"补上，A1b 就会让"先造边后补站点"的写法**立刻红**。

**G2 → 针对 H4**
把 U2b 从"钉一条"改成**遍历全部 20 条**：每条断言 `outcome ∈ VALID_OUTCOMES` **且** `outcome == 该 token 的期望结局`（期望结局写成一张显式的期望表，而不是从 `PRIMITIVES` 里读自己 —— 否则就是自证）。再补一条反向前提：`join_tokens()` 与 `async_tokens()` **交集必须为空**。这一条零成本、立刻可加。

**G3 → 针对 H5**
给 `HOP_DEVICES` 每条加 `implemented_in`（模块名，如 `"binfmt/gpu.py"`），U4 断言该文件存在且其中出现对应符号。把"愿望清单"变成"实装清单"。

**G4 → 针对 H6**
新增判据 `B4`：`verified_by` 为空的规则数**必须报出分母**，且任何"规则已命中"的报告里，未验证的规则不得以"已支持"字样出现。把"未验证"从沉默变成带分母的状态。

**G5 → 针对 H7**
把 `evolve_loop.PLAN` 从硬编码改成**从 `docs/EVOLVE_ROADMAP_360.md` 的表格解析**。这样路线图与环路是**同一份事实源**，改一处即生效；再补一条判据断言"PLAN 里已实现的轮次 ⊆ 路线图登记的轮次"。

**G6 → 针对 H3**
给 A2 造一条**真实**触发路径：让 T2 的二进制加载器在"符号解析不出端点"时**故意**产出挂空端点的边并记 `unknown`，由守恒判定器报出。这样 A2 就不再只靠探针活着。

**G7 → 针对 H1 / 白帽 §7**

## 【蓝帽】综合结论 + 行动建议

### 结论

**Phase 0 是真的。** 有独立证据链（远端克隆逐字节 + 274 个 blob sha256 + 克隆内门禁 rc=0 + NEGCTRL 分辨力），有真缺陷产出（`binhop` 非派生），有真停机记录（第 3 轮 `blocked`）。它不是"看起来完成了"。

**但它买到的是判据的形状，不是任何识别能力。** 这句话必须和"全量门禁全绿"一起说，否则那句绿灯会被误读。

### 本轮最需要写下的一句话

> **门禁全绿证明的是「恒等式成立」，不是「覆盖度足够」。**
> 今天 8 个站点桶里有 6 个恒为 0，而这**不会**让任何一道门变红 —— 因为 A1 只约束"边与站点对得上"，不约束"站点数够不够"。
> 分界线在于：**Phase 0 的绿是"没写错"，Phase A 的绿才可能是"写对了"。**
