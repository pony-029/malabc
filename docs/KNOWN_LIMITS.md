# 已知限制（v1.0.0-preview）

> 每一条都给出**数量、判据、以及"为什么不做"或"怎么做"**。
> 数字来自 YALMIP（1204 个函数，1114 个 `.m`），由
> `python tools/runnable_report.py <工程> --recursive` 与 MIR 的 `# why:` 标注得出。

## 0. 一句话总览

```
1204 个函数
  ├─ 1043 被整函数拒绝（struct/cell/varargin…）  ← 结构性，本架构不做
  └─  161 可转
        ├─    3 真正算出数值
        ├─   37 能跑但函数体是桩（差最后一条语句）
        └─  121 不可驱动（返回值形状未知）
```

## 1. 整函数被拒（1043 个）—— 结构性，不打算做

| 原因 | 函数数 | 含义 | 为什么不做 |
|---|---|---|---|
| `struct` | 866 | 函数签名或体内用了 struct | C 没有对应物；要支持得先有类型系统与反射，等于重写半个前端 |
| `cell` | 557 | 用了 cell 数组 | 异构容器，C 里只能用 tagged union + 动态派发 |
| `method` | 364 | 类方法 / `@obj` | 需要对象模型（vtable、生命周期） |
| `varargin` | 228 | 可变入参 | C 签名无法表达；只能引入 `(argc, argv)` 约定并改调用方 |
| `varargout` | 170 | 可变出参 | 同上 |

> 一个函数可能命中多个原因，故合计 > 1043。
> **降低 `reject` 计数不是进展** —— 这 1043 个不是"还没做"，是"这个架构不做"。

### 3.1 「形状推不出」的三种来源（实测归类）

按"这个名字是怎么写出来的"分组（228 处空形状返回值 / 151 个函数）：

| 来源 | 处数 | 能否静态定形 | 处置 |
|---|---|---|---|
| 分支里赋值（`if ... a = ...; end`） | **71** | ❌ 需要形状注解 | 如实拒绝（桩） |
| 多返回 `call2:` | 32 | 取决于被调方 | 可做（传递性） |
| 字面量 `const:` | 18 | ✅ 1x1 | **已支持** |
| `OP-SETIDX` 写入 | 14 | 取决于目标 | 需运行时分配 |
| `fill:` / `set:` | 11 / 10 | ✅ / 全局变量 | fill 已支持；set 不做 |

**样本与更正**：此前把「无写入」判定为"分支里赋值"，**这是错的**。
核对样本后发现，那些返回值**根本没有写入语句**，因为赋值本身就没被映射：

```matlab
properties = setfield(properties, checkfor, default);   % struct -> 不做
tbasis     = spalloc(n^2, 1+nvari, 2);                  % 稀疏构造
tbasis     = [BasisReal BasisImag];                     % 拼接
```

也就是说：**「形状推不出」很多时候是症状，真因是上游那条语句没被映射。**
（这就是为什么本轮把 `/* unmapped: ... */` 改为**始终**列在生成的 C 头部 ——
否则返回值一走 dynshape，这些注释就消失，桩看起来像"只差一条形状"。）


## 4. 语义边界（不是 bug，是未实现）

| 项 | 现状 | 风险 |
|---|---|---|
| **全局变量** `global x` | 不支持，`x` 变局部 | 静默算错 —— 已如实拒绝而非放行 |
| **数组别名** `y = x` | 不支持（`const:` 只接数字） | 如实落 unmapped |
| **`str` 相关** | 不做 | 参与数值时报错，不猜 |
| **整型/逻辑类型** | 一律 `double` | 溢出语义与 MATLAB 不同 |
| **`end` 在索引里** | 部分支持 | 复杂表达式里未支持 |

## 5. 性能（如实）

| 负载 | 相对 Octave | 说明 |
|---|---|---|
| 手写循环 | **快 ~90×** | 解释器吃亏的地方，C 赢最多 |
| 归约 `sum`/`max` | 持平 | 都被内存带宽限制 |
| **矩阵乘** | **慢 ~4.5×** | Octave 走 BLAS；我们的 4×4 微内核到标量上限 |

> 对照的是 **Octave**，不是 MATLAB。MATLAB 有 JIT，循环差距会明显缩小。
> **不要把"翻译成 C 就会变快"当默认结论** —— 只有原文本身是"解释器吃亏"的写法才快。
