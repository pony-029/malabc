# 设计：HIR —— 在 MIR 之上加一层语义层（R691）

> 目标重申（用户明确）：**MATLAB 仍然转成 C**，不转成 Rust。Rust 只用于**工具与运行时的效率**。
> 因此本文的 HIR 是 **C 生成链路上的一层**，不是另一条产物线。

---

## 一、为什么要 HIR：MIR 正在承担它不该承担的职责

现状：MATLAB 文本 →（`mir.py` 的正则）→ **MIR** →（`emit.rs` 的分支）→ C。

问题在于 **MIR 同时是"语义层"和"三地址层"**：

| MIR 里能看到 | 它其实是什么 |
|---|---|
| `setb:__i1:add:i:1` | 一个临时量的自增（**实现细节**） |
| `op:OP-MASK:y:x:0:2` | "按条件选值"（**语义**），但被压成了三元组 |
| `fill:y:1,4:0` / `fill:A:0:0` | 两种完全不同的语义（造数组 / 空数组），靠**逗号有没有**区分 |
| `op:OP-IDX2` vs `OP-INDEX` | 同一个"取下标"，按形状是否已知分成两个算子 |

后果就是我们这十几轮反复遇到的：**每加一个能力，都在 MIR 这一层打补丁**，
而 MIR 的形态（临时量、参数顺序、逗号约定）本来只是"降级后的样子"。

**HIR 的作用：把语义决定上移，让 MIR 退化成"机械降级结果"。**

---

## 二、HIR 形态（文本、人可读、和 MIR 同级简洁）

```
hir 1
func: snr
  param sig   vec[4]
  param noise vec[4]
  ret   y     scalar

  v1 = ew.mul(sig, sig)
  v2 = red.mean(v1)
  v3 = ew.mul(noise, noise)
  v4 = red.mean(v3)
  v5 = ew.div(v2, v4)
  v6 = un.log10(v5)
  v7 = ew.mul(v6, 10)
  y  = guard.clamp_min(v7, 0)
```

与 MIR 的三点本质差别：

| 差别 | 解决什么 |
|---|---|
| **表达式是树**（可嵌套 `ew.div(red.mean(ew.mul(a,a)), b)`） | 不再需要 `__t1/__s2` 这类临时量，也不再出现"临时量判成不是 i64 标量" |
| **算子带 family**（`ew/red/un/lin/shape/cat/idx/mem/guard/search/alloc/set`） | family 决定**参数要求**（`red` 要 vector、`lin` 要 matrix），归因从"桶名"变成"期望 vector 实际 record" |
| **类型写在值上**（`vec[4]` / `scalar` / `record{...}`） | 类型成为一等公民，`check` 的"期望/实际"对照有了依据 |

---

## 三、HIR → MIR 是**机械降级**，不是第二套逻辑

```
hir:  y = ew.div(red.mean(ew.mul(a, a)), b)
mir:  op:OP-MUL:__h1:a:a
      op:OP-MEAN:__h2:__h1
      op:OP-DIV:y:__h2:b
```

规则只有三条：

1. 后序遍历表达式树，每个内部节点分配一个 `__h<n>`，产出 `op:`；
2. 常量 → `const:`，字面量标量 → `const:` 临时量；
3. 控制流 → 现有的 `if:` / `while:` / `for:` 块。

**判据**：任何 HIR 程序降级出的 MIR，都必须能被现有 `emit.rs` 与 `cmir.py` 原样接受
（即：**HIR 不改变发射器**）。这条把风险锁死在"上层"。

---

## 四、迁移策略：**并行**，不推倒

```
            ┌─ 旧路径：MATLAB ─re­gex→ MIR ─→ C     （保持绿，随时可退）
MATLAB ─────┤
            └─ 新路径：MATLAB → HIR → MIR ─→ C     （逐函数接管）
```

- 用一个开关（`--via-hir`）选择路径；
- **每接管一个函数**，判据是：三段对拍 58/58 不变 + 该函数数值不变；
- 当**全部语料**走 HIR 且仍 58/58 时，旧正则路径才允许删除。

这样：主线（MATLAB→C）始终可用，HIR 是一层**可回退的增量**。

---

## 五、两条并行线（按你的要求）

| 线 | 内容 | 归属 |
|---|---|---|
| **主线 A：HIR** | HIR 规范 → 构造器 → 降级器 → 逐函数接管 → 删旧正则 | 我做设计与验收；实现可委派 |
| **副线 B：Rust 运行时** | `m2c run <mir>`，先用它替代 Octave 做自证 | 可委派给本地模型 |

**两线的交汇点**：HIR 降级出的 MIR，正好是 Rust VM 的输入 —— 所以 VM 不需要知道 HIR 存在。
这让两线可以**完全并行**，不会互相阻塞。

## 六、委派与验收（本轮的协作方式）

委派原则：**任务必须自带可机器判定的验收条件**，否则我不接受。

| 任务 | 内容 | 验收方式（我来跑） |
|---|---|---|
| **D1** | `HIR_TO_MIR` 映射表（纯数据） | ①每个 id 都存在于 `translate/operators.py`；②18 个 key 齐全、无重复；③`ast.parse` 通过 |
| **D2** | HIR 文本解析器（`parse_hir(text) -> list[dict]`） | 用我给的 3 个样例逐字段比对 |
| **D3** | 降级器（`hir_to_mir(prog) -> text`） | 对样例输出与现有 MIR 等价（算子序列一致） |
| **D4** | Rust VM 骨架（读到 `op:OP-ADD` 能算） | `m2c run` 对 `snr.mir` 输出与 Octave 一致 |

**验收纪律**（沿用本项目既有原则）：

- 不看"看起来对不对"，只看**判据是否通过**；
- 委派产物若不能通过判据，**不入库**，并把失败原因写回任务描述；
- 每个委派任务都要留一条**常驻判据**，避免下次被改坏。

## 八、风险与止损

| 风险 | 止损 |
|---|---|
| HIR 变成"第二套 MIR"，两套并行维护 | 硬规则：**HIR 不允许出现临时量、不允许出现算子 id**；它只说 family + 名字 |
| 迁移期两条路径行为不一致 | 每接管一个函数就比对"新旧 MIR 的算子多重集"，不一致立即回退该函数 |
| 委派产物质量不稳 | 任务粒度小 + 机器判据 + 不过即弃 |
| VM 抢走 HIR 的资源 | 两线**文件不重叠**（`translate/hir*` vs `rust/m2c/src/vm*`），互不阻塞 |

## 决策：是否默认启用 `--hir-emit`（2026-11-10）

**结论：暂不默认。** 依据是实测的代价，不是偏好。

| 路径 | `op` 数 | `# src:` 标注 | MIR 体积 |
|---|---|---|---|
| 默认 | 96 | **165** | 13.4 KB |
| `--hir-emit` | 96 | **0** | 9.2 KB |

**算子一个没丢**（96 = 96），丢的是**逐行行号对应关系**。而 `check` 的诊断完全依赖它：

```
默认      ：第 12 行 `y = A((i+0))` 无法降级
hir-emit ：某处无法降级          ← 这一行退化成不可行动
```

### 为什么不"顺手把行号带过去"

折树是后序遍历，算子**顺序会变**（`OP-MUL → OP-MEAN → OP-DIV` vs `OP-MEAN ← OP-MUL`），
所以"第 n 个 op 对应原来第 m 个"不成立。要保留行号，得在表达式树节点上挂源码位置 ——
那是 `HIR` 的**下一层能力**（带位置信息的节点），不是一次改动能补的。

### 什么时候可以默认切换

1. HIR 节点能携带位置（`{op, args, src}`），降级时按节点回写 `# src:`；
2. 且判据里有一条"`--hir-emit` 后 `check` 的诊断行号覆盖率 ≥ 默认路径的 95%"。

在满足这两条之前，`--hir-emit` 保持 **opt-in**：它是"证明 HIR 能产出"的证据，
不是日常路径。

### 2026-11-10 复核：两个前置条件都已满足

| 条件 | 要求 | 实测 |
|---|---|---|
| ① 位置可携带 | HIR 节点带位置，降级回写 | ✅ `ew.mul@L7(a,b)` / 顶层 `expr@L12` |
| ② 行号覆盖 | ≥ 默认路径 95% | ✅ **165 / 165 = 100%** |

配套判据：`tests/test_hir_srcline.py`（行号 ≥95% + 算子数不变）。

**仍未改为默认** —— 不是因为条件不够，而是因为"改默认"是一次**全量行为切换**：
所有下游（`check` 的行号、报告、快照）都会跟着变。切换前应先跑一轮
"默认 vs hir-emit"的**逐函数对拍**（行号 + 算子 + 数值三项全等），
确认无一处差异后再切。这一步没做，就不切。

### 2026-11-10 对拍结果（切换前的最后一道闸门）

`tools/hir_parity.py --values`：

```
函数数：默认 58 ｜ hir-emit 58 ｜ 交集 58
差异：0 个函数
数值：两条路径完全一致
```

逐函数三项（算子多重集 / `# src` 取值集合 / 数值位模式）全等。

**仍然没有在本轮切换默认** —— 切换会让**所有人拿到的 MIR 文本**改变
（`# src` 与算子的排列顺序不同、多一行 `hir-emitted` 标记），
这需要一次独立的、可回退的变更，而不是夹在功能开发里顺手做。

切换时的验收清单（已备好，按此执行即可）：
1. 加 `--no-hir-emit` 开关，默认开启；
2. `test_hir_parity` 仍绿；
3. `check` 的诊断行号在 hir-emit 下抽查 5 个函数，行号与默认路径一致；
4. 出问题时可一键回退（开关本身即可回退）。

### 规则：`#` 注释是**元数据**，折树必须原样保留

`--hir-emit` 用 HIR 降级结果替换算子区。中间踩过两次同类缺陷，都是**丢注释**：

| 丢的注释 | 后果 | 抓到它的判据 |
|---|---|---|
| `# why:K` | `check` 的卡点类别全退化成 `[misc]`（行号还在，但不可行动） | `test_check_diag_two_paths`（诊断逐字一致） |
| `# dropped:K` | `test_drop_sideeffect` 两条红（断言"副作用语句被丢弃"） | 全量编译门 GX2 |

所以现在 `hir_emit` **保留全部 `#` 行**。它们各自都是契约：

* `# src:N` 行号；`# why:K` 卡点类别；`# dropped:K` 被丢弃的副作用语句。

### 连带的一条实现细节

保留注释后，函数体块**末尾可能不是 `end`**（例如尾部有一条 `# dropped:`）。
此时"只看 `body[-1]` 是否 `end` 再 pop"会漏删，然后在末尾再补一个 → 产出
`多余的 end`（m2c 直接报错，第 13 行）。

正确写法是：**删掉最后一个 `end`（按位置找），而不是看末尾元素**。

### 2026-11-11 落地：`--hir-emit` **已设为默认**

前面几节的"暂不默认"已被这条取代。切换共试了 4 次，前 3 次都是同一个原因失败：

| 第几次 | 结果 | 原因 |
|---|---|---|
| 1 | 回退 | 验证者（`check_translate_port`）跟着默认漂了，红得毫无信息 |
| 2 | 回退 | 同上，另加 `# why:` 丢失导致诊断退化 |
| 3 | 回退 | `# dropped:` 丢失（`test_drop_sideeffect` 两例红）、块尾注释导致多一个 `end` |
| **4** | **通过** | 上面全部修好；全量编译门 `GX1–GX2` 绿；`check_all` 42 门全绿 |

**现在**：

```bash
python translate/mir.py foo.m            # MIR 由 HIR 降级产出（默认）
python translate/mir.py foo.m --no-hir-emit   # 回退到直出
```

**为切换建立的三道闸门**（都在 CI 里常驻）：

| 闸门 | 判什么 |
|---|---|
| `tools/check_hir_two_paths.py`（TP9a–TP9d） | 两路逐函数等价：函数集合 / 算子多重集 / `# src` 集合 / 数值 |
| `tests/test_check_diag_two_paths.py` | `check` 的诊断**逐字一致**（不比中间产物，比用户看到的字符串） |
| `tests/test_hir_meta_lines.py` | `# src` 与 `# why` 两类元数据注释都守恒 |

**代价与边界**：折树会改变 `# src:` 与算子的**排列顺序**（集合相等、顺序不同），
所以任何"比对 MIR 字节"的外部脚本都会发现差异 —— 这是预期的，不是回归。
