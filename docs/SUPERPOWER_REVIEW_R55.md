# R55 —— 「诚实的边界」里每条「不做」承诺，必须有一台能说「不」的判据

> 上一轮（R54）修的是**测量工具自己**。本轮修的是一条**更安静的缺口**：
> R51 已经把 `--help` 的「诚实的边界」变成与 `BOUNDARY_CLAIMS` 互为对手方的**逐字契约**，
> 但那条契约只核对「这句话**还在不在**」，**从不核对这句话是否仍然成立**。
> 一句话：**承诺有人守着「在不在」，没人守着「还成不成立」。**

## §1 白帽：事实（全部来自仓库外独立装置实测，不是门自己说的）

### 1.1 证据一：帮助与行为的**分叉**（`_r55/probe_p6.py`，7 种情形矩阵）

| 情形 | 输入 | rc | stderr `[warn]` 行数 |
| --- | --- | --- | --- |
| E1 | 只有 `thing.rs`（本次语言 = matlab） | 1 | **1** |
| E2 | `thing.rs` + `ok.m`（**混放**） | 0 | **0** |
| E3 | `thing.ts` + `thing.go` + `thing.java` + `ok.m` | 0 | **0** |
| E4 | E2 + 显式 `--lang matlab` | 0 | **0** |

修前 `--help` 的「语言：」这条是**无条件**承诺：

```text
语言：TypeScript / Rust / Go / Java 等**没有前端**。扫到这些文件时它会
    打出 [warn] 点名语言与文件，**不会静默返回 0 结果**。
```

而 `README.md` / `README_CN.md` 两侧写的是**窄触发**（「而本次请求的语言一个源文件都没找到时」）。
⇒ **帮助、行为、README 三方分歧**：只有「本次语言 0 源文件」时才 warn，混放时**一行都没有**。

### 1.2 证据二：一条**没有对手方**的承诺（`_r55/probe_p2.py` 的 A2 段 + 提交态复量）

「前端实现：」这条逐字承诺：

```text
仍**不识别** K&R 老式定义（`)` 后面不是 `{`）与返回函数指针的声明
```

在提交态 `HEAD=2caf526` 上量 `tools/` 与 `tests/`（判据唯一能落地的两个地方）：

| token | `tools/` + `tests/` 出现次数 | 落点 |
| --- | --- | --- |
| `函数指针返回` | **0** | —— |
| `返回函数指针` | **0** | —— |
| `K&R` | **1** | `tools/check_help_contract.py:556` 的 `"help_must": ("行锚定正则", "不识别", "K&R")` |

那唯一一次 `K&R` 就在 **`BOUNDARY_CLAIMS` 里** —— 它是**承诺的副本**（R51 拿来做逐字匹配），
**不是判据**。即：这条承诺在仓库里**没有任何东西能说「不」**。

### 1.3 缺陷性质

不是「产品算错了」，而是**契约缺了对手方**：

1. **「抄写一致」冒充「事实一致」。** R51 全绿只证明两处文字逐字相同 —— 文字一字不改而**行为已经漂移**
   时（`语言：` 正是如此），R51 依然全绿。
2. **承诺的量词与实现的分支对不上。** 「扫到这些文件时」是无条件量词，实现却有个前置条件
   （本次语言源文件数 = 0）。这种错位**只在混放场景**才暴露，单语言目录里测不出来。

## §2 黑帽：本轮要防的三类静默失效

1. **用「承诺在不在」冒充「承诺成不成立」。** 若新判据只做「bullet 里有没有关键字」的正则扫，
   它只是 R51 的第三条同义实现，会跟着一起漂。所以判据必须**读公开 CLI 的真实读数**。
2. **空断言。** 只断言「某东西**不出现**」的 case 在「产品什么都不产出」时**也成立**——
   它会在产品彻底坏掉时依然全绿。所以 V3 硬要求每条 case **两向**：
   至少一条「必须出现」+ 一条「必须不出现」。
3. **棘轮只加不查。** `EXPECTED_BOUNDARY_BULLETS` / `EXPECTED_NEGATION_BULLETS` / `MIN_REVERSE_CASES`
   若不与实测**相等**核对，删掉一整条边界承诺、或删掉一整族判据而不改数字，都不会红。

### 2.1 本轮**自己承认**的盲区（写进文档，不藏）

棘轮实测 `EXPECTED_BOUNDARY_BULLETS=8`、`EXPECTED_NEGATION_BULLETS=7` ⇒
**有且仅有 1 条边界 bullet 落在 V1 的网外**：`* Mach-O：…`。

原因：V1 的覆盖范围由 6 个标记词决定（`不识别` / `不做` / `不跟踪` / `按兵不动` / `不保证` / `静默`），
而 `Mach-O：` 写的是**状态声明**（「本机无真实语料，所以报告里仍是 `verified: NO`」），不含任何标记词。
⇒ **它不是「不做」，但「README 两侧都写了 `verified: NO`」这件事同样没人守。**
本轮**不修**这一条（它需要把 V1 从「标记词覆盖」升级为「全部 bullet 覆盖」，
是独立的一件事），但**登记为 C10-7 并写进 §2**，免得下一轮把它当成已完成。

### 本机踩坑（本轮的）

1. **`/tmp` 重定向在 Windows 上不落地。** 往 `/tmp/help.bin` 写 `--help` 没生成文件（`/tmp` 有两种语义）。
   → 改写到 `E:/matlabc/_r55/help.bin`（正斜杠），得 `help bytes = 50451, delta 221`。
2. **JSON 路径猜错一次。** 先按 `c_model.files` 读，得 0 条；实际 C 数据在**顶层 `files[]`**（键
   `['functions','includes','macros','rel']`）。**猜测路径 = 用被测对象的形状当自己的量尺**，
   这类错误只有独立探针能抓。
3. **同一个「测试尾巴」撞两次。** `patch_r55_tests.py` 的锚点命中 **2 次**（R52 与 R53 的测试
   结尾都是 `assert "G1–G7 全绿" in out, out[-600:]`）。**全或无守卫当场拦下、一个字节都没写**；
   改成 EOF 锚点 + 「新符号必须尚不存在」的幂等检查后才落笔。
4. **突变选错了对象。** 第一条 r55 测试在突变 ⑤ 失败 —— 我改的是
   `preprocessing-boundary` 的**正向**期望，导致「必须不出现」条数没变，`V3` 不红。
   → 这是**量尺自己的 bug**，不是门的 bug；换突变对象后通过。
5. **docstring 承诺了、代码没实现**（本轮最有价值的一次）。我在门的 docstring 里写了
   「`case["docs"]` 的 (文件, token) 必须逐字存在」，但 `judge_registry` 里**没写这段检查**。
   只跑真树**发现不了**（真树本来就对）；是**对照组只报 1 项违规、而不是应有的 3 项**
   （两侧 README 一条都没被点名）把它顶出来的。补上后自证 19 → **21**、对照组违规数 1 → **3**。
   ⇒ 印证本仓纪律：**门全绿 ≠ 门有效**，必须靠对照组/突变证明它「能红」。
