## 一、摘要与结论（TL;DR）

**定位**：`matlabc.py` 是一款「**告警质检引擎**」——分析能力已到变量级/字段级/多语言，但展示层停留在「把 JSON 模型打印成 HTML 表格」的阶段，缺乏"代码浏览与理解"的第一性能力。

**最大差距（性质）**：不是功能缺失，而是**结构性空白**——模型层无「文件夹树/文件依赖/函数详情」三类聚合结构，渲染层无「目录树导航/函数详情页/交互式调用图/全文搜索」四项浏览能力，导致 **Doxygen 的"从文件到文件夹、从函数到调用、从静态到可检索"三级浏览体验完全缺失**。

**下一步（做什么）**：按 P0→P1→P2 三阶段，先补「目录树模型 + 函数详情页 + 源码大纲」浏览骨架（1 轮），再补「自包含交互调用图 + 全文搜索 + hover 预览」（1-2 轮），最后补「深色/键盘/响应式 + 度量雷达 + 导出」（1 轮），目标：无网络环境下 3 步内从首页到任一函数源码行。

## 五、根因深度分析（为什么缺，而非缺什么）

1. **定位基因**：工具诞生于"门禁质检"（P94 门禁矩阵、P91 参数位门禁），HTML 站只是「结果报告」，从未定位为「代码浏览入口」。Doxygen 的基因则是"文档/理解"，交互层是主产品。→ 根因是**产品定位**。
2. **单文件自包含架构约束**：13,595 行单文件 + 纯 stdlib + 内网离线（无 CDN），渲染函数全部用 f-string 拼 HTML 字符串，导致：任何交互都要手写 JS/CSS，成本高；Graphviz/ECharts/D3 全部不可依赖。→ 根因是**技术约束**，但可用「自包含 SVG + 预构建 JSON 索引」绕过。
3. **模型层扁平**：`model["files"]` 是 `[{path, functions, ...}]` 平铺数组，没有 `dirs` 树、没有文件依赖图、没有「函数 → 文件 → 目录」的聚合链。渲染层想展示目录树也无数据可用。→ 根因是**模型缺层**。
4. **一次渲染管道**：`--browse` 是「全量静态生成」，无客户端路由/无状态持久化，跨页筛选器（选个目录，所有页面跟着过滤）无基础。→ 根因是**无状态架构**。
5. **未把「自包含」当特性做**：明明可以在**生成时**就把 JS 索引、SVG 图、CSS 主题打进 HTML（构建期计算，运行时零依赖），但从未系统性设计。→ 根因是**思维定势**。

**一句话根因**：引擎与展厅是两套产品逻辑，目前只建了引擎。

## 六、引领性改进方案（P100-P112，按性价比排序）

## 九、引领性结论

1. **定位升维**：从「告警质检报告」升级为「**工程理解门户**」——分析引擎已够强，把 `--browse` 做成"无网络也能用的迷你 Doxygen"，是投入产出比最高的一步。
2. **判断**：当前差距是**结构性空白（模型无层）+ 深度不足（展示有雏形）+ 生态缺失（无可视化/搜索）** 三型并存，其中模型无层是根因。
3. **不做什么（边界）**：不引入 Graphviz/CDN/前端框架（破坏自包含与离线）；不做在线编辑；不做模糊匹配搜索（保持确定性）。
4. **可持续**：把「D1-D10 对照表」作为 self-improvement 自评清单常驻仓库，每次版本升级回填，防回归。
5. **最大杠杆**：P104 函数详情页 + P106 调用图，一次性把"交互友好度"从 30 分拉到 75 分；P107 搜索再拉 10 分；其余为锦上添花。
