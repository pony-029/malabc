# matlabc 深度改进方案：文件夹→文件分析 × 显示/交互

> 分析对象：`matlabc.py`（v1.11.92，118 项测试）
> 对标：Doxygen（文件/目录文档生成）+ Doxygen Awesome 主题（现代 UI 范式）
> 方法：superpower 联动（loop-engineering 定完成标准 + fireworks-tech-graph 图谱视角 + brainstorming 发散方案）
> 日期：2026-08-20

---

## 一、摘要与结论（TL;DR）

**定位判断**：`matlabc` 在「文件夹→文件」这条链路上，**数据层已经很深**（文件头注释、目录依赖、目录循环、复杂度、扇出扇入、入口函数全都有），但**呈现层相对 doxygen 落后**——存在典型的「数据有、呈现弱」错位。

**最大差距（5 个结构性缺口）**：

| # | 缺口 | doxygen 对应能力 | 性质 |
| --- | --- | --- | --- |
| 1 | 文件描述未在列表页展示 | 文件列表页展示文件头注释作描述 | 数据有、呈现缺 |
| 2 | 目录依赖是表格不是图 | 目录依赖**图形化**（Directory Dependency Graph） | 形态落后 |
| 3 | 文件页缺「文件概览卡片」 | 文件页顶部有文件级文档 | 数据有、呈现缺 |
| 4 | 包目录（`+pkg`）无命名空间语义 | Namespace/包列表 | 语义缺失 |
| 5 | 函数索引是扁平表，未按目录/文件分组 | 文件列表分组树 + 成员索引 | 信息架构落后 |

**风格判断**：功能齐全但**体验朴素**（GitHub 工具风），缺暗色模式、卡片化架构、可折叠目录树、搜索引导。

**引领性方向**：从「一页塞满的索引」进化为「**分层钻取的信息架构**」（概览 → 目录 → 文件 → 函数），配合「**现代化视觉系统**」（暗色/浅色主题 + 卡片 + 图形化依赖）。

## 二、现状盘点（文件夹→文件链路 + 风格）

### 2.1 文件夹→文件分析链路（现状已较强）

| 层级 | 现有页面 | 已实现能力 |
| --- | --- | --- |
| 概览 | `index.html` | 目录树、全量函数索引、文件夹调用统计、文件夹依赖、热点分析、交互调用图 |
| 目录 | `dirs/*.html` | 文件/函数列表、扇出/扇入目录、子目录、概览卡片、循环依赖标注、面包屑 |
| 文件 | `src/*.html` | 函数索引、语法高亮源码、调用图下钻、调用路径 BFS、影响面面板、库函数说明 |
| 横切 | `complexity.html` | 文件/目录复杂度热力图 |

**已沉淀的数据**（但部分未呈现）：文件头 `mf.header`（author/date/description）、目录耦合度、目录循环、文件级复杂度。

### 2.2 风格现状（显示/交互）

- **视觉**：GitHub 深色 header + 浅色内容 + 蓝色 accent；源码页语法高亮、函数分块、注释折叠、命中高亮。
- **交互**：搜索（函数/全文/正则）、调用图 SVG 力导向、预览弹窗、调用路径 BFS、影响面面板。
- **弱项**：目录树是纯文本 `<pre>`（不可折叠）、导航 10+ 链接无分组、无暗色模式、搜索无引导、首页信息过载。

## 三、与 doxygen 的逐项差距（文件夹→文件维度）

| 维度 | doxygen | matlabc 现状 | 判定 |
| --- | --- | --- | --- |
| 文件列表页（含描述） | ✅ 每个文件一行 + 文件头注释作描述 | 🟡 目录页有文件列表，但**无文件描述** | 数据有、呈现缺 |
| 目录依赖图 | ✅ 图形化（dot 渲染） | 🟡 表格（扇出/扇入），非图 | 形态落后 |
| 文件页文件级文档 | ✅ 文件页顶部有文件头文档块 | ❌ 直接进源码，无文件概览 | 缺失 |
| 命名空间/包 | ✅ Namespace 列表 | ❌ `+pkg` 包目录无特殊语义 | 语义缺失 |
| 成员索引分组 | ✅ 文件列表分组树 + 复合索引 | 🟡 函数索引扁平表 | 信息架构落后 |
| 源码页文件元信息 | ✅ 文件头（作者/日期/版权） | 🟡 已有 mf.header，但未在页面展示 | 数据有、呈现缺 |

**根因**：数据层（`_collect_*`、`mf.header`、`_compute_folder_edges`）已经很完整，但**渲染层没有把这些数据「用起来」**——这是典型的「分析强、文档弱」错位。

## 四、引领性改进方案

### 4.1 文件夹→文件分析改进（补呈现，非补数据）

**A1. 文件描述进列表**（补缺口 #1、#3、#6）
- 目录页/首页的文件列表，每行展示文件头 `description`（截断 + title 悬浮完整）。
- 源码页顶部新增「文件概览卡片」：文件头 author/date/description + 复杂度 + 函数/类数 + 依赖目录。

**A2. 目录依赖图形化**（补缺口 #2）
- 复用已有的 `render_folder_function_graph_svg` 思路，生成「目录依赖图」（目录为节点、依赖为边、扇出扇入为色阶），替换首页的依赖表格。
- 目录页内嵌「本目录的依赖子图」（只看本目录 + 直接邻居）。

**A3. 包（`+pkg`）语义**（补缺口 #4）
- 识别 `+pkg` 目录为命名空间，目录页/首页标注「包」，函数签名显示 `pkg.func` 全限定名。

**A4. 函数索引分组**（补缺口 #5）
- 首页函数索引从扁平表改为「按目录分组」的可折叠分组（doxygen 文件列表风格）。

### 4.2 显示风格改进（视觉系统升级）

**B1. 主题系统（暗色/浅色）**
- CSS 变量已用 `:root`，扩展为 `:root[data-theme=dark]`，新增暗色主题 + 顶部切换按钮（localStorage 记忆）。
- 暗色配色：背景 `#0d1117`、代码 `#161b22`、高亮 `#1f6feb`，复用 GitHub Dark 语义。

**B2. 卡片化信息架构**
- 概览统计用「渐变卡片 + 图标」，目录页概览、文件页概览统一卡片化。
- 首页导航分组：`文档（类层次/成员索引/注释标签）· 分析（复杂度/静态检查/风险度量）· 图（调用图/分层图）`。

**B3. 现代视觉细节**
- 统一圆角、阴影、hover 过渡；表格斑马纹；代码块配色对齐 GitHub 主题。

### 4.3 交互改进（体验升级）

**C1. 可折叠目录树**（替换 `<pre>` 文本树）
- 用 `<details>/<summary>` 实现可折叠目录树，默认展开，支持展开/折叠全部。

**C2. 搜索引导**
- 搜索框 placeholder 保留，新增：结果计数、上下键选择、Enter 跳转、Esc 关闭、快捷键提示（`/` 聚焦搜索）。

**C3. 调用图交互增强**
- SVG 力导向图新增：滚轮缩放、拖拽平移、节点点击聚焦、子树折叠。

**C4. 返回顶部 / 面包屑**
- 长页面（源码页、首页）加「返回顶部」浮动按钮；文件页/目录页统一面包屑样式。

## 六、引领性判断（超越 doxygen 的方向）

doxygen 的文件夹→文件文档是**静态、单向**的（列表 + 图 + 源码）。而 matlabc 已经沉淀了 doxygen 没有的**分析数据**（文件头结构化、目录耦合、复杂度、循环、入口函数、类型/形状/死代码/未初始化告警）。

**引领性机会**：把「分析数据」注入「文档呈现」，形成 doxygen 做不到的「**带分析的文档**」——例如：
- 文件列表直接标注「该文件有 3 个未初始化告警、复杂度 42、被 5 个目录依赖」；
- 目录页直接标注「循环依赖 + 高耦合，建议拆分」；
- 源码页文件概览直接给出「本文件的复杂度热点函数」。

这比「doxygen 的纯文档」更进一步：**doxygen 告诉你「有什么」，matlabc 可以告诉你「有什么 + 哪里有问题」**。这是本方案的核心引领方向。
