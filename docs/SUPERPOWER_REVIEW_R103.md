## §5 缺口 A：台账摘要入仓

### §5.1 设计（只放指纹）

`docs/PLAN_LEDGER_DIGEST.json`：

* `rounds`：`{轮号: sha256(objective)}`，**只放指纹**，台账原文（`_r82/rounds.jsonl`）**不入库**；
* **故意不记**计划槽数与台账行数 —— 记了就会在每次加槽时报「陈旧」，
  把陈旧训练成噪音（R83 ④）。那两条关系由**仓内用例现算**断言。

生成器 `_r103/gen_plan_ledger_digest.py`：落盘前**先用环路自己的口径现算一遍**
（`ledger_plan_problems`），非空就**拒绝写盘** —— 否则会把坏事实固化成「基线」。

### §5.2 ⚠ 口径修正（本轮自己抓到，**最危险的一类**）

蓝图初稿把集合关系写成 **`摘要 == 计划`**。读 `ledger_plan_problems` 真身
（`_r82/evolve_loop.py:174-199`）发现它的 docstring 明写：

> 「反方向（计划里有、台账里没有）是**正常**的 —— 那是还没跑的计划。」

⇒ 只能是 **`摘要 ⊆ 计划`**。写成 `==` 会把「刚加进计划、尚未执行」**误判成红** ——
一个**永远报红**的判据，迟早被当成噪音关掉（R83 ①：口径类缺陷所有读数一起错且都自洽）。

### §5.3 判据的六个控制（`test_r103_plan_objective_digest_matches_ledger`）

| # | 形态 | 期望 |
|---|---|---|
| ① | 真文件：计划块可解析 + 摘要一致 + `0 < 摘要条数 <= 计划槽数` + schema | 过 |
| ② | **正向控制**：合成的好对 | **必须过**（挡住「判定器永远报红」） |
| ③ | 反向：真计划表某行 objective 尾加一个汉字 | 必须红 |
| ④ | 反向：摘要指纹改错 | 必须红 |
| ⑤ | 反向：摘要里塞一个计划里没有的**幽灵轮号** | 必须红 |
| ⑥ | 反向：摘要 `rounds` 置空 | 必须红（空集先断言非空，R99 ④） |

对照真身：判据只做「摘要 → 计划」一个方向 + 非空 + schema，**不多管**（管的边界写进 docstring）。

### §5.4 变异体三实验（`_r103/mutate_r103.py`）

```
[base    ] rc=0  1 passed
[A inject] 第 0 轮 objective 尾部加一个汉字；计划表 71249 -> 71252 B
[A inject] rc=1  1 failed   ← 注入即红
[restore ] 计划表 sha256 还原=True
[B inject] 摘要第 0 轮指纹首字符改掉；2538 -> 2538 B
[B inject] rc=1  1 failed   ← 注入即红
[restore ] 摘要 sha256 还原=True
[C inject] 摘要 rounds 置空
[C inject] rc=1  1 failed   ← 注入即红
[restore ] 摘要 sha256 还原=True
[final  ] rc=0  1 passed    ← 还原即绿
```

### §5.5 生成器 `--check` 的两向（自己先咬了我一次）

```
注入一字节 ⇒ [FAIL] …与现算不一致（陈旧）  rc=1
还原       ⇒ [OK] …与现算一致（2538 字节 / CRLF）  rc=0
```

⚠ 第一次跑 `--check` 报「陈旧」，**先问哪一边错**：盘上 2,538 B、现算 2,508 B，
**差恰是 30 个 CRLF** ⇒ 我的比较器拿 **CRLF 文本**对 **LF 文本**，
**是量具错**，文件内容是对的。修比较器（先归一 LF 再比 + 顺便断言 `bareLF==0`）。
