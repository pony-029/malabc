## 1. 白帽 —— 事实与读数

### 1.1 这一轮改的是「口径」，不是「功能」

`--callgraph` 的产物里印过一句话：内核整树的最大「调用环」有 **37,775 个成员**。
它不是真的 —— 节点身份是「函数名」，同名不同文件的 `static` 被**合并成一个节点**，
于是互相调用的两个同名函数被读成了一个大环。

这一类缺陷的危险在于它**不在功能层**：调用边一直在正确计算，分析结果一个数都没错，
错的是**怎么把边读成图**。R83 的定论在这里第二次应验 ——
功能错了会有测试红；**口径错了，所有读数会一起错、而且全都自洽**。

修法不是删边，而是换身份：**默认节点 = 「函数名 @ 定义文件」**。

### 1.2 内核整树：三个读数必须一起看

| 读数 | R87（名字级） | R88（定义落点） | 变化 |
|---|---|---|---|
| `nodes_total` | 645,111 | **698,598** | +53,487 |
| `edges_total` | 7,060,966 | **7,060,966** | **0** |
| `cross_file.ambiguous` | 5,149,101 | 5,149,101 | **0** |
| `cycle_stats.components` | 908 | **1,066** | **+158** |
| `cycle_stats.nodes_in_cycles` | 41,008 | **5,235** | −87.2% |
| `cycle_stats.biggest` | 37,775 | **591** | −98.4% |
| `unresolved_total`（不进图） | 1,295,143 | 1,295,143 | 0 |
| `kernel_callgraph.json` 字节 | 3,567,011 | **4,247,921** | **+19%** |

⚠ **反直觉的一条，也是本轮最重要的判据教训**：**环的份数上升了**（908 → 1,066），
而环内节点塌掉 87%、最大环塌掉 98%。⇒ 「**环变少了**」这个听起来最自然的判据，
在这一轮**正确的修复**上会**直接误报**。R87 说「只断言环变少可以被整类不报刷出来」；
本轮实测更进一步：**它连必要性都不成立**。正确的判据是
「**最大分量掉到三位数**」**且**「**边数一个不少**」，两条都要有对手方。

### 1.3 探针：两种夹具，两次纠正

一份口径两份夹具（不是两份实现）：

* `_r88/probe_defsite.py` —— **合成夹具**（A/B/C/D 四段）：假环 3→0、接口面差异逐名登记、
  `hub_of` 边界、渲染不合并。定稿复跑 **FAILURES=0**。
* `_r88/probe_defsite_real.py` —— **真 C 语料**（`matlabc.build_c_model` 真跑）：
  5 棵内核子树 + 一档跨区域语料。判据 **I1–I11**，**0 失败**。

**探针两次纠正了我对 R87 预测的理解**（这是本轮最值钱的方法论）：

1. **「子树里的环也会塌」是错的。** 实测：`fs/nilfs2` 最大环 66 → **66**
   （节点 656 → 656，1,689 条边两端**全是** `K_DEF`）；`net/mptcp` 33 → 33；
   `fs/jffs2` 50 → 50。⇒ **子树内部的环是真实的**，不是同名合并造的。
   5 棵合计只拆出 1901 → 1922 个节点，`K_SITE` **0 条**。
2. **判据不能写成全局命题。** 首版 I8/I9 写成「有名字被拆 ⇒ 环就塌」，
   当场被否证：`init` 拆了 7 个名字而最大环本来就是 0。
   ⇒ 塌陷是**局部**机制，判据必须落在「**这个环里有没有被拆的名字**」上。

跨区域一跑（`CROSS` 档，3,927 文件）：最大环 **1750 → 36**、
边 **68,030 → 68,030**（一条不少）、**1,415** 个名字被拆，其中 **382** 个落在名字级最大环里。
新最大环 36 是 `mm/slub.c` ↔ `mm/page_alloc.c` ↔ `mm/swap.c` 之间的**真环** ——
**塌陷只发生在被拆到的那部分**，没被拆到的照旧留着。

### 1.4 ⚠ 上一轮给的三向判据，我只满足一向

R87 §7 的原话：出口判据必须**两向** —— 同名多定义占比**下降**、
`ambiguous` 桶只准**变小**、且最大分量掉到 **≤ 三位数**。

| 判据 | 本轮 | 说明 |
|---|---|---|
| 最大分量 ≤ 三位数 | ✅ **591** | 直接达成 |
| `ambiguous` 只准变小 | ❌ 5,149,101 **原样** | **结构性做不到**，见下 |
| 同名多定义占比下降 | ❌ 72.9% **原样** | 同上 |

**为什么做不到**：`frontends/ir.py::resolve_calls` 产出的边里**不带**命中的是哪一份定义
（它取的是 `func.name`，没取 `file.rel`）。所以对「同名多定义」的被调者
**判不出调的是哪一份** —— 本投影**不猜**，把它并成一个汇点节点 `K_AMB`，
并把这笔账留在 `cross_file.ambiguous` 里。要让这一桶掉下来，得改**前端**
（让边携带定义落点），不是改图。

替代判据（等强或更强，已写进 F9）：

* **两种口径的 `edges_total` 逐位相同**（7,060,966）—— 这是「**一条边都没删**」的
  **直接**证据，比「桶只准变小」**更难被伪造**：整类不报会同时改掉 `edges_total`，当场红。
* **`cross_file` 四桶逐桶相同**（internal 660,640 / cross 1,251,225 /
  ambiguous 5,149,101 / unknown 0，四桶之和 == 7,060,966）—— 它量的是**边**的性质，
  换节点身份本就不该动它。

⇒ 结论：**三向判据我只满足一向，另两向被「结构性做不到」挡住，用两条等强判据顶上。**
这不是妥协，是一个必须写下来的**能力缺口**（见 §3.2 与 §7.1）。

### 1.5 `hub_of` 里藏着一个真缺陷

**同分时挑到一个「扇入 100、出边 0」的汇点**，于是**默认**焦点子图退化成
**1 节点 / 0 边** —— 用户不给 `--callgraph-focus` 时拿到的是空图。

探针 D1 的两向读数（同一份夹具）：

| 情形 | 子图 |

| 对照（把 sink 当根） | **1 节点 / 0 边** |

### 1.7 一次「差点丢账」：驱动的潜伏缺陷（不是读代码读出来的）

整树重跑两个臂都跑完了（`c` rc=0 / `asm` rc=0），命令却 **EXIT=1**：

```
KeyError: '5400'
```

根因一行：`--arms` 的解析器把后面**任何**不以 `-` 开头的 token 都当臂名，
于是 `--timeout 5400` 的 `5400` 也成了臂名。**崩在写 AGG 之前** ⇒
症状是「分析成功、**记账丢失**」—— 近 20 分钟的读数只剩三份产物，AGG 与 vs_r81 对照全没了。

⚠ 它与 `--extra-c` 那处**是同一个根因**（naive 过滤）：那一处作者已踩过并写下注释
「不要用跳过以 `--` 开头的元素那种过滤」，这一处没有。
**同一根因在第二个位置复现 —— 「修一个点 ≠ 修一类点」。**

修好之后的第二次实测又暴露**第二个**问题：为验证解析器而单跑的 `--arms asm`
**写盘成功**了，但它把 AGG 里**上一轮（R87）的 `kernel_c_summary` 条目原样留下** ——
一份 AGG 里**两套指纹并存**（顶层 `provenance` 是本轮的，`results[]` 里的条目带着
R87 的 `matlabc_sha256` 与墙钟）。合并只按 label、**不核指纹** ⇒
「**一个没跑过的数冒充跑过的**」，而 W2 那道门**看不见它**（它只钉顶层 `provenance`）。
修法：旧条目必须**自带当前被测物的指纹**才准合并进来，不符 ⇒ **丢弃并大声说出**。

⚠ 连带一条操作纪律：**长跑期间不许改被测物**。我在这趟重跑开始后改了 `matlabc.py`
的帮助正文（`7,065,831` → `7,060,966`，**同长度** ⇒ 字节数不变、`matlabc_sha256` 变了），
发现后立刻 kill 并用**冻结后**的文件重开。若没发现，跑完的 AGG 会是
「顶层指纹 A + 条目指纹 B」的自相矛盾产物。

### 1.8 顺带清掉的两类一致性欠账

1. **陈旧读数散落在 5 处用户可见文本里**：`7,065,831` 是 R86 时代的调用边数，
   R87 的属性能修复把它降到 `7,060,966`（`docs/KERNEL_RUN.md` 如实记了这次变化），
   而 **`matlabc.py` 的 `--help` 正文**、`README.md`、`README_CN.md`、
   `docs/matlabc_USAGE.md`、`docs/matlabc_FEATURES.md` **一处都没跟上**。
   `check_help_contract.audit_doc_numbers` **只管「N 道护栏」类数字** ⇒ 调用边数**没有门在守**。
   同长度替换（都是 9 字符）⇒ 帮助字节快照**逐位不变**，门当场自证。
2. **两处仍在用旧标签描述「默认」口径**（`docs/matlabc_FEATURES.md` / `USAGE.md` 的
   `cycles` 说明写着「名字级」）—— 其余几处在**正确地**指代老口径这个可选项，不动。
3. **`docs/kernel_report.html` 仍印着 R75/R84 时代的数**（`7,065,831`），
   但它与 `docs/SUPERPOWER_REVIEW_R75.md` 同类 —— **是历史快照**，不是当前读数。
   本轮**不改它**（改了就等于篡改一份快照），只登记一件事：
   **这份受控文件上没有一处写着「我是哪一轮的快照」**，而它**没有任何门在看**
   ⇒ 读者完全可能把它当成当前读数。这是「唯一事实源指针」（L85）在那份文件上缺失。

## 3. 黑帽 —— 风险

1. **`K_AMB` 汇点 ⇒ 会漏报真环。** 判不出被调者是哪一份定义时，出边归给了
   「各定义所在文件」上的节点 ⇒ **经过它的环不再被报出**。上界 = `cross_file.ambiguous`
   （5,149,101）。取向是「宁可少报，不可错报」，代价**已写进 `limitations`**，由 F7f 钉住。
2. **`ambiguous` 原样不动（72.9%）** —— 上一轮把它当作要塌的那一桶，本轮证明
   **不在图这一层**。这是本轮**没有解决**的问题，不许说成「已解决」。
3. **焦点子图的边数仍然无上限，而且比上一轮更严重。** 本轮默认焦点
   （自动枢纽 `main @ tools/testing/selftests/mm/khugepaged.c`）报
   **34 节点 / 19,460 边**、`hit_node_cap=false`；R87 是 **300 节点 / 14,816 边**。
   ⇒ 节点数掉到约 1/9 而**边数反而涨了 31%**，「按节点封顶」的遮掩效应在定义落点口径下更弱。
   产物字节 **3,567,011 → 4,247,921 B（+19%）**。⚠ 注意这与 R87 §8 那条
   「**字节数变化 ≠ 图变化**」**方向相反**：R87 的 2.72× 几乎全部来自被截断的有界投影，
   图本身没动；这一轮的字节变化**确实由图变化驱动**，而驱动它的正是**这个没有上限的投影**。
   R87 §8 登记的 `--callgraph-max-edges` 仍然欠着。
4. **焦点行与 R87 不可比**（必须声明）：R87 那趟显式给了 `--callgraph-focus memcpy`
   （故 `direction=both`），本轮没给（走自动枢纽，`direction=callee`）。
   两行都是真的，但**不是同一个问题的两个答案**。
5. **调用边数散落在 5 处用户可见文本里，没有任何门在守**（§1.8）。
6. **`check_all.py` 的 ASCII 树行没有任何门在看** —— H1 显式把 runner 排除在外。
   本轮第一次只改了 5 处级联、漏掉树行，是靠 `EVOLVE_ROADMAP_360.md` 里写过
   「六处」才想起来。**级联点的清单本身没有对手方。**
7. **墙钟未归因**：R87 631 s → R88 1165 s（+85%）。已排除 O(E×D) 二次爆炸
   （`_sym` 是 O(1)、`_defset` 带缓存），但**未归因到唯一原因** ——
   definition-site 分支的额外字符串构造（`_key` + `SEP` 格式串）与
   「我自己把门禁与重放和重跑并发跑了」两者都可能是主因。按纪律，墙钟属时钟键，
   **不参与** R81⇄R84 逐位对照，也**不许**用它归因版本。

## 4. 黄帽 —— 价值

- **用户直接看到的产物不再有假环**：最大「调用环」从 37,775 掉到 **591**，
  而**边一条没删** —— 拆的是节点身份，不是证据。
- **口径写进了产物**：`call_relations.identity` / `evidence_kind` 自述，
  并且**是登记表里的头两行**。理由是实测出来的：换口径后 `biggest_cycle` 塌了、
  `nodes_total` 涨了，而 `edges_total` **一个都没变** —— 只看后面几行会以为
  「图被大改」，实际是**同一张图换了身份口径**。
- **可复现基线并存**：老口径 `--callgraph-identity callee-name` 仍可显式选中，
  于是「37,775 是怎么算出来的」**随时可复现**，不用信任一段散文。
- **节点键编码可推广**：`kind + U+001F + rel + U+001F + name` ——
  U+001F（Unit Separator）**在文件名里不合法** ⇒ 切分不会错位。
- **不猜的取向被钉住**：`limitations` 必须与 `identity` 对得上，
  由 F7f 钉住「口径与它的局限必须一起写下来」。
- **新增公开名 13 个、签名变更 4 个**逐名登记在探针 C 段里 ——
  接口面的变化**不靠读者 diff 发现**。

## 5. 绿帽 —— 想法

1. **同一文件内的定义落点消歧**（下一轮首选）：被调侧有多份定义时，
   若**恰好一份**在调用者所在文件里，那它就是解析结果 —— 这是 **C 的作用域规则**
   （另一个 TU 里的 `static` 本来就不可见），**不是猜**。
   它能真正让 `ambiguous` 掉下来，且不需要改前端协议（改写 `resolve_calls` 的归属即可）。
2. **`--callgraph-max-edges`**：焦点子图的边数必须也能封顶，
   并且**撞上限要显式上报**（与 `hit_node_cap` 同一个口径）。
3. **把 argv 写进登记表**（R87 已登记、本轮顺延）：本轮焦点行不能与上一轮比，
   根子就是过程参数只活在命令历史里。产物自述了 `identity`/`evidence_kind`，
   下一步该自述**整条 argv**。
4. **「已知噪声登记」范式**（R87 提出）继续推广：把「已知的、不是缺陷的」读数
   显式列出并断言「不多不少」。
5. **「会烂的散文数字」需要一个守的人**：现在的机制只管护栏数（§1.8）。
   最小可行做法不是加一道门，而是把这些数字**收敛到一个产物**（登记表）
   然后让别处只引用、不重抄。

## 6. 蓝帽 —— 流程与元

- **门数刻意不变（仍 19）**：0j 只给 `check_c_frontend_shapes.py` 加判据族 F9
  （F1–F8 → F1–F9），不加闸门 —— 「缺口为 0 时加闸 = churn」（R85 定论）。
- **六处级联**：门自身 / **`check_all.py` 的 ASCII 树行** / `GUARD_CONTRACT` /
  `tests/test_matlabc.py` / README ×2。⚠ **树行最容易漏，而且它没有任何对手方。**
- **「会走进文档与提交信息的数字，必须有一个能在下次重算它的装置」**（L67）：
  本轮 `--help` 的字节快照是**批准**（56566→57451 / 46929→47659），
  **带宽 ±64 一个字不动** —— 加功能就更新快照，不放宽带宽。
- **同长度替换是可控的**：`7,065,831` → `7,060,966`（都是 9 字符）⇒
  帮助字节数与规范形**逐位不变**（门当场自证）。但**内容**变了 ⇒ 指纹变了 ⇒
  **长跑必须先冻结被测物**（§1.7）。
