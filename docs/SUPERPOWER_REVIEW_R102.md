## §3 白帽：起点侦察（**以源码与实测为准，不轻信文档声明**）

### §3.1 那个缺口是怎么被量出来的

R101 做了一件对的事：**去真跑一遍整套 `tests/`**。它跑了**两次**，两次的红数**不同**：
`24 failed / 508 passed / 4 skipped`（它 §15 记录的那次）与
`23 failed / 509 passed / 4 skipped in 2093.63s`（`_r101/pytest_full_r101b.log` 那次）。
⚠ **总数恒为 532**（24+508 = 23+509 = 532），差 1
⇒ **至少有一支用例是非确定的**（与宿主负载相关）。
可用的逐条 `FAILED` 列表**只有后一次**（23 条）
⇒ **本轮的逐条裁定以那 23 条为准**；第一跑多出的那一条
**没有日志可查** ⇒ 如实记为边界，由本轮第三次全量跑
（`--with-tests`）裁定。这件事直接给「`passed` 容差 = ±5」
提供了**实测依据**：同一棵树的两次跑本来就差 1 条。

但更值得注意的是**为什么**这批红能积压两轮：

```
tools/check_all.py  ──▶ 只跑 tools/ 下的 check_*.py          （21 个护栏脚本）
                    ──▶ **结构性**不跑 tests/                 ← 缺口在这里
tests/test_matlabc.py ─▶ 536 条用例（R101 收集数），从 R99 起红着 23 条
```

R99 起每一轮都只跑**定点**用例（R100 只跑了一条），于是：

> **门禁绿 ≠ 测试绿**；而「测试红」在 R101 之前**没有任何聚合入口**。

这与 R82 的结论同源：**门禁绿 = 恒等式成立 ≠ 覆盖度足够**（本轮是它的第 4 次应验）。

### §3.2 红线清单（动手前先立）

## §4 23 条红的逐条裁定（18 量具错 / 2 真缺陷 / 3 过期）

### §4.1 18 条 = **量具错**（站点同名页有三个家族）

R99 让 MATLAB `--browse` 站点接入了 C/Py/JS 的同一份基础层，于是**同一个文件名出现在三个目录**：

| 家族 | 目录 | 内容 |
|---|---|---|
| 宿主源码页 | `src/` | 带调用图 / 结构体图例的**主**页 |
| 基础层文件页 | `file/` | 跨语言统一的文件清单页 |
| 基础层源码页 | `xref_src/` | 基础层的源码页（R99 为避开与 `src/` 冲突而落此） |

而测试助手只按**文件名**找：

```python
def _glob_file(base, name_sub, suffix=".html"):
    for root, _dirs, files in os.walk(base):      # ← os.walk 字母序先撞 file/
```

于是 18 条断言对着 `file/` 页说「源码页缺少 X」。**裁定依据**：R101 已用 `git stash`
回 HEAD 复现同一断言 ⇒ 与当轮改动无关；且**站点页本身没坏**（`fe_audit` 另说，见 §4.2）。

修法（**不是**放宽断言，是让定位器**指名家族**）：

- `_glob_file(..., subdir=None)` + `_SRC_FAMILIES = ("src", "xref_src")`，不给 `subdir`
  时按家族顺序找，最后才全树兜底（`index.html` 这类不属于任何家族的页）；
- `sorted(files)` 消掉 `os.walk` 的跨文件系统顺序不确定性；
- **对手方**：新用例 `test_r102_site_locator_names_the_page_family` —— 造一棵
  「`file/` 先建」的最小站点树，断言定位器取到的是 `src/`；并反向断言
  `subdir="dir"` 找不到时必须返回 `None`（**不许串门**）。

### §4.2 2 条 = **真缺陷**（`fe_audit` 的 94 条 WARN，横跨三条规则族）

| S19 | 13 | `file/` 页与宿主源码页**标题逐字相同**（同一份页面名，两份不同内容） |
| S7 | 2 | `dir/` 页只在被 `skip_index` 跳掉的索引里有入口 |

**这两条不是量具错**（`fe_audit` 报的是三条**规则族** S9/S19/S7，
落到**两条**用例上：`test_p271_fe_audit_ratchet_baseline` 与

  「`<rel> · 文件`」并挂「所在目录」回链。删除行 **恰 8 条**（7 条为提前/删除的构造 + 1 条旧 `_head` 调用）。

### §4.3 1 条 = **量具过期**（r76 页数公式）

`test_r76_c_site_is_paginated_and_styled` 实得 13 页 ≠ 硬编码 12 —— 差的是

修法：页数公式**由产物推导**（`funcs/deps/索引/根页现算`），不写死。

### §4.4 1 条 = **表过期**（跨命名空间两向登记表）

`test_r72_cross_namespace_families_are_registered` 实测多出
`{'tools/check_browse_clean_manifest.py': {'R'}}` —— R100 新增的**第 21 道门**没有登记。

归因（**量具的宽读，不是判据缺口**）：该门 docstring 用**双引号**写了 `"R100：…"`，
被宽读器 `_JUDGE_LIT_RE = ["\']([A-Z]{1,3}\d+[a-z]?)([ :：　])` 命中；
而同类门的 R 族历来来自**单引号** docstring。修法：补登记 + 写清「这是轮次引用被宽读」。

### §4.5 1 条 = **分母过期**（p77 性能阈值）

`test_p77_incremental_perf_benchmark`：80.40 s / 90.43 s > 60 s。**决定性实测**：

| N | 页数 | 墙钟 |
|---|---|---|
| 200 | 631 | 20.28 s |
| 400 | 1231 | 39.50 s |
| 800 | 2431 | 83.41 s |

`t(400)/t(200) = 1.95`、`t(800)/t(400) = 2.11` ⇒ **线性**（每页 ≈34 ms），**不是 O(n²)**。

`cProfile`：`{built-in method _io.open}` tottime 20.28 s / 3428 次（占总 22.77 s 的 89%）；
`_finalize_site_html` 11.75 s；`_write_site_manifest` 8.56 s。
IO 单价对照（2800 B 的页）：写 0.53 ms / 读 0.88 ms / 覆写 0.80 ms
⇒ 本环境 **C:（系统盘）≈7× 慢于 E:**，宿主负载是主因。

根因：60 s 的**绝对**阈值标定于「每文件 1 页」时代（60 / 830 ≈ 72 ms/页），
而站点现在每文件 **3** 页。修法：**按页数归一 75 ms/页（页数现算）** + **非空断言**
（页数为 0 ⇒ 归一化分母为 0 ⇒ 判据恒真，必须先断言 `n_pages > 0`）。**同量级，不放松。**

## §5 给「测试红数」补对手方

### §5.1 为什么它只能是**开关**，不能是第 22 道门

R99 的教训摆在眼前：**门禁绿 + 测试红 ⇒ 至少一个量具错**。也就是说，**测试本身是
「门在具体输入上测得对」的证据来源**。把测试基线做成第 22 道门，会让「门」去审「门的证据」，
并在出错时把两个层次的失败混成一个信号；而做成 `check_all.py --with-tests` **开关**，
则保持层级清晰、且**不触发**判据签名的七处级联。

### §5.2 基线的判据（`test_baseline_problem`，两向）

| 情形 | 结果 |
|---|---|
| 红数**变多** | 红 —— 新红没有任何门在看 |
| 红数**变少** | **也红** —— 有人修好了，请来改表（与 R72 跨命名空间表同一条纪律） |
| 通过数**掉出**容差 | 红 —— 测试被删或被跳过 |
| 通过数**上升** | **不判红（设计内）** —— 容差是**单边**的：真身只有 `passed < base_passed - tol` 一条，**没有上界判据** ⇒ 加测试是良性的（「新坏掉的测试」已由 `failed > 0` 那条堵住）|
| 换了**解释器** | 红 —— 读数不可比，重录基线而不是把差异读成退化 |
| **取不到汇总行** | 红 —— 不许把「根本没跑起来」读成「全绿」 |

自证：`check_all.py --selftest` ⇒ `SELFTEST COUNTS {"bad": 0, "good": 16}`（新增 6 个基线样本 + 1 个解析器样本）。

**单边容差是被探针抓出来的**（不是想出来的）：第一版探针假设「通过数远超容差 ⇒ 红」，拿 `(0, 999, 4)` 试 ⇒ 返回 None。**先问哪一边错** ⇒ **量具错**（探针的期望写错了），判据的真身是 `if passed < base_passed - tol`。改探针、不改判据；`_r102/probe_baseline_verdict.py` 现为 **6/6 相符**（实测汇总 + 5 个反向/设计内控制）。

### §5.4 ⚠ 同一形状的**第五次**：连「正证据」也会被 `return 1` 挡住

`_tests_prob` 的**计算**独立之后，它的**正证据**却仍排在 `return 1` **之后**：

```text
check_all: pytest 退出码 0
check_all: 实测汇总 (failed, passed, skipped) = (0, 534, 4)
check_all: 1 项失败：['check_kernel_snapshot.py']        ← 当时 W2 还没重跑
（「测试基线一致」这一行**没有**出现）
```

⇒ 读者只能看到**汇总数字**、看不到**裁决** —— 「判了且一致」与「根本没判」又被混成一个信号。
本轮的回填脚本就因此**误报**了一次（「日志里没有一致性行 ⇒ 本门自己判红」）。
修法（`_r102/patch_checkall_r102e.py`）：把那一行移进 `elif`，与 `_tests_prob` **同时**结算 ⇒ **正反两面都能独立看见**。
`check_help_contract`（退出码契约）与 `--selftest` 复跑全绿 ⇒ 契约未变。

### §5.3 解释器口径：**用版本串，不用路径**

原设计把机器相关的**路径**写进基线并与实测路径逐字比 ⇒ 换台机器、同一个 3.10 也会红。
改为 `python_version: "3.10.10"` 与 `PYVER = sys.version_info[:3]` 比对 ——
**这是「改正量具」，不是「放宽判据」**（路径也没被提交进仓库）。

同时把**容易踩的坑**写进帮助与报错：测试门用**当前解释器**跑 pytest
（`py = python_exe or sys.executable`），所以 `--with-tests` **必须用录制基线时的那个解释器**跑；
换解释器会判红，那是「读数不可比」，不是测试退化。

## §6 🔥 R101 把环路搞砖死了两处 —— 而没有任何东西在看

这是本轮**最有价值的发现**，也是「真正的实现」与「只改表」的分水岭：
修完测试网之后，按规范去跑一次**真正的**环路预检，才发现环路**根本起不来**。

```
$ python evolve_loop.py --plan
PLAN 解析失败（缺输入即红）：E:\matlabc\malabc\docs\EVOLVE_ROADMAP_360.md
```

### §6.1 F1：槽 25 的末列以 ` |` 收尾 ⇒ 该行 7 列

`load_plan()` 的严格规则：

```python
cells = [c.strip() for c in s.split("|")]
if len(cells) != len(PLAN_COLS):     # PLAN_COLS 有 6 列
    return None                      # ← **整块**不可信，不是「跳过这一行」
...
if plan is None:
    print("STOP  路线图里解析不到 ROUNDS:PLAN v1 —— 缺输入即红")
    return 2
```

R101 把落地记录塞进槽 25 的**末列**、并在末尾多带一个 ` |` ⇒ 该行切出 **7 列**。
实测：该行 515 字符 / 7 列；`load_plan() -> None`。

### §6.2 F3：槽 23 的 `objective` 漂移 26 字

修好列数之后再跑，**仍然**起不来：

```
ledger_plan_problems -> ["第 23 轮的目标文本与计划不符（台账=…'实测记分牌 40 yes / 16 no / 8 na'
                    / 计划=…'实测记分牌 40 yes / 16 no / 8 na（R101 槽 25 落地后 47 / 9 / 8）'）"]
```

`run_loop()` 对**非空** `plan_probs` 直接 `return 2`。根因：R101 把一句注记
追加进了槽 23 的 `objective`，而本仓明文纪律是
「轮 N 的 objective 保持**逐字等于台账** —— 台账是不可改的事实」。
（R95 那句「逐字对齐归零」说的正是这件事。）

计划 301 字 vs 台账 275 字，**差 26 字**，逐字对账只差这一处。

### §6.3 为什么坏了两轮没人知道

```
R86 砖死（预检非空即 return 2）──▶ R95 逐字对齐归零 ──▶ R99 的 E10 判据：
        `python _r98/verify_loop_plan_r98c.py` ⇒ `load_plan -> 39 槽`
                                            ↑ 结论只写进了复盘文档，**不可重跑**
```

R99 的 E10 把「环路预检 0」的证据**写进了 `SUPERPOWER_REVIEW_R99.md` 的表格里**，
但没有任何**可重跑**的东西在看着它 ⇒ R101 破坏之后，下一次没人再跑那条探针。

**这与 §3.1 的缺口同构**：一次性的手工探针 = 下一轮同形状的事故。
R99 在站点页上刚吃过一次（同名页家族），R101 在计划源上又吃了一次。

### §6.4 处置

### §6.5 顺手修掉的第三处：测试门会被别人的红整个挡住

读 `check_all.py` 的 `main()` 时发现：

```python
    if bad:
        print("check_all: %d 项失败：%s" % (len(bad), bad))
        return 1                      # ← 这里就返回了
    ...
    if "--with-tests" in argv and ...:
        prob = tests_gate_problem(tools_dir)     # ← **永远走不到**
```

即：**只要有一道护栏红，「测试红数」就又失去了对手方**。
一条会「在别人红的时候静默失效」的判据，与没有这条判据只差一层**错觉** ——
它看起来在守，其实没守。本轮要补的正是这种东西，不能自己再犯一次。

修法：两条判据**各自独立行使**，最后一起结算 rc。代价是护栏红时也会真跑一遍
整套 `tests/`（≈35 分钟）—— 但那正是 `--with-tests` 这个**显式**开关的语义：
**要么不跑，要么就给出汇总。**
