# SUPERPOWER_REVIEW_R49 —— 跨行签名感知 · 一台「对照装置」照出两处存量缺陷 · 活代码真漏归零

> 本轮主题：把 C 前端的函数定义识别从**行锚定正则**换成**词法 + 括号配平扫描**。
> 这是 R43/R44 反复记录、始终没动的 **C''''1（最高优先）**。
>
> 一句话结论：在 glibc-2.37（13,527 个 `.c/.h`）上，**被漏掉的定义从 15,471 条
> （99.05%）降到 4 条，且那 4 条全在 `#if 0` 死区里 —— 活代码真漏 = 0**；
> 旧实现误报的 9 条假阳性同时归零。**过程中另有两处存量缺陷被「对照装置」当场照出来。**

## §2 黑帽：本轮抓到的真问题

### 2.1 目标缺陷：跨行签名（P2/P3/P4 整类不可见）

`_RE_C_FUNC` 的中间段是 `[A-Za-z0-9_ \t\*]*?[ \t]+`，字符类里**没有 `\n`**，
整条又被 `(?m)^` 行锚定 —— 所以「名字(参数) {」必须**全在同一行**。
glibc 的主力写法恰恰相反（返回类型独占一行），P3 一人就占 15,266 / 15,619。

### 2.2 第二处：行计数对**字符串字面量里的花括号**完全失明

把跨行签名修好之后，仍有 **40 条**漏识（0.26%）落在同一类文件上。
根因不在签名，而在**函数体边界**：

```c
fputs ("{\n", ctx->fp);      /* 字符串里的 `{` —— 行计数把它当成真花括号 */
fputs ("\n}", ctx->fp);      /* 字符串里的 `}` —— 同理 */
```

旧实现用 `line.count("{") - line.count("}")` 判闭合，**不看字符串也不看注释**。
于是 `json_document_begin` 永不闭合，把 `json_document_end` **整个吞掉**。
修法：`_scan_c_definitions` 已在词法层维护深度，顺手回填配对的 `}` 行（`end_line`），
逐行循环优先用它；拿不到（未闭合）时退回原行计数（行为保持）。
效果：漏识 40 → 4。

### 2.3 第三处：词法层**行号漂移**（三小类）

残余 4 条之外的 3 条活代码漏识，根因是 `_c_lex` 的行号不准：

1. **字符串续行**：`if text[j] == "\\": j += 2` 把 `"…\` + 换行的那个 `\n`
   **跳过却没计行**。实测 `nss/getent.c` 因此漂 −4 行 ⇒ 该文件之后**每个函数的
   `line` 都偏小**，`defs_by_line` 永远对不上 ⇒ 定义被丢掉。
2. **`//` 续行**：C 里 `//` 注释也能反斜杠续行；不认就会把注释正文 token 化。
3. **多行 token 记结束行**：`toks.append(("str", "", line, i))` 里的 `line`
   此时已是结束行，而 `off = i` 指向起始行 —— 恒等式不成立（对识别无功能影响，
   但让「漂移 == 0」这条不变量无法断言）。

三处都修完之后，恒等式在全语料上成立（§1.6）。

### 2.4 自伤 ①：`params` 切片多带一个 `(`

自证第一轮就红了 5 条，其中 1 条是真 bug：
`text[off + len(txt):toks[rp][3]]` 从 **`(` 本身**开始切，于是**每个函数的
第一个参数**都变成 `"(int a"`。这属于「一眼看不出来、但会污染报告表格」的错误。
**它不是靠人眼发现的，是靠对照装置 A/C 的逐字段比较当场抓住的。**

### 2.5 自伤 ②：样本选错 —— 顺手量出**第三处**老缺陷

自证另外 4 条红是**我自己的样本选错了**：我假定
`char *dup(const char *s) { … }` 这类单行定义旧正则会认 —— **它不认**。
`_RE_C_FUNC` 的 `[A-Za-z0-9_ \t\*]*?[ \t]+` 要求**名字前必须是空白**，
所以 **指针返回类型紧贴函数名**（`int *pi(` / `char *dup(`）整类不可见。

这不是跨行问题，是**又一处独立的老缺陷**（R49 顺手量出来的），
于是自证被拆成两组：**agree**（旧正则认得的，必须逐字段一致）与
**beyond**（旧正则不认、新实现必认：P2/P3/P4 + 指针返回类型）。

跑受影响家族（83 条）时发现 **7 failed**。逐条看，它们断言的是**仓库里从来
不存在**的东西：

## §3 黄帽 / 绿帽：收益、边界与替代方案

**收益**

- `unresolved` 假阳性在真实 C 语料上**归零**（B 独有 9 → 0，活代码真漏 0）。
- 报告里的「返回类型 / 参数 / 行号」第一次覆盖**全部**函数，而不是 0.4%。
- 函数体边界不再被字符串里的花括号带偏（这是**一处静默的数据损坏**，此前无从察觉）。
- `_RE_C_FUNC` 从「唯一实现」变成「有独立证人的对照装置」——**替换而不是删除**，
  保留了 15 年使用史所积累的验证。

**明确声明**的边界（不做、也不静默）

- K&R 老式定义 `f(a, b) int a; int b; {`：`)` 后面不是 `{` ⇒ **不识别**。
- 返回函数指针 `int (*f(int))(void)`：`)` 后面是 `(` ⇒ **不识别**。
- 宏拼出来的签名（如 glibc 的 `STRCPY (…)`）以**源码里的名字**出现（`STRCPY`）——
  不展开宏是本项目一贯的立场，不是漏。
- 函数体内的**调用**收集仍走 `_RE_C_CALL`（行锚定），跨行书写的调用表达式仍可能漏。
  **R49 只解决「定义识别」，没有顺手动调用**（见 §8 C'''''8）。

**替代方案与为何没选**

- *完整 AST / 引入 `pycparser`*：违反「离线、零依赖、兼容 3.6.5」。R44 的门槛是
  「若 < 1% 就只修跨行签名」；实测是 **99.05%**，所以修，但仍用**自研词法**而非 AST。
- *只把正则改成 `(?s)` 允许跨行*：会**大幅扩大误报面**（正则跨行后会吞掉任意
  跨语句文本）。R44 §9 已明确拒绝「为让判据通过而放宽判据」。
- *把 `_RE_C_FUNC` 删掉*：那就丢掉了唯一的对照证人（§1.1）。

## §4 蓝帽：本轮建立的不变量

1. **定义计数不变量**：活代码里「装置 A 有、B 没有」必须为 **0**（本轮实测 0）。
2. **假阳性不变量**：B 独有必须为 **0**（本轮实测 0）。
3. **行号恒等式**：`token.line == 偏移所在真实行`，全语料漂移 **0**。
4. **行为保持不变量**：两装置都认得的函数里，「消失」必须为 **0**（本轮实测 0，
   且 45/46 的 (line, body_start, body_end) **完全一致**）。
5. **对照装置不变量**：凡是 `_RE_C_FUNC` 认得的单行定义，新扫描器的
   name / ret / params 必须**逐字段相同**（自证 agree 组，实测 5/5）。
6. **形态自足**：四种书写形态（P1/P2/P3/P4）+ 指针返回类型，各有一把手写样本
   （自证 beyond 组，实测 5/5）；且**控制语句 / 调用 / 宏一律不假阳**（实测 4/4）。

自证读数：`SELFTEST COUNTS {"bad": 0, "good": 22}`。

## §8 C'''''1–C'''''10：下一次建设性意见

排序原则不变：**优先「已有装置但没接上线」与「已有承诺但没装置」**，
每条都必须先说清「**什么会红**」。

**C'''''0（阻塞项）把 `fe_audit.py` 与 `.github/workflows/frontend-gate.yml` 补齐，或把 7 条测试显式登记为「不做」。**
现在 `tests/` 有 **7 条永久红**（§2.6）：它们断言的两个产物**从未被提交**。
这比一个功能缺陷更值得先处理 —— 因为「守护慢到没人愿意跑」与「守护永远是红的」
是同一种疾病：**红变成背景色之后，真红就没人看见了**。
落点：要么补 `fe_audit.py`（一个只做前端审计的独立入口）与那条工作流，

## §9 明确拒绝做的事（避免下一轮走回头路）

1. **不为跨行而把正则改成 `(?s)`。** 它会吞掉任意跨语句文本，制造比现在更糟的
   假阳性（与 R44 §9 第 3 条同源）。
2. **不引入 AST / 第三方解析器**（`pycparser` 等）：违反离线零依赖与 3.6.5。
3. **不删 `_RE_C_FUNC`。** 它是**对照装置**；删掉等于销毁本轮唯一的
   「行为保持」证人。
4. **不用 `git diff` 当行为保持的证据。** 它按同一套规则把两侧都归一化了；
   本轮用的是**逐函数元组比较**（§1.5）。
5. **不把「装置 A 独有」直接当产品缺陷。** 必须先按 `#if 0` 分型 ——
   R49 一开始就是把 4 条死区假阳性算成了产品漏识。
6. **不在仓库外留判据。** 探针可以放 `_r49/`，但任何「说得出什么会红」的断言
   必须进 `tools/` 或 `tests/`（这正是 C'''''1 的理由）。
