# R89 复盘 —— 调用图的**解析阶梯**（Phase 0k · 轮 16）

> 轮次 **16**（Phase **0k**，线路 `t2`）· 判据族 **F1–F10** · **门数 19（刻意不变）**
> 入口：R88 复盘 `docs/SUPERPOWER_REVIEW_R88.md` §7 ①（「同文件内的定义落点消歧」）
> 本轮的一句话：**把「不猜」做成一条**有分母**的阶梯 —— 能判的判出来，判不出的数出来。**

## 0. 先看结论（三行）

| 问题 | 结论 |
|---|---|
| R88 §7① 说的「同文件消歧是让 `ambiguous` 真正掉下来的路」 | **错**。跨区域语料上它只值 **9.9%**；加 `#include` 闭包三明治也只到 **18.4%** |
| 那剩下的 81.6% 是什么 | **这一层判不出来**（同名宏遮蔽 / 函数指针 / `#ifdef` / 语料切片外定义），不是「还没修」 |
| **三层对账装置抓到了什么**（R89k） | **一个真缺陷**：`include_graphs()` 的 `under` 图按 include **行数**判唯一性 ⇒ 共享头整条被丢出 ⇒ 第二级在真语料上**一条也判不出来**（引擎 `include=0`，而独立量具测出 **2,034**）。修复后引擎与量具**逐位相等** |
| 顺带挖出的第二件事 | `matlabc._rel_of()` 对「被分析目录在 cwd 之外」的路径会把 `rel` 塌成 **basename** ⇒ 阶梯读数**依赖调用者的 cwd**（内核实测 `same_file` 381290 → 348353）。**只登记 + 列 R90 第一候选** |
| 这一轮真正交付的东西 | 一条**只走「恰一份」**的作用域阶梯 + `resolution` **五档**（之和恒等于 `edges_total`）+ `local_scope` 产物自称参数 + 判据 **F10a–F10k** + 探针 **140** 条 + 变异体 **12** 个 |

**最重要的一句**：这一轮的价值**不在**「救回了 18.4%」，而在**把「救回了多少」变成了一个
带分母、可被别人独立算一遍的数** —— 三支**先于产品**的量具（预登记）与产品在同一批文件上
逐位对账，对不上就拒绝记账。

## 1. 动因：R88 §7① 的预期，以及它错在哪

R88 交给本轮的建议是：

> ① **同一文件内的定义落点消歧** —— `resolve_calls` 侧的一条 **C 作用域规则**（被调侧多份定义时，
> **恰好一份**在调用者所在文件里 ⇒ 用它；**不是猜**：另一个 TU 里的 `static` 本来就不可见）
> ⇒ 这是唯一能让 `ambiguous`（内核 5,149,101 = 72.9%）**真正掉下来**的路。

这条建议的**方向**是对的（它是 C 语义的既有部分，不是新发明的启发式），但它对**幅度**的预期
没有任何证据。本轮先造量具再改代码，量出来的结果把它当场否证：

| 口径 | CROSS 档（8 区域 / **3,927** 个 C 家族文件 / **68,030** 条边 / 23,957 条歧义） | 占比 |
|---|---|---|
| 唯一命中（rung 0，R88 已有） | `unique` **44,073** | 64.8% |
| **rung 1 同文件优先**（调用者文件里恰一份定义） | `same_file` **2,370** | 歧义的 **9.9%** |
| 松判据：闭包内**有**候选就用 | `rung2_loose` **4,059**（**含假包含** ⇒ 不可用） | — |
| **rung 2 三明治**（`vis_under == vis_over == {同一份}`） | `include` **+2,034** ⇒ 合计 **18.4%** | 歧义的 **18.4%** |
| 残余 | **19,553** | **81.6%**（其中 **3,558** 的**调用点落在头文件里**） |

⚠ **这张表刚才差点变成「半张假账」**（R89k 的由来）。表里的 `include +2,034`
是**独立量具**测出的**潜力**，而产品当时一条也没兑现 —— 账本的**三层对账**
（① 先对分母 ② 两侧语料标签一致 ③ 两个桶**逐位相等**）在真语料上当场红：

```
!! measure_scope    说 same_file=2370，引擎报 2273
!! measure_sandwich 说 include=2034，引擎报 0
```

两条失败的**根因不同**，判别实验（`_r89/dbg_cross_reconcile.py`）把它们分开：

* `same_file` 那一层**与判据无关** —— **同一份模型**上 `callrel._edge_res`
  与量具规则**逐边 0 差异**（都给 2,370）。差值来自**另一份模型**：
  账本用「`cwd=仓库` + 绝对根」调 CLI，而 `matlabc._rel_of()` 会把 cwd 之外的
  `rel` **塌成 basename**。⇒ **装置本身的调用形态错了**（已改成规范形态），
  同时把这条产品敏感度**登记进 `limitations`** 并列为 R90 第一候选。
* `include` 那一层是**真缺陷** —— `include_graphs()` 的 `under` 图按 include
  **行数**判唯一性（`by_base[b] += 1`）⇒ 被 ≥2 处包含的头（内核里**最常见**的
  形状）**整条被丢出**欠近似图 ⇒ 三明治在主战场上**恒失败**。按 include 边算：
  行数口径只留 **606 / 28,333**，目标数口径留 **7,823**。
  修法（R89k）＝把唯一性判成「这个 basename **解析到几个目标文件**」，
  并把口径名登记进 `local_scope.under_basis`。修复后引擎
  **`include=2034` / `ambiguous=19553`**，与量具**逐位相等**。

三支量具的先后顺序本身就是一条方法：

1. `measure_scope.py`（**只看同文件**，不调用新代码）：2,370 / 23,957 = **9.9%**，
   并且量出**同名宏遮蔽 89 条** —— 这 89 条**永远**判不出来（预处理才能知道谁被替换）。
2. `measure_ladder.py`（rung0/rung1/rung2**松**/残余）：松判据 **31.2%** —— 看似「一加闭包就救一半」，
   但**假包含**会把「可见 0 份」抬成「可见 1 份」。这条量具的作用是**否证一个假的好消息**。
3. `measure_sandwich.py`（三级：`closure_under ⊆ 真 TU ⊆ closure_over`，两侧必须对上同一份）：
   **18.4%**，`FAILURES=0`；并把残余记成「**这一层判不出来**」，逐项列出原因。
4. `measure_incx.py`（第四支，**为三明治找对手方**）：basename 撞车语料上
   `under != over` ⇒ 把三明治松成 `if vu or vo:` 的错报**当场可见**。

**教训（R83 的第三次应验）**：口径类缺陷不会让任何一处读数变红 —— 它让**所有读数一起错且全都自洽**。
所以本轮的出口判据**不是**「`ambiguous` 必须下降 N%」（那个数随时可以靠换分母变好看），
而是：**五档之和 ≡ `edges_total`** + **三口径 `unique`/`external` 逐位不变** + **与预登记量具逐位相等**。

## 2. 口径设计：两级阶梯、五档分母、三条边界

### 2.1 两级阶梯（`callrel.py`，`CALLREL_VERSION = 3`）

```
被调侧多份定义（否则 R88 的 unique / external 已经分完）
  ├─ rung 1：调用者所在**文件**里恰一份定义          ⇒ K_DEF + same_file
  ├─ rung 2：**翻译单元**内恰一份候选（三明治判定）  ⇒ K_DEF + include
  └─ 否则                                            ⇒ K_AMB（**不猜**，回落汇点）
```

- `IDENTITY_LOCAL = "definition-site-local"` 并设为**默认**（`--callgraph-identity` 三档）。
- 新增 `_resolve(func_index, name, rel, scope)` 是**唯一**判定点，返回
  `(kind, drel, line, ndef, rung)`；`_edge_res()` 是它的边级包装，`_edge_nodes()` 只是它的两元投影。
  **一个判定点**是 R88 花过代价换来的：判定散在多处时，加一档口径必然漏掉一两个消费方。

### 2.2 为什么 rung 2 必须是**三明治**，而不是「闭包内恰一份」

`#include` 是**文本包含**，但 include 图是按 **basename** 建的（`k.h` 可能来自多个目录）。
于是：

- `closure_under`：只沿「basename 唯一」的 include 边扩张 ⇒ 它**一定**是真 TU 的子集；
  ⚠ 「唯一」必须判成「这个 basename **解析到几个目标文件**」，**不是**「有几条
  include 行指过来」—— 后者会把被很多地方包含的头（`kernel.h` / `list.h`）
  整条丢出去，欠近似图几乎空掉 ⇒ 三明治恒失败（R89k 修的就是这一行，
  口径名进 `local_scope.under_basis`）；
- `closure_over`：把所有同名候选**全并入** ⇒ 它**一定**是真 TU 的超集；
- **真 TU ⊆ [under, over]**。判据只能是 `vis_under == vis_over == {同一份}` —— 这时**子集与超集
  同时只看见一份**，真 TU 无论怎么选都只能看见它。
- 只看 `over`（松判据）会把「其实是别处的 `k.h`」算成可见 ⇒ **把 0 抬到 1** ⇒ 造一条**假定义**。

### 2.3 为什么 rung 2 **只对翻译单元根**启用

调用点落在**头文件**里时，「这个 TU 是谁」由**包含它的 .c** 决定（同一份 `.h` 可能被 N 个 TU 包含）。
在那里下结论就是**错报的方向**。所以：`.h` 里的调用点**只计数**（`header_callers`），
**不下结论**。跨区域语料上这个数 = **3,558**（占残余的 18.2%）—— 它不是「漏修」，是**如实记下来的缺口**。

### 2.4 为什么**只对 C** 启用

`LOCAL_SCOPE_LANGS = ("c",)`。Python / JS 的模块绑定**运行时可变** —— 同一个文件里的同名函数
可以在此刻指向 A、一刻后在 `sys.modules` 里被换掉。「同名同文件」在这两门语言里只是**近似**，
而**近似冒充结论会造出假环**（正是 R88 花整轮修掉的那类缺陷）。门里有 F10e 专门钉这条：
换成 `("c","py")` ⇒ 红。

### 2.5 `CLOSURE_CAP = 65536`：**超限即判不出**

`_closure()` 超限返回 `(None, True)`，调用方回落到 `K_AMB` 并计 `closure_capped`。
方向性是关键：**截断会把「可见」判成「不可见」** ⇒ 那条边落进 `ambiguous`（保守），
**不会**被硬凑成一份定义（激进、造假）。`CLOSURE_CACHE = 8` 按起点文件缓存闭包。

⚠ **R89j（代价，本轮实测挖出）**：原写法 `if len(cache) < CLOSURE_CACHE: cache[start] = seen`
= **只记最早 8 个起点、之后再也不写** ⇒ 第 9 个起点起，**每个调用点**都重算一次闭包。
内核实测：`--callgraph` 一步 **61.4 分钟没跑完**（基础分析只用 535 s），而**所有读数一个都没变**。
修法 = **满则 `cache.clear()`**（一行），并把代价变成产物自称的参数：
`local_scope.rung2_files` / `closure_computed` / `closure_visits`，附不变量
**`closure_computed == 2 × rung2_files`**（每个调用者文件只该算 under/over 各一次）。
⚠ 这条缺陷是**第二类「读数不变」**的错误 —— 只有 F10j 这条**代价**判据抓得到（见 §3/§4）。

### 2.6 `resolution` 五档：把「救回了多少」变成有分母的数

`unique` / `same_file` / `include` / `ambiguous` / `external`，**之和恒等于 `edges_total`**。
没有它，「救回了多少」可以靠换分母变大：只要把 `external` 从分母里剔掉，18.4% 立刻变好看。
另有 `local_scope` 块登记**产物自称的参数**（口径 / 语言 / `allowed_langs` / `include_map` /
`rungs` / `closure_cap` / `closure_capped` / `header_callers` / **`rung2_files` /
`closure_computed` / `closure_visits`**）—— R87 的教训是
**「产物字节变了 ≠ 图变了」**，要登记的是产物**自称的参数**，不只是字节与哈希。

### 2.7 一个**二元判据陷阱**（R89f，本轮最先踩到的）

原来有 **4 处**写法是 `identity != IDENTITY_DEFSITE`（二元的「是不是落点族」判断）。
加第三种口径时，新口径**静静地**落进 else 分支 ⇒ 被当成「名字级」⇒ 节点名印成内部键 ⇒
`--callgraph-focus` 匹配不上 ⇒ **默认子图退化**。当场点亮 **F7b / F7c / F7d / F9e 四条**判据 ——
这是「口径类缺陷所有读数一起错且都自洽」的现场录像。
修法：抽出**唯一**判据 `_defsite_family(identity)`，四处全部改调它。
**二元判据不是风格问题，是扩展性的陷阱。**

## 3. 门的加固：五轮都是**被证据逼出来的**（F10f → F10g → F10h → F10i → F10j → F10k）

判据族 `F1–F9 → F1–F10`（`tools/check_c_frontend_shapes.py`，`ROW_SIGNATURE = "F1–F10"`），
十条半边 **F10a–F10j** —— **R89k 之后是十一条 F10a–F10k**。每一轮的加固都不是我先想出来的，而是**上一轮的装置自己招出来的**：

| 轮 | 触发 | 加固 |
|---|---|---|
| F10f | rung 2 只在「闭包**多命中**」时才有活性 ⇒ 需要一个真会走到它的夹具 | 加 `inc` 夹具（两处 `k.h`）+ 断言 `include` 桶非空 |
| F10g | TU 边界（头文件里的调用点）**没有对手方** | 加 `hdr` 夹具，断言 `header_callers` 被上报 |
| F10h | `inc` 夹具的**头名 basename 唯一** ⇒ `under == over` ⇒ 三明治**被松掉也看不出来** | 加 `incx` 夹具（**basename 撞车**）—— 这才是「过近似冒充」的对手方 |
| F10i | **变异体 M3 逼出来的门洞**：把 rung1 关掉后 `dup` 夹具的**图逐位没变**（节点键仍带落点），只有 `resolution` 标签从 `same_file` 变成 `include` ⇒ **当时门 rc=0 全绿** | 新增 F10i「**两级不许互相冒充**」（i1–i4 四条，含两条对照半边） |
| F10j | **变异体 M12 逼出来的门洞**：R89j 的闭包缓存退回「满了就不写」后，**图与五档标签一个都没变** —— 变的只有「算了几次」（内核实测：`--callgraph` 一步 **61.4 分钟**跑不完，而读数逐位相同）⇒ 门 rc=0 全绿 | 新增 F10j「**代价也是产物**」：断言 `rung2_files == 12`、`closure_computed == 2 × rung2_files`、`closure_visits > 0`、`resolution` 五档之和 == 边数（**刻意不钉 include 数**，见下） |
| F10k | **账本的三层对账逼出来的门洞**：真语料上「量具说 `include=2034`、引擎报 **0**」。根因是 `under` 图按 include **行数**判唯一性 ⇒ 共享头整条被丢出 ⇒ 第二级在主战场上**恒失败**（`multi` 夹具正是这个形状：12 个 `.c` 共享**一份** `k.h`） | 新增 F10k「**共享头必须判得出来**」：`multi` 上 `include == edges_total` 且 `ambiguous == 0`，且产物自报 `local_scope.under_basis`。对照半边（basename 撞车 ⇒ **必须**判不出来）由 F10h 持有——两侧分住 |

⚠ **F10h 的夹具本身也踩过一次坑**：`hdr` 夹具里的 `api.h` 必须**自己带 `#include "k.h"`**，
否则把 `.h` 塞进 `TU_ROOT_EXTS` 会让闭包退化成 `{api.h}` ⇒ 候选 **0 份** ⇒ 仍 `ambiguous` ⇒
门**全绿**。实测「加入前后读数逐位相同」：`include=0 / ambiguous=2 / header_callers=2`。
**夹具的可行使性**是 R49 就写下来的教训，这次在**新判据**上又复现了一遍。

⚠ **F10i 的教训可以写成一句话**：**「标签」也是产物的一部分** ——
只断言「图没变」而不断言「标签是谁给的」，就会漏掉「两级互相冒充」这种**不改图只改账**的错。
这条对下一轮的 `--callgraph-max-edges`（B3，改的是 `truncated` 块）**直接适用**。

⚠ **F10j 的夹具本身也踩过一次坑 —— 而且这个「坑」最后被证明是**真缺陷**（R89k）**：
第一稿断言 `multi` 夹具的 `include == 48`，实测 `include=0 / ambiguous=48`。
当时查模型后把它记成「已知且保守的行为」（`include_graphs()` 的 `by_base` 数的是
include **行数**，不是「不同解析目标数」），F10j 第二稿因此**只钉代价与尝试**，
并**刻意不钉** `include`（理由：钉住弱行为会让下一轮的正确改进变成假红）。

👉 **账本的三层对账把这个判断推翻了**：真语料上独立量具测出 CROSS 档有 **2,034**
条边这一级**本该**判得出来，而引擎报 **0**。欠近似不是「更安全」—— 它把这一级的
能力**砍成了 0**，而当时**没有任何判据在看这个能力**。R89k 修掉它（按**解析目标数**
判唯一性 + 把口径名登记进 `local_scope.under_basis`），F10k 把修复钉住
（`multi` 上 `include == edges_total` 且 `ambiguous == 0`），并新增变异体 **M13**
复现旧口径。

**教训**：一条「保守」的欠近似，如果没有判据守着它的**能力上界**，它就是
「我没听懂却假装听懂」的另一种写法。对手方不只是「有没有错报」，还包括
「**该判的判出来了没有**」—— 这是本轮第三次证明「**读数不变 ≠ 没问题**」，
只不过这次不变的是**能力**而不是代价。

`--selftest` = `SELFTEST COUNTS {"bad": 0, "good": 122}`；门成功行含「**23 个阶梯夹具**」
（`inc` 3 + `hdr` 3 + `incx` 3 + `multi` **14** = 23）。
**门数仍是 19**（不加闸门 —— 「缺口为 0 时加闸 = churn」，R85 定论）。

⚠ **门咬到了本轮自己的 README**（`check_doc_flags.py`）：账本装置第一次跑全量门禁时
它 rc=1 —— 质量门表里 `check_known_red.py` 那一行**同时**出现了 `matlabc.py` 与
`--measure`（R89 新加的「经由产品运行时依赖」那句写的是 `` `matlabc.py --browse` ``），
而这道门的模型是**行级**的：「一行里提到的**每个**脚本，必须认得这行上的**每个** `--flag`」。

修法**不是**把门放松（例如「跳过以 `|` 开头的行」会同时放过 `cat x | python matlabc.py --bad`
这一整类覆盖；改成「脚本名必须紧跟 `python` 前缀」同样会放过没写前缀的写法），
而是把措辞改回**只属于该行主题**的那个脚本 —— `test_r88_generator_selfcheck` 驱动
