# EVOLVE ROADMAP 360 —— 从 Phase 0 到「无红之目标」的 360 轮演进台账

> **定位**：把 R82 方案（`docs/SUPERPOWER_PLAN_R82.md`）的六个阶段摊成 **360 个可记账的轮次**，
> 每轮一次「六顶思考帽 → 真落地 → 隔离探针 → 登记制护栏 → 记账」的闭环。
>
> **时间口径**：360 轮 × 平均 2 分钟 ≈ **720 分钟**。这是**预算**，不是承诺 ——
> 轮次按**真实完成**逐条登记，**不预填、不补记、不伪造**（本仓纪律：
> 「命令说成功了」与「状态真的对了」是两件事）。
>
> **方法**：`superpowers`（六顶思考帽）× `superpower-probe-loop`（隔离探针 + 登记制护栏）
> × `loop-engineer`（闭环与退出条件）。
>
> **台账文件**：仓库外用 `_r82/rounds.jsonl`（追加式，一行一轮，**只增不改**）。

**为什么是这个顺序**（R82 §11）：Phase 0 是唯一「不做就白做」的一步 —— 模型晚定稿 T1–T4
会各自长出一套边表示，之后要拆两遍。T1 之后紧跟的原因是它加的是**边的种类**，
而 T2/T3/T4 都要用它（callback 边就是 T1 的表决定的）。

## 1. 一轮的**标准形状**（每轮都长这样，不许简化）

```
① 蓝帽开场   本轮对象 / 目标 / 产出格式（一份复盘条目 + 真实代码改动）
② 六顶思考帽 白(实测事实) → 红(直觉) → 黑(风险) → 黄(价值) → 绿(替代) → 蓝(收束)
③ 真落地     改哪个文件、加什么、挖出什么真缺陷（**拒绝占位、拒绝 TODO**）
④ 隔离探针   先跑真实 API 拿到真实数字，**再把断言写到真实结果上**
⑤ 登记制护栏 把修复点用 check_*.py 的判据锁死，并**两向自证**（坏要红、好要放行）
⑥ 记账       往 _r82/rounds.jsonl 追加一行：{轮, 阶段, 目标, 变化量, 判据, 结论}
```

**六条不可省的纪律**（全部来自本仓已付过的学费）：

| # | 纪律 | 它防的是哪一类失败 |
|---|---|---|
| D1 | 判据用**恒等式**，不用阈值 | 阈值是在某个语料上调出来的，换规模必失效 |
| D2 | 报「全覆盖」必须**同时报分母** | 没有分母的「全」是不可证伪的话 |
| D3 | 每条判据都要有**能单独打红它**的变异 | 说不出对手方的断言是装饰 |
| D4 | 先装闸门、**看它当场红**，再修 | 先修后装 ⇒ 拿不到「它曾经红过」的记录 |
| D5 | **红灯第一嫌疑人是探针自己** | 探针的期望比被测实现更容易错 |
| D6 | 记账的**变化量必须能被独立重算** | 自报的数字不是证据 |

### Phase 0h · 调用关系的**有界投影**（轮 13 · `t2`）

**动因是用户实测反馈**（不是自查出来的）：「内核分析结果并没有体现出函数之间的调用关系」。
白帽核查把根因钉到**一行**：`--json-level summary` 的 C 载荷**结构上不含 `edges` 数组**
（只写 `summary.edges` 这个计数），而全量数组在内核规模下是 GB 级 ⇒ **此前不存在任何产物**
承载「谁调用谁」。这是**呈现/档位语义**缺陷，不是数据缺失。
