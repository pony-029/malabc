# R105 复盘 —— 修掉 R104 抓到的那条真红：`p77` 增量宽限的**过期绝对容差**

> 起因：R104 §8 第 1 条，也是 R103 §9 排定**顺序**的兑现 —— 先让门把读数打出来，
> 再动阈值。R104 已经把读数打出来了（余量 0.99936×），本轮才动阈值。
> 本轮**只改这一条**：不顺手改别的阈值、不加新护栏。
>
> ⚠ 本轮的直接后果（R104b ㊱ 的应用）：**不再用占位符装配复盘文档**。R104 那个
> 「零长度代码块」正是装配插占位符留下的 —— 所以本文件的实测段是**跑完再追加**，
> 不是先写占位符再替换。

## §1 缺陷：`+0.8 s` 是标定于「一轮 ≈2.1 s」年代的**绝对**容差

`tests/test_matlabc.py::test_p77_incremental_perf_benchmark` 里有两条断言：

| # | 断言 | 分母 | R102 的处置 |
|---|---|---|---|
| ① | `dt_first < 0.075 × n_pages` | **页数**（现算） | **已归一**（60 s 绝对阈值 ⇒ 75 ms/页） |
| ② | `dt_inc < dt_first + 0.8` | **一轮墙钟** | **漏了** ← 本轮修的就是它 |

R34 加 ② 时，注释里就写着它的标定值：`dt_first=2.12s dt_inc=2.16s` ⇒
`0.8 / 2.1 ≈` **38%** 相对带 —— 在那个年代够宽，也确实是「去抖动」而非「放宽」。

R99/R100 之后，同一份输入产出 **3 倍页数**（每文件 `src/` + `file/` + `xref_src/`），
一轮墙钟从 ≈2.1 s 涨到 ≈82–98 s，**分母涨了 ≈39 倍，而容差一动不动**：

| 量 | R34 标定 | R104 首跑实测 | 说明 |
|---|---|---|---|
| 一轮墙钟 | ≈2.1 s | **82.006 s** | ≈**39×** |
| 旧式容差 | +0.8 s = **38%** | +0.8 s = **0.9757%** | 没跟着涨 |
| 实测抖动 | 0.3%（2.216 / 2.209） | **1.0104%**（82.859 / 82.006） | **比容差还大** |

⇒ 结论是可推导的、不是猜：**旧判据的红绿由噪声决定**（R104 实测余量 0.99936×，当场红）。
它不是「判据太严」，而是「判据退化成了抛硬币」—— 与 R102 ㉖ 记的那次**同一形状**。

## §2 改法：`max(0.8 s, 10% × dt_first)`

新纯函数（与用例同批入库，`tests/test_matlabc.py`）：

```python
_P77_INC_BAND_REL = 0.10      # 相对带
_P77_INC_BAND_ABS = 0.8       # R34 的绝对下限

def _p77_inc_band(dt_first):
    return max(_P77_INC_BAND_ABS, _P77_INC_BAND_REL * float(dt_first))
```

断言与侧信道读数**同时**换成算出来的容差：

```python
_band = _p77_inc_band(dt_first)
_emit_perf_margin("p77_incremental_perf_benchmark/inc", dt_inc,
                  dt_first + _band, kind="tolerance")
assert dt_inc < dt_first + _band, \
    ("增量运行不应显著慢于首次（dt_first=%.3fs dt_inc=%.3fs 比值=%.4f；"
     "容差=%.3fs = max(0.8s, 10%%×dt_first)）"
     % (dt_first, dt_inc, dt_inc / dt_first, _band))
```

* **保留绝对下限 0.8 s**：小文件场景（dt_first 只有几秒）不许被相对带压掉 ——
  这正是 R34 当年加它的理由。
* **断言消息把每个被测的量都打成数字**（比值 + 容差 + 它的来历）—— 这是 R104b 补的
  那条出处教训（首跑那条红只能从 `AssertionError` 正文读出来）的直接应用：
  红了就要能**当场算**，不用回去复现。

## §3 为什么是 10%，而不是标定时的 38%

三条理由都可重算（也逐条写进了代码注释与用例）：

1. **标定点逐字不放松**：`max(0.8, 0.10 × 2.209) = 0.8` ⇒ 在 R34 的标定分母上，
   新式与旧式**同一个上限**，一个字节都没松。
2. **10% 比标定时的 38% 更严**：38% 是「不许比它更松」的**上限**，不是要复刻的目标值。
3. **10% 是实测扩散的 ~10 倍**：实测相对差 0.3%（R34）/ 1.0104%（R104 首跑），
   10% 留了一个数量级的余量 ⇒ 不是抛硬币；而 1.5× 那种**真回归**照样红（§4 ⑥）。

⚠ **方向必须说清**（R102 ㉖「只有升不许降」在这里要说实话）：在大分母上，新式确实比
旧式**宽**（0.98% → 10%）—— 但旧式那个 0.98% **低于噪声**，它当年提供的不是强度而是
随机性；在标定分母及以下，两者**完全一致**。这不是「改正量具顺带放宽判据」（R90 ②），
而是「把一个已经退化成噪声探测器的判据换回判据」。

## §4 两向自证（不是「跑一遍看没炸」）

新用例 `test_r105_p77_tolerance_band_is_scale_invariant`，六条：

| # | 判据 | 方向 |
|---|---|---|
| ① | `f(2.209) == 0.8`、`f(2.12) == 0.8`、`f(8.0) == 0.8` | 标定点**同上限** |
| ② | `f(82.006)`、`f(98.257)` 都 `== 0.10 × dt_first` 且 `≥ 10 × 0.8` | 确实跟着涨 |
| ③ | 七个分母上单调不减、且**永远 ≥ 0.8** | 不许被相对带压掉 |
| ④ | 旧式相对带 `0.8/82.006 = 0.9757%` **<** 实测噪声 `1.0104%` | 翻红机制**可算** |
| ⑤ | 在 R104 实测值上：旧式**必红**、新式**必绿** | 用**真读数**复算，不是构造数 |
| ⑥ | `1.5×` 真回归在 2.209 s 与 82.006 s 上**都必须红**；`1.02×` 不该红 | **第二向**：不是只会变绿 |

实测：`1 passed, 509 deselected in 2.53s`（用例总数 **510**）。


## §5 端到端实测（跑完才追加；数字全部从产物现读）

`p77` 单条真跑，命令 = `-k p77_incremental`（`PYTHONPATH` 已清、系统 3.10.10），
侧信道路径由**门之外**显式给定（`MALABC_PERF_MARGIN_LOG`），读数落在
`_r105/margins_p77_r105.jsonl`：

```
rc=0（后台任务 `rc=` 读数，转述）
1 passed, 509 deselected in 895.44s
```

```
{"kind": "budget", "limit": 182.325, "measured": 77.93683671951294, "node": "p77_incremental_perf_benchmark", "ratio": 2.339394408014914, "unit": "s"}
{"kind": "tolerance", "limit": 85.73052039146424, "measured": 72.43029999732971, "node": "p77_incremental_perf_benchmark/inc", "ratio": 1.183627851805458, "unit": "s"}
```

| 断言 | `measured` | `limit` | 余量 | 判据 |
|---|---|---|---|---|
| 预算门（`dt_first` vs `0.075 × n_pages`） | **77.937 s** | 182.325 s | **2.34×** | 不变（R102 已归一） |
| 增量宽限（`dt_inc` vs `dt_first + band`） | **72.430 s** | 85.731 s | **1.184×** | **本轮改成按分母归一** |

⚠ **口径自证（产物级，不是声明）**：`tol.limit − bud.measured = 7.793684 s`，而 `0.10 × bud.measured = 7.793684 s` ⇒ 两者相等（差 5.33e-15）⇒ **跑的就是新口径**，不是「改了代码没生效」。旧口径下这个差值应恒为 `0.8 s`（R104 两跑都是：`82.806−82.006`、`99.057−98.257`）—— 所以这一条能**分辨两代口径**。

⚠ **宽限那条的余量要按新口径读**：它的 `limit` 就是 `dt_first + band`，
所以余量**天然**落在 `1/(1−10%) ≈ 1.11×` 附近 —— 这个数字回答的是
「10% 的容差带消耗了多少」，**不是**「离红有多远」的绝对值。真正该看的是
**`dt_inc / dt_first` = 0.9293**（新口径下容差带 = 7.794 s，即 10.0%）。

对照 R104（**旧口径**，同一条断言）：

| 跑 | `dt_first` | 该跑用的 `limit` | 余量 | `dt_inc/dt_first` | 结果 |
|---|---|---|---|---|---|
| R104 首跑（含负载） | 82.006 s | 82.806 s（**旧** +0.8） | **0.9994×** | 1.0104 | **红** |
| R104 空机复跑 | 98.257 s | 99.057 s（**旧** +0.8） | 1.156× | 0.872 | 绿 |
| **R105（本轮）** | 77.937 s | 85.731 s（**新** +band） | **1.184×** | **0.9293** | **绿** |

⚠ **反事实（同一跑）**：若 R105 这次仍用**旧口径**，`limit` 会是 78.737 s ⇒ 余量 1.087×，
   也会绿 —— 也就是说**这一跑分辨不了两代口径的好坏**；能分辨的是 §1 的
   算式与 §4 的用例。真正被修掉的是「红绿由噪声决定」：旧口径的 0.98% 带比
   实测抖动 1.04% 还窄。

⇒ 同一形状的输入下，新口径给出的判定与旧口径**不矛盾**（都没有把 1.0104 这种
   噪声级差异算成回归），但新口径**不再让噪声决定红绿**（§1 的算式）。

## §7 诚实边界

1. **没有做端到端的「注入即红」**：`p77` 单跑 ≈19 分钟，注入一次慢路径再跑一次
   成本过高。红的方向由**公式级两向**给出（§4 ⑤⑥：拿 R104 的**真实读数**复算，
   旧式必红 / 1.5× 真回归必红），绿的这一向由本轮真跑给出。
2. **10% 这个系数是选出来的，不是测出来的**：它的依据是「标定点同上限 + 比 38%
   更严 + 是实测扩散的 ~10 倍」。若要改，必须连 §3 的三条算术一起改（注释里写了）。
3. **`p77` 读数仍受机器负载影响**（MEMORY 硬纪律：同臂相邻两次可差 3 倍）⇒
   本轮的单次读数只当**量级**；能变成判据的只有**比值**与**带**。
4. **`--with-tests` 全量仍未做**（R104 §7-2 的缺口延续）：本轮只跑了 `p77` 单条。
   这条缺口与 `TEST_BASELINE.json` 的重录是同一件事，留给下一轮。
5. **取消占位符装配**：本文件是**先跑后写**（§5 由脚本按产物现读生成）。
   R104b ㊱ 的根因就是占位符装配 —— 本条是它的直接应用，也是可复用的排版纪律。
