# matlabc.py 使用说明

MATLAB 代码结构梳理与分析工具（**纯 Python，零第三方依赖**）。无需安装 MATLAB 即可对大型 MATLAB 项目进行：目录扫描、函数/类/脚本解析、调用关系分析、依赖图生成，以及**交互式源码跳转浏览**。

> 前端产物质量门禁（`fe_audit.py` 的硬门禁校验）说明见 [`README.md`](README.md)。

---

## 一、功能特性

| 功能 | 说明 |
| --- | --- |
| 目录结构树 | 递归扫描全部 `.m` 文件，按目录树展示 |
| 语法解析 | `function` / `classdef` / 局部函数 / 嵌套函数 / 脚本 / 主函数 / 类方法 / 构造函数 / `arguments` 参数验证块 |
| 签名提取 | 输入/输出参数（含多返回值 `[a,b]` 解构、可变参数 `varargout`/`varargin`）、函数名、所在文件与行号 |
| 调用分析 | 项目内调用边 + 跨文件调用 + 内置/外部函数统计 + 动态调用（`feval`/`str2func`/字符串回调）+ 函数句柄 |
| 深度关系分析 | 影响面/依赖面传递闭包、追本溯源到根、关键函数风险度量（圈复杂度/扇出/扇入）、同名函数歧义可视化与一键切换 |
| 类层次分析 | 类继承图（父上子下 UML 泛化，支持多继承 `A & B` 与包限定父类）、类协作图（uses 关系）、全局成员索引（属性/事件/枚举/方法）、类定义明细表 |
| 注释标签聚合 | `% TODO/BUG/DEPRECATED/FIXME/NOTE` 等标签提取 + `annotations.html` 技术债清单（可跳转源码行） |
| 公式渲染 | 注释内 LaTeX 公式（`$$...$$` 等）经 MathJax 渲染，离线优雅降级 |
| 目录级分析 | 目录依赖关系、目录循环依赖检测、目录索引页、目录-函数分层调用图、目录统计（扇出/扇入/入口函数） |
| 数据流 | 变量读写、结构体字段访问与跨文件跳转、注释折叠 |
| 交互与检索 | `--browse` 静态站点：点击跳转定义、函数预览、全文搜索（多关键字/正则）、预览历史、调用图下钻 |
| 多种输出 | Markdown 报告、Mermaid 图、Graphviz DOT、HTML 报告、结构化 JSON / XML、`--reproducible` 可复现构建 |
| 中文友好 | 中文目录名/文件名/GBK 注释均可正常解析 |
| 文档增强 | 内部函数缺头注释时自动合成中文友好摘要（签名 / 定义位置 / 调用关系 / 圈复杂度），兜底至函数卡片、调用列表、入口列表；报告与浏览站点对源码**实际调用**的内置 / 工具箱函数额外补「参数（维度）/ 返回维度」两列（详见 `MATLAB_BUILTIN_DETAILS`，当前覆盖 100+ 个高频函数，可继续扩展） |

## 二、环境要求

- Python 3.6.5+（Windows / macOS / Linux 均可；已严格兼容 Python 3.6.5，未使用 3.7+ 语法）
- 仅使用标准库，**无需安装任何包**
- 建议 Windows 控制台执行 `chcp 65001` 切换 UTF-8（可选，不影响分析结果）

## 三、快速开始

```powershell
# 1. 基础分析，直接在控制台输出 Markdown 报告
python matlabc.py D:\你的\matlab项目

# 2. 生成完整分析套件（报告 + 图 + HTML + JSON）
python matlabc.py D:\你的\matlab项目 -o report.md --mermaid deps.mmd --dot deps.dot --html report.html --json report.json

# 3. 生成可点击跳转的源码浏览站点（推荐，详见第六节）
python matlabc.py D:\你的\matlab项目 --browse site

# 4. 分析完成后用浏览器打开 site\index.html 即可浏览（无需服务器）
# 5. 用配置文件一次性指定全部参数
python matlabc.py --config analyzer_config.example.json
```

### 报告中的「函数调用关系」章节

Markdown / HTML 报告在「函数调用关系」下分三块，专门回答"函数之间有没有调用、从头到尾怎么走"：

1. **调用链路（从入口到末端）**：自动找出入口函数（项目内无人调用的函数，通常是主函数 / 脚本 / 回调），用树形自顶向下展示「谁先执行、再调用了谁」，每一层标注**调用深度（距入口的层级）**，直观呈现从头到尾的执行路径；遇到循环调用会标记并截断，避免无限展开。
2. **各函数调用详情（谁调用 / 被调用）**：逐函数列出它**调用了谁**与**被谁调用**（双向调用关系），并标注每个函数的**类型与所属文件**，便于精确定位。
3. **完整调用边列表**：`调用方 → 被调用方` 的逐条明细表，并标注是否跨文件。

`--json` 输出额外包含 `call_graph` 字段（`nodes` / `entries` / `outgoing` / `incoming` / `ambiguous`），其中 `ambiguous` 记录存在**同名函数歧义**的调用方与被调名、同名候选数量，便于程序化核查。

> **同名函数解析规则**：当多个文件定义了同名函数（如 `a/foo.m` 与 `b/foo.m`）时，调用链接按「**同文件（局部函数）→ 同目录 → 其余按相对路径**」就近解析，且目录树/函数索引均为每个文件生成**独立**页面与链接，不会互相串页。若某调用存在歧义，报告会在对应位置给出 ⚠ 提示。

> 输出文件/目录生成在当前位置，**不会修改原 MATLAB 项目**。

## 四、命令参数

| 参数 | 说明 |
| --- | --- |
| `dir` | （必填）要分析的 MATLAB 目录 |
| `-o, --output FILE` | 输出 Markdown 报告（默认仅打印到控制台） |
| `--mermaid FILE` | 输出 Mermaid 调用图（`.mmd`，可在 mermaid.live 渲染） |
| `--dot FILE` | 输出 Graphviz DOT 文件 |
| `--html FILE` | 输出自包含 HTML 报告（内嵌调用图） |
| `--json FILE` | 输出结构化 JSON（函数/类/调用边/编码等全量数据） |
| `--sarif FILE` | 输出 SARIF 2.1.0 静态分析结果（未初始化/死代码/类型不一致，接入 GitHub/GitLab 代码扫描） |
| `--sarif-base FILE` | 基线 SARIF 路径：启用增量模式，`--sarif` 只保留相对基线的「新增」告警（行级指纹，PR 级扫描） |
| `--sarif-diff FILE` | 输出 Markdown 格式的 SARIF 增量差异报告（新增/已修复告警明细表；未指定 `--sarif-base` 时自动复用上次分析自动持久化的 `.codebuddy/analyzer/sarif_base.json` 基线） |
| `--gate-file FILE` | P94：JSON 声明式门禁矩阵（`taint_gates`/`rule_gates`/`max_warnings`/`test_coverage`），与 CLI 参数合并后统一执行，违例返回非零退出码 |
| `--max-warnings-by-rule SPEC` | P94：按规则独立告警阈值（如 `uninitialized:10,dead_code:5`），与 `--gate-file` 的 `rule_gates` 合并（CLI 优先） |
| `--max-warnings N` | 告警数超过 N 时返回非零退出码（`0`=不限制，CI 质量门禁） |
| `--export-doxygen-xml OUTDIR` | P112：Doxygen 兼容 XML 导出目录（`index.xml` + 每文件 compounddef，含函数 memberdef/location，供 doxygen 工具链/CI 消费） |
| `--reproducible` | 可复现构建：全部产物（Markdown/HTML/JSON/browse 站点）省略生成时间戳，使同一项目两次输出逐字节一致（便于 CI 比对） |
| `--diff BASE CUR` | P126：双快照差异对比——文件/函数/类/调用边/告警五层按 key 对齐的「新增-删除-修改」，`generated_at` 时间戳差异忽略；配合 `--fail-on-diff` 做 CI 零漂移门禁（有差异退出 1）；`-o` 输出 Markdown 差异报告 |
| `--fingerprint FILE` | P127：计算 JSON 快照内容寻址指纹——整体 + 逐文件 + 告警组三层 SHA-256（规范化键序、忽略 `generated_at`），`--json` 落盘指纹文件 |
| `--verify FP [SNAP]` | P127：校验快照内容指纹——与指纹文件逐项比对，任何不一致返回退出码 1（防篡改）；SNAP 可选覆盖指纹文件记录的快照路径 |
| `--browse OUTDIR` | 生成交互式源码浏览站点 |
| `--file-graph` | 调用图按**文件**聚合（默认按函数） |
| `--folder-graph` | 调用图按**文件夹（目录）**聚合，展示目录级依赖关系 |
| `--combined-graph FILE` | 输出「目录-函数」分层调用图 SVG（doxygen 风格：目录为簇、函数为节点、跨目录边标红） |
| `--no-recursive` | 不递归子目录 |
| `--incremental` | 增量分析：缓存未变文件解析结果（`.matlabc_cache.pkl`），仅重分析变更文件 |
| `--exclude NAME` | 排除子目录名（可多次指定；默认已排除 `.git/.svn/.hg/__pycache__/node_modules`） |
| `--encoding ENC` | 强制 `.m` 文件编码（如 `gb18030`），默认自动探测 |
| `--title TEXT` | HTML 报告标题（默认"MATLAB 代码结构分析报告"） |
| `--config FILE` | 从 JSON 配置文件读取参数（CLI 显式参数优先） |
| `--version` | 显示版本 |
| `--check-py36` | 仅做 Python 3.6 兼容性自检：扫描 `matlabc.py` / `fe_audit.py` 是否误用 3.7+ 语法（海象 `:=`、仅位置参数 `/`、`list[int]` 内置泛型下标等），用于 CI 最低版本保障 |
| `--init-header` | 非破坏式「缺头注释」清单：扫描全部函数，区分两类并**基于签名 `inputs`/`outputs`** 生成可复制的 `% DESCRIPTION / Input / Output` 脚手架（不改动任何源码）：① 缺 DESCRIPTION 头注释者；② 有 DESCRIPTION 但缺 `Input`/`Output` 子段者（即「头注释不完整」）。用于配合 CI 复盘注释覆盖率，从源头补文档（与「文档增强」互补） |
| `--used-builtins` | 列出**每个具体函数实际调用的 MATLAB 内置函数，并附带其输入/输出维度**（维度取自内置函数维度说明表；未登记维度者明确标注「维度未登记」）。与 `--init-header` 互补：脚手架会为「调用内置的函数」追加「`Used Built-ins（输入/输出维度）`」段。不改动任何源码 |
| `--used-builtins-by` | 配合 `--used-builtins` 的分组视角：`function`（默认，按函数分组）/ `builtin`（按内置函数分组，列出每个内置被哪些函数调用） |
| `--dim-coverage` | 报告**项目调用的 MATLAB 内置函数中已完成输入/输出维度标注的覆盖率**（如 `维度标注覆盖率：150/150 (100.0%)`），并列出尚未登记维度的内置（若有）。用于持续监控维度表覆盖度，确保「具体函数里标注的维度」不遗漏 |
| `--dim-coverage-by-file` | 在 `--dim-coverage` 基础上**额外按文件分组**输出覆盖率（如 `a.m：12/14 (85.7%)`），凸显覆盖最差的模块，解决「内置统计所有模块一个样」的痛点（P217） |
| `--json` 扩展 | `--json` 输出的每个函数对象新增 `used_builtins_dims` 字段（`[{"name","dims"}, ...]`），便于程序化消费「函数调用的内置及维度」；`--browse` 生成的函数详情页也会内联渲染「调用内置函数（输入/输出维度）」区块 |

### 5.1 AI 流程 JSON 配置（ai_cli.py）

`ai_cli.py`（AI 模型 CLI 接口层）与 matlabc 的 AI 入口都可由一份结构化 JSON 驱动，做到**离线优先、零依赖、密钥不落盘**：

- **两种放置方式**（合并生效）：
  1. 作为 `analyzer_config.json` 的 **`ai:` 嵌套段**（见下 Demo）；
  2. 作为**独立**配置文件，用 `ai_cli.py --ai-config ai_config.json` 加载（顶层即 ai schema，无需嵌套 `ai:`）。
- **字段**（完整 JSON Schema 见 `ai_config.schema.json`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `default_provider` | 字符串 | 缺省供应商：`offline` / `openai` / `anthropic` / 国产 `deepseek` `qwen` `zhipu` `moonshot` `baichuan` `doubao` `yi` `stepfun` `ernie` `iflytek`（亦可用中文别名，见下）。可被环境变量 `MA_AI_PROVIDER` 覆盖 |
| `default_task` | 字符串 | 缺省任务：`review` / `fix` / `tests` / `refactor` |
| `fallback` | 字符串数组 | 优先供应商缺密钥时的尝试顺序，**末位必须为 `offline`**（可含国产名，如 `["qwen","deepseek","ernie","offline"]`） |
| `request_timeout` | 数字 | HTTP 超时（秒），provider 未单独指定时生效 |
| `providers.<name>` | 对象 | 每供应商：`cls`（openai/anthropic/ernie/iflytek，缺省 openai）、`api_key_env`、`api_key`、`base_url`、`model`、`request_timeout`；`ernie`/`iflytek` 额外需 `api_secret_env`/`api_secret`，`iflytek` 还需 `app_id_env`/`app_id` |
| `tasks.<task>` | 对象 | 每任务：`model` / `max_tokens` / `temperature` / `system`（完整系统提示，给定则覆盖内置引导）/ `user_suffix`（追加到分析输入后的说明） |
| `flow` | 对象 | 修复闭环编排（`steps` / `auto_apply`），由上游编排脚本读取 |

- **密钥安全**：只通过 `api_key_env` 引用环境变量名（如 `OPENAI_API_KEY` / `DASHSCOPE_API_KEY` / `ERNIE_API_KEY`），**绝不在 JSON 中写明文**；`ai_cli.py` 读到后立即脱敏，出错信息也不泄露密钥。
- **优先级**：`--provider/--model/--task/--max-tokens/--temperature/--base-url` 等 CLI 显式参数 > 环境变量 > 配置 > 内置默认；缺密钥时按 `fallback` 链降级到 `offline` 提示词。

| `moonshot` | Kimi/月之暗面 | OpenAI 兼容 | `moonshot-v1-8k` | `MOONSHOT_API_KEY` |

## 六、源码跳转浏览（--browse）

生成纯静态 HTML 站点，双击 `index.html` 即可浏览，支持：

1. **目录树 + 文件索引**：主页列出全部文件与目录树，点击文件名进入源码页；
2. **函数定义跳转**：源码中项目内函数调用点（蓝色高亮链接）点击直达其定义行；
3. **函数间双向跳转**：源码页顶部每个函数速览卡片列出
   - *调用（calls）*：该函数调用了谁 → 点击跳转
   - *被调用（callers）*：谁调用了该函数 → 点击跳转
4. **行号 + 高亮定位**：定义行整行高亮（浏览器 `:target`），跨文件跳转自动定位到具体行；
5. **命令面板（Ctrl+K）**：一次搜索「函数 / 文件 / 目录 / 全局变量 / 源码全文」，
   支持模糊匹配（`fda` 命中 `fooDetailA`）、最近访问、`Shift+Enter` 跳全局状态并预置筛选；
6. **类浏览**：类文件显示类定义、属性、方法、事件与枚举。

**操作示意**：`main.m` 调用了 `process_data()` → 在 `main.m` 源码页点击 `process_data(` → 自动跳到 `process_data.m` 定义处 → 卡片显示"被调用"列表回到 `main.m`。

> **全站交互说明（快捷键 / 命令面板 / 可分享深链 / 离线 / 无障碍 / 自查）**
> 见 **[`matlabc_FRONTEND_GUIDE.md`](matlabc_FRONTEND_GUIDE.md)**。
>
> 常用两招：
> - **`Ctrl+K`**：跨五类目标模糊搜索，比翻页面快得多；
> - **点击源码行号**：一键复制该行链接（`#L42` 或 `#L42-58` 区间），讨论代码时直接发链接。

> 站点为纯静态文件，可直接拷贝、离线使用，也可放入任意静态服务器（Nginx / GitHub Pages 等）。

## 七、中文与编码说明（重点）

- **目录名 / 文件名含中文**：Python 内部全程 Unicode 处理，无影响；站点内中文文件名经 URL 编码，跨平台安全；
- **源码注释为 GBK/GB2312 编码**：自动按 `UTF-8(含BOM) → GB18030 → GBK → Latin-1` 顺序探测，无需手动指定；GB18030 是 GBK 的超集，覆盖绝大多数中文注释；
- **强制指定编码**：若个别文件探测异常，用 `--encoding gb18030`（或 `utf-8`、`latin-1`）强制；
- **所有输出文件一律 UTF-8 编码**，在任意编辑器打开均无乱码；
- **Windows 控制台显示中文异常**（乱码或报 `UnicodeEncodeError`）：
  - 本工具已内置兜底（无法编码的字符以 `?` 代替，不会崩溃）；
  - 想要完美显示，可先执行 `chcp 65001` 再运行。

## 八、性能与大型项目

- 词法清洗结果在解析阶段缓存复用，调用分析不再重复清洗，大项目提速明显；
- 函数→文件使用 O(1) 哈希映射，调用边构建非 O(N²)；
- 实测：**300 个文件、343 个函数、1437 条调用边**的项目，全量分析 + 浏览站点生成约 **0.8 秒**，数千文件亦可支撑；
- 未解析为项目内调用的名称（如工具箱函数）自动归入"内置/外部调用"统计，不影响分析。

## 九、常见问题（FAQ）

**Q1：报告里某些函数显示"解析失败"？**
检查是否为非常规语法（如跨行 `function` 定义、`newline` 等）。工具按行解析，罕见的跨行定义可能截断，一般不影响主流程。

**Q2：HTML 报告里的调用图不显示？**
Mermaid 图依赖 CDN 加载 `mermaid.min.js`。离线环境请使用 `--mermaid` 生成的 `.mmd` 文件在 [mermaid.live](https://mermaid.live) 查看。

**Q3：`--browse` 生成后可以删除吗？**
可以。站点与项目完全独立，删除 `OUTDIR` 不影响原项目。

**Q4：调用图太大、太乱？**
用 `--file-graph` 按文件聚合；或在 mermaid.live / Graphviz 中只查看关心的子图。

**Q5：输出到文件时报编码错误？**
工具输出统一 UTF-8，若编辑器打开乱码，请确认编辑器编码设置为 UTF-8。
