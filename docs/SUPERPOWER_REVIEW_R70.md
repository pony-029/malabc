## §2 黑帽：真缺陷与它们的边界

1. **描述文本的「值」没有任何读者。** 全仓 `grep GUARD_CONTRACT` 只有
   `check_help_contract.py` 自己命中，且只用了**键**：`G1` 用键 ⇄ 源码退出码，
   `G2` 用键 ⇄ docstring 退出码段，`G0b` 用文件名 ⇄ 表。**值是纯散文**。
2. **它真的落后过两轮。** R68 实测 `C1–C6` vs 事实 `C1–C12`；R69 手工改，
   没留门 ⇒ 下一次还会再落后。**「有人改过」不等于「以后不会再错」**。
3. **顺带量到、本轮不修（重要）**：签名 ⇄ **它实际发出的判据前缀** 这一层，
   本来就存在不对称 ——
   * `check_boundary_reverse.py` 的 `ROW_SIGNATURE = "V1–V5"`，但它会发 **`V6`**；
   * `check_import_graph.py` 的 `ROW_SIGNATURE = "G1–G7"`，但它还发 **`B6–B9`**。
   本轮 H1 只管「**描述文本** ⇄ 已声明的签名」，**管不到**「已声明的签名 ⇄
   实际前缀」—— 后者需要每个护栏暴露自己的前缀集合，是**下一轮**的活
   （见 §7 C20-1）。**不修 ≠ 不知道**：这里逐字写下来。

### 2.1 本轮的边界（诚实披露）

* H1 **只比对字符串**：把签名塞进 `rc=0` 描述就算过。它挡得住「签名随判据族
  长上去而描述没跟」，**挡不住**「描述把签名写对了、其余全说错」。
* H1 不校验 `rc=1/rc=2` 的描述 —— 这是**口径选择**，不是疏漏（见 §3.2）。
* H1 不校验 README 门表那一行（那是 P5 的活），也不校验护栏**成功行**（P5 的
  行为半，见 `tests/test_matlabc.py::test_r62_*`）。

## §3 黄帽：落地的装置

### 3.1 判据 H1

`tools/check_help_contract.py` 新增：

* `_load_row_signature(path)` —— 纯读一个护栏源码里的 `ROW_SIGNATURE`
  （`ast` 求值，**不导入**被核对象）；
* `guard_signature_problems(contract, sig_by_script, runner=…)` —— **纯函数**，
  对每条护栏（runner `check_all.py` 除外）：
  * 源码里没有可读的 `ROW_SIGNATURE` ⇒ `H1 …（缺声明 → 红）`；
  * `rc=0` 描述里逐字找不到签名 ⇒ `H1 …（描述陈旧 → 红）`。
* `audit_guards()` 末尾接线：给真树每条护栏读签名，跑一次纯函数并上报。

### 3.2 口径选择（写下来，别让下一个会话重猜）

R68 预量了两种口径。**R70 选严格（`rc=0` 单槽位）**，理由三条：

1. **语义贴合**：`rc=0` 是「这门**通过**意味着什么」的**唯一权威行**；签名是
   它自己声明的判据族 —— 让 `rc=0` 必须命名它，等于把「签名 ⇄ 通过语义」钉死。
2. **单槽位更严**：「任一值含签名」会让签名**漂到 `rc=2`（缺输入）行上还算过**
   —— 门会宣称一套它在 `rc=0` 里**没说**的判据族。
3. **与 P5 同构**：README 门表（P5）也只看**行首那一列**，都是「一个规范位置」。

代价：严格修 **11** 条描述（宽松修 10 条），只多 `readme_parity` 一条 —— 换来
语义更紧，值得。

## §8 明确拒绝做的事（避免下一轮走回头路）

1. **不为「让数字好看」而改判据**：H1 存在的原因是**描述会偷偷腐烂**，不是
   为了让探针从 11 走到 0。
2. **不放宽口径换省事**：选严格（修 11 条）而不是宽松（修 10 条）—— 省的那一条
   换来一个语义漏洞（签名能漂到 `rc=2`），不值。
3. **不动 `mit` 正文 / `VERSION` / `flow/diagrams` / 行尾策略**；**不引新依赖**
   （离线、零依赖、3.6.5）。
4. **不借 H1 去「顺带修」`V6` / `B6–B9`**：那是 C20-1 的活，需要新的「前缀
   集合」声明；硬塞进 H1 只会让「描述 ⇄ 签名」这条判据变成两件事的混合物。
5. **不把 `rc=1`/`rc=2` 的描述也纳入 H1** —— 那是**已在 §3.2 记录的口径决定**，
   不是漏做。
6. **不动别人门的签名**：`H*` 是**先核过命名空间**才选的（`C/F/G/I/K/L/N/P/R/S/V/D`
   均已被占）。`G3` 名字虽空，但语义上撞 import 图 / patch_ops 的 `G0–G3`，故弃用。
