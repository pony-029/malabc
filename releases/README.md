# 离线安装包归档

这里只保留**最新一个**可交付的离线安装包：哪个版本、什么时候出的、多大、改了什么。

旧版本不在仓库里堆积（历史见 `vscode/CHANGELOG.md`，需要时 checkout 对应提交重新打包）。

使用者拿到 `.vsix` 就能装，不需要联网、不需要仓库 —— **clone 下来 `releases/vsix/` 里就是当前版本**。

---

## 怎么安装

1. 到 `releases/vsix/` 取 `.vsix`（仓库里只存最新版本）
2. VS Code → 扩展 → `…` → **从 VSIX 安装**
3. `Ctrl+Shift+P` → `Reload Window`

需要**旧版本**时：在 `vscode/CHANGELOG.md` 里找到那个版本号，
`git checkout <对应的提交>` 后跑一次 `python tools/build_vsix.py` 即可重新产出。

> **装完必须重载窗口**，否则编辑器仍在跑旧的扩展进程。

## 归档约定

- `vsix/` 下只放**已安装验证过**的包，文件名与版本号一致
- **只把最新一个包入库**：`build_vsix.py` 每次打包后会删掉旧包，
  并把 `vsix/.gitignore` 的例外规则改成当前文件名（手改必然忘）
- 每发布一版，在上表加一行：版本、日期、字节数换算成 KB、一句话变化
- **一句话变化写“用户能感觉到的”，不写内部实现**

## 重新生成某个版本

离线包由仓库内脚本产出，**版本号取自扩展清单，产物直接落到 `vsix/`**：

```
python tools/build_vsix.py
```

输出形如 `built <仓库>/releases/vsix/matlabc-0.6.84.vsix 1093002 bytes`。

版本表由 `tools/make_release.py` **自动生成**，不靠手工补行：

| 列 | 来自 |
| --- | --- |
| 版本 | 扩展清单 |
| 主要变化 | 更新日志里该版本的第一条 |
| 大小 / 日期 | `vsix/` 里对应文件 |

**默认只列真的能装的版本**（有 vsix 的），加 `--all` 才把历史全列出来；
只看不写用 `--dry-run`。
