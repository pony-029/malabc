01问题：为什么"代码转代码"走不通

MATLAB 是动态大一统内存模型：所有变量都是自动管理的多维数组，用户从不关心 它在哪、多大、何时释放。嵌入式是极其严苛的物理切片：64KB 的片上紧耦合内存、 外挂 DDR、DMA 通道、多核共享区——每一块内存的容量、延迟、访问权限都是硬约束。

把前者编译成后者，如果只做"一行 MATLAB 对应一行 C"，会遇到四道墙：

墙表现根因
内存512×512 的 double 矩阵就是 2MB，塞进 256KB 当场 HardFaultC 需要静态布局，MATLAB 不需要
数据搬运大数组在外存，CPU 只能访问片上没有 DMA 就是纯拷贝，性能塌方
算子实现同一个 sum，不同芯片有不同指令算子语义与指令实现被混在一个符号里
平台接口disp/fopen 在裸机上不存在语言运行时假设了操作系统

核心判断：这四道墙都不是"翻译得不够好"，而是翻译这件事本身缺少一个中间层—— 一层用来描述"目标硬件长什么样"的声明，和一层用来做"语义到实现"的选择。

03小脑：确定性能解决 90% 的事

"这个数组多大""这个段还剩多少""头文件里有没有这个符号"——这些问题全是可复算的， 不需要任何智能，只需要一个算得对的程序。

3.1 口径写死，不给自己留解释空间

字节数 = prod(shape) × 8          # f64，与运行时 MLC_F64 一致
函数峰值 = 该函数内所有数组之和     # 保守上界，不做活跃期分析
形状未知 → 不计入峰值，但单独计数   # 不把"不知道"算成 0

第三条是最重要的。把"不知道"算成 0，会让预算校验假通过—— 报告好看，实际问题被藏起来。本仓在多个地方踩过这个坑，所以它现在是硬规则。

3.2 分段：从"一段"到"任意段"

初版只有单一静态池（65536 字节）——那其实是退化的 TCM。要做通用， 段必须是配置出来的，而不是写死的：

{
  "sections": [
    {"name": "itcm", "capacity_bytes": 65536,  "max_array_bytes": 4096},
    {"name": "dtcm", "capacity_bytes": 262144, "max_array_bytes": 32768},
    {"name": "ddr",  "capacity_bytes": 134217728}
  ]
}

分流规则：按声明顺序 first-fit——找第一个"装得下这个数组"的段。 不写 max_array_bytes 的段视为能装任何大小（通常是最后的大内存）。

这条规则是实测逼出来的。初版只用首段与末段，于是三段以上的 profile 里 中间段永远为 0——实测 dtcm（256KB 的 CPU 直连内存，最该被用上的那段） 用量恒为 0。"可配置段个数"在数据格式上成立、在分流逻辑上不成立，等于没配。

04大脑：四信号与可回答的问题

小脑能算的算完，剩下四类不能猜的，显式升级：

信号在本场景的含义为什么不能猜
S1 无先例算子/形状组合在知识库没有先例猜错会生成编不过的 C
S2 复发同一段反复超限（如超幅 > 25%）说明当前分流规则对它不适用
S3 无见证数组形状未知当 0 会让预算假通过
S4 未归类profile 没声明这个段 / 这个 ISA生成器不知道往哪放

4.1 每一信号必须带一个"可回答的问题"

[大脑] 必须升级 2 项
  S3  有 9 个数组没有形状标注，峰值的下界算不准
      问：这些数组的实际维度是多少？或者它们能否改成由常量初始化？
  S4  profile 声明了 56 个算子想要的 ISA 变体，但头文件里没有对应符号
      问：这些算子在本板子上是「没有向量实现」还是「符号名不同」？

为什么必须是"问题"而不是"警告"：警告只能让人知道出事了， 问题才能让人知道下一步做什么。"S4 缺失"是警告；"是没有向量实现，还是符号名不同"是问题—— 后者当场就能回答，前者要重新调研一遍。

05声明式配置：profile 是物理事实

5.1 两份结构不同的 profile（这才是"通用"的证明）

profile段ISA 优先级用途
mcu_256k2 段（tcm 256KB + ddr 64MB）scalar → simd128简单 MCU
cortex_a_tcm_ddr3 段（itcm 64K + dtcm 256K + ddr 128M）neon → sve → dsp + accel异构 SoC

只用一份 profile 验证"可配置"，永远不会暴露缺陷。 第一份配置往往是照着代码写的，结构上必然通过。只有换一份结构不同的 （段数、顺序、层级都变），才能测出"逻辑是否真的跟着配置走"。

5.2 配置项的边界

可配不可配
段个数 / 段名 / 每段总容量 / 每段单数组上限 / ISA 顺序 / 加速器开关 / 算子覆盖 字节数算法（prod(shape)×8）/ "形状未知不计入"这条规则 / 四信号定义

右边那一列是口径。口径也做成可配置，等于允许每个项目自己定义"什么算超限"—— 那就没有判据了。

06算子映射：三层路由与优先级

6.1 现状：语义、实现、符号名被压在一个字段里

{"id": "OP-SUM", "matlab": "sum(x)", "c": "mlc_op_sum", "kind": "reduction"}
                                     ↑
                        一个字段同时承担了三件事

后果：想换成 SIMD 或公司库，只能改 c——而那是语义登记， 一改就连带 TP8 三处一致性判据一起晃。

6.2 拆成两层：变体选择 + 外部覆盖

候选 = [c_neon, c_sve, c_dsp, c_accel]   # 按 profile 的 ISA 顺序
      + [c]                              # 标量兜底，永远最后
选中 = 第一个在 mlc_ops.h 里声明过的
覆盖 = op-map 文件里声明的 c（优先级最高）

这里出现过一次只有自证能抓到的 bug：scalar 被放在优先级序列第一位， next() 永远先命中它，simd128 与 accel 永远选不上—— 而输出表看起来完全正常（56 个算子"都有实现"）。

抓它的是自证里那句"有 simd 实现时必须选中 simd"。这句话在现实中毫无用途 （那时还没有任何 simd 实现），它唯一的作用是描述"正确的行为应该是什么样"。

6.3 三层路由（修正后的优先级）

层来源优先级失败时
1项目映射文件 --op-map最高缺 why 直接判文件不合法
2平台配置（profile）次之ISA 未声明则该层跳过
3内置字典（operators.py）再次算子不存在则解析期报错
4weak 桩兜底必须报桩比例，见 §8

顺序必须是这样，而不是"内置 → 配置 → 桩"。配置的全部意义就是覆盖内置—— 公司想用自己的 sum 时必须能压过内置表。把配置排在后面， 功能"看起来实现了却不生效"。

6.4 覆盖必须可审计

{"overrides": {
  "OP-SUM": {"c": "hw_dsp_sum", "why": "公司 DSP 库有专用归约指令，快 4~6 倍"}
}}

why 必填，缺失即判文件不合法。理由：半年后有人看到 sum 变成了 hw_dsp_sum，没有一行说明他就只能猜——而猜错的代价是换掉整个算子语义。

08已知缺口与落地路线

8.1 缺口（不假装覆盖）

缺口后果状态
无数据流（读写关系）段分配只能按大小猜，中小数组全落错段未做
emit.rs 未接 profile"自由转换"差最后一环；生成器不询问变体未做
段属性注入生成的 C 没有 section / align未做
weak 桩比例守卫大量 stub 会让 C 编译通过但什么都不做未做
DMA / .ld / Log 环形缓冲方案提到的下游能力未做

最危险的一条是"weak 桩"。若 100 个函数里 60 个变成 stub， 生成的 C 编译通过、运行不报错、但什么都不做——这是静默降级。 必须加一条桩比例上限（如 >10% 即红），和本仓 check_ane 对 except: pass 立基线是同一个思路。

8.2 落地顺序（按依赖，不按模块编号）

① profile + 段预算校验        ✅ 已完成（自证 6/6）
② 算子变体 + 外部覆盖         ✅ 已完成（自证 5/5 + 手工验证覆盖）
③ 小脑/大脑适配器             ✅ 已完成（自证 3/3）
④ 数据流（读写关系）          ❌ ④⑤⑥ 的共同前置
⑤ emit.rs 接 profile          ❌ 依赖 ④
⑥ 段属性 + .ld + glue         ❌ 依赖 ⑤
⑦ Log 环形缓冲 / weak 桩      ⏳ 与 ④⑤⑥ 独立，可并行
⑧ 桩比例守卫                  ⏳ 与 ⑦ 同时做

④ 是所有后续的共同前置。没有读写关系，"哪个数组该进 TCM"只能按大小猜—— 而按大小猜会让大矩阵全进 DDR、小数组全进 TCM，看起来对，实际把高频小数组放到了最慢的地方。

09设计原则（可复用的判断方法）

口径不可配，参数全可配

段容量、ISA 顺序、映射覆盖都是参数；字节数算法与"形状未知不计入"是口径。口径也配，就没有判据了。

自证要测"本该做到什么"

只测"跑起来不出错"不够——优先级写反的实现照样能输出一张看着正常的表。

用结构不同的配置验证可配置

第一份配置往往照着代码写，结构上必然通过。换 2 段→3 段才测出中间段恒为 0。

"不比"和"跳过"都要说出来

静默的"没判"与"判了且通过"在输出上一模一样，失效时无从分辨。

覆盖必须写为什么

没有理由的覆盖，半年后没人敢动，也没人敢删。

跨项目接口只交付纯数据

合并前后都不需要改的接口，只能是不含策略的数据结构。
