03关键发现

  • 修复前：0/300（全 0），根因是生成器写了 y = zeros(1);，zeros 未映射导致解析在该行断掉、后续语句被吞。
  • 修复后：① 96/120 = 80% 进 MIR。
  • ② 32/120 = 26.7% 生成 C —— 这是整条链路唯一的损失点（96 → 32，丢 64 个）。
  • ③ 32/32 = 100%：凡是生成出来的 C，全部编译通过并跑对。也就是说 C 生成之后的环节没有质量问题。
  • 结论：当前瓶颈 100% 在「MIR → C」这一段，不在解析、不在编译、不在运行。

04诚实边界

这是 120 个合成用例的结果，不是 333 万个全跑。333 万个 × 3 阶段 = 1000 万次是用例池容量，不是已执行次数；全跑按每文件约 1 秒估算需要约 38 天。合成用例只覆盖 add/sub/mul/div/sum/mean/max/min/abs/sqrt/matmul/hcat/index 十三个算子，不代表真实工程语料。
