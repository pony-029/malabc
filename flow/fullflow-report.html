03关键发现

  • 两轮独立抽样给出几乎相同的比例：600 个 -> 100% / 94.0% / 74.5%；1200 个 -> 100% / 93.5% / 74.25%。样本翻倍、场景组合翻倍，三个比例的变化都在 0.5 个百分点内。
  • ① 解析零未映射 = 100%（两轮都是）：这是前几轮修掉 __k%d 保留名冲突与矩阵字面量之后的稳定结果。
  • ② 生成 C ≈ 93.5~94%：约 6% 在 m2c 这一步失败。
  • ③ 编译运行 ≈ 74%：这一段掉了近 20 个百分点，是当前最大损失点。已定位到具体机制：emit.rs 把返回值 y 初始化成0 元素（(int64_t[]){0}），依赖 mlc_op_* 就地扩容；对二维数组这会导致越界写（0xC0000374 堆损坏）。
  • 链路形状：100% → 93.5% → 74.25%，损失集中在最后一段。

04诚实边界

这是 1200 个合成用例的结果，不是 333 万全跑。3333334 × 3 = 10,000,002 次是用例池容量，不是已执行次数（全跑按 0.6 秒/文件约需 23 天）。合成用例只覆盖 13 个算子、7 种形状，不代表真实工程语料——真实对照：yalmip 全量降级率 16.2%、matpower 三段全通 0/120。另：两轮都是按生成顺序取前 N 个，仍偏向 early 的简单算子；但因为 variants 从 4 提到 8，第二轮的组合覆盖比第一轮宽。
