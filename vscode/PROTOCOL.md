# 语言服务协议能力

本扩展以语言服务器方式接入编辑器，实现的标准方法与自定义方法如下。

**这份文档面向维护者**：读者关心的是「服务端实现了什么、编辑器侧怎么用」。
面向使用者的功能与操作说明在 `README.md`，两份文档职责不同，不要混写。

---

## 标准方法（Language Server Protocol）

| 方法 | 用途 | 使用者的感知 |
| --- | --- | --- |
| `textDocument/documentSymbol` | 符号大纲 | `Ctrl+Shift+O` 查看文件内的函数 |
| `textDocument/definition` | 转到定义 | `F12` |
| `textDocument/references` | 查找引用 | `Shift+F12` |
| `textDocument/hover` | 悬停说明 | 鼠标停在标识符上 |
| `textDocument/codeLens` | 调用规模标注 | 函数定义行上方的调用者/被调用数量 |

## 自定义方法

| 方法 | 用途 |
| --- | --- |
| `matlabc/impact` | 返回目标函数的上下游、来路（含调用发生行）与未解析计数 |
| `matlabc/heat` | 返回按「复杂度 × 调用者数」排序的热点函数列表 |
| `matlabc/field` | 结构体字段的跨文件读写位置（按基名归类） |
| `matlabc/cbridge` | 跨语言桥接：MATLAB 未解析调用在 C 源里的定义位置 |

## 与编辑器侧的分工

- 服务端只负责**计算**，不持有界面状态
- 侧栏「关系」面板由扩展侧发起 `matlabc/impact` 并按结果渲染
- 分析结果首次计算后缓存到工程目录下的隐藏文件，后续请求直接复用
- 分析尚未完成时，请求返回「进行中」标记而不是空结果 —— 空结果会被界面读成「没有」

## 维护约定

**新增或修改 `textDocument/*` 方法时，必须同步更新上表**。
`tools/check_lsp_doc_parity.py` 会做双向核对：代码里有、表里没有会失败；
表里写了、代码里没有也会失败。

**这份文档不写实现细节**（函数名、缓存结构、算法），只写「对外承诺的接口」。
