# matlabc

MATLAB 工程的代码理解工具。

**不运行 MATLAB，不修改你的代码，装上就能用，全程离线。**

---

## 它解决什么问题

接手一个几十上百个文件的 MATLAB 工程时，通常只能靠搜索和记忆：

- 这个函数是谁在调用？
- 改这里会影响哪些地方？
- 这个结构体字段在哪些文件里被写、被读？
- 这个变量是在哪里定义的？
- 一份代码里，先看哪几个函数？

本扩展把这些问题的答案放到编辑器里，**不用离开代码**。

---

## 功能

| 功能 | 你能做什么 |
| --- | --- |
| **转到定义** | 光标停在函数、局部函数、类方法、结构体成员（`s.field`）、结构体变量（`s`）上，按 `F12` 直接跳过去 |
| **关系侧栏** | 光标停在一个名字上，右侧「关系」面板立刻显示它被谁调用、它调用了谁 |
| **调用链** | 从目标函数一路追溯到你工程的入口，每一跳都标出所在文件与行号 |
| **影响面** | 改代码前先看上游：谁依赖它、有几条来路 |
| **全局变量** | 区分「定义」「声明」「使用」三类，并列出分布在哪些文件 |
| **结构体字段** | 按变量名分组，显示字段在哪些位置被写入、哪些位置被读取 |
| **符号大纲** | 按文件列出全部函数，快速跳转 |
| **调用规模标注** | 每个函数上方直接标出调用者数量、被调用数量、圈复杂度 |
| **热点排行** | 按「复杂度 × 调用者数」排序，回答「先看哪几个函数」 |
| **结构感知诊断** | 缺文档、未初始化读取、死代码等问题，打开文件即在编辑器里标出 |
| **语义高亮** | 参数、局部变量、函数、字段、全局变量、内置函数分别着色 |
| **保存即刷新** | 保存后自动只重算改动的文件，不会卡住编辑器 |
| **HTML 分析报告** | 一条命令生成整份报告，浏览器打开即可阅读、打印、转发 |

## 怎么用

### 最常用的五件事

| 想做什么 | 操作 |
| --- | --- |
| 看某个名字定义在哪 | 光标停在它上面，按 `F12` |
| 看谁用了它 | `Shift+F12` |
| **看它的上下游** | **光标停在它上面，右侧「关系」面板自动更新** |
| 看这个文件里有什么 | `Ctrl+Shift+O` |
| 看它有多少调用者 | 看函数定义行上方的数字标注 |

### 「关系」面板在哪

打开任意 `.m` 文件后，左侧资源管理器下方会出现 **「关系」** 面板。

- 光标停在一个**函数名**上 → 显示「上游（谁调用它）」与「下游（它调用什么）」
- 光标停在一个**变量或字段**上 → 显示「声明」与「本文出现」的位置
- 点面板里的任意一行 → 编辑器跳到对应的**调用发生的那一行**

### 命令面板里的四个命令

按 `Ctrl+Shift+P`，输入 `matlabc`：

| 命令 | 作用 |
| --- | --- |
| `matlabc: 热点函数排行` | 全工程按「复杂度 × 调用者数」排出一张榜，选中即跳转 |
| `matlabc: 热点函数排行（当前目录）` | 只看当前目录 —— 跨模块的分数没有可比性 |
| `matlabc: 生成 HTML 分析报告` | 生成整份报告并在浏览器打开 |
| `matlabc: 生成 MCP 配置（给 AI 客户端）` | 需要让 AI 助手读你的工程时使用 |

## 安装（离线包）

1. 拿到 `matlabc-<版本号>.vsix` 文件
2. 打开 VS Code → 左侧「扩展」→ 右上角 `…` → **从 VSIX 安装**
3. 安装完成后，按 `Ctrl+Shift+P` → 输入 **Reload Window** 并回车
4. 打开任意 `.m` 文件即可

> **装完必须重载窗口**，否则编辑器仍在运行旧的扩展进程，看到的是修复前的行为。

---

## 第一次使用，建议按这个顺序

1. 打开工程里一个 **`.m` 文件**，按 `Ctrl+Shift+O` —— 先看它有哪些函数
2. 把光标停在**某个函数名**上，看右侧「关系」面板 —— 观察它的上下游
3. 按 `F12` 跳到它的定义
4. 点函数定义行上方的**调用计数**，选「预览调用关系图」
5. 命令面板执行 `matlabc: 热点函数排行` —— 决定接下来读哪几个函数

## 常见问题

**打开大工程后，几分钟内没有反应？**
首次打开需要为整个工程建立索引，文件越多越久。索引建好后不会再重复，之后都是秒级。

**「关系」面板是空的？**
把光标**停在代码里的名字中间**（不要停在整行选中的状态，也不要停在注释里）。注释里的文字不会被当成代码。

**大纲是空的？**
确认扩展已启用，并重载过窗口。若仍为空，换一个 `.m` 文件试试。

**看不到函数上方的调用计数？**
需要等索引建立完成。也可以先保存一次文件。

**同一个名字在多函数文件里为什么被分成几组？**
MATLAB 没有块级作用域 —— `if` / `for` 里定义的变量，是整个函数共用的；
但**函数才是作用域边界**：同一个 `.m` 文件里的主函数与局部函数，各自的 `x`
是两个不同的变量。所以关系面板在**单函数内合并**显示，跨函数时分组，
并标注「同名但不同变量」。

**诊断标记太多？**
可以按 `Ctrl+,` 打开设置，搜索 `matlabc`，关掉不需要的检查项。

**能不能分析 `.mlx` 或 Simulink 模型？**
当前只处理纯文本 `.m` 文件。

## 给 AI 助手用（MCP）

扩展同时提供一个 MCP 服务，AI 助手可以直接调用它的分析能力。

配置方式：命令面板 → **`matlabc: 生成 MCP 配置（给 AI 客户端）`**，
按提示写入配置文件，或复制到剪贴板贴进客户端。

**只需要模型的连接信息，不需要再单独装什么。**

### 只读工具（13 个）—— AI 能查什么

| 工具 | 回答 |
| --- | --- |
| `matlabc_help` | 当前有哪些工具、怎么问最有效 |
| `matlabc_stats` | 工程规模：文件、函数、调用边、最复杂的几个 |
| `matlabc_outline` | 一个文件里有哪些函数、各在第几行 |
| `matlabc_search` | 名字记不全时按子串找 |
| `matlabc_explain` | 函数速览：角色、改动风险、从哪看起 |
| `matlabc_impact` | 谁调用它（含完整来路）、它调用谁、多少处解析不到 |
| `matlabc_heat` | 按「复杂度 × 调用者数」排前面的是谁 |
| `matlabc_changed` | 改了这几个文件，谁需要先回归 |
| `matlabc_definition` | 某个位置指向哪里 |
| `matlabc_references` | 被谁引用；全局变量分定义/声明/使用 |
| `matlabc_fields` | 字段的跨文件读写位置，按变量名分组 |
| `matlabc_cbridge` | 解析不到的调用落到哪：C 源定义位置、`mex` 二进制、或 `calllib` 的库导出表核对（每条都标注证据来源） |
| `matlabc_diagnostics` | 工程体检：未初始化、未使用等（首次较慢） |

### 写工具（3 个）—— AI 改代码时走三步

| 工具 | 作用 |
| --- | --- |
| `matlabc_propose_edit` | 只算改动内容，**不写入**，先给人看 |
| `matlabc_apply_edit` | 确认后才写入，写前自动备份 |
| `matlabc_undo_edit` | 从备份恢复 |

### 批量写（3 个）—— 一次改多个文件

| 工具 | 作用 |
| --- | --- |
| `matlabc_propose_edits` | 一次算多个文件，任何一条不合格则整批不生成 |
| `matlabc_apply_edits` | 全部校验 → 全部备份 → 逐个写，失败自动回滚 |
| `matlabc_undo_edits` | 整批恢复 |

**核心保证：要么全改，要么一个都不改。** 不会出现“改了三个、第四个失败”的半成品状态。

## 设置

| 设置项 | 默认 | 什么时候需要改 |
| --- | --- | --- |
| `matlabc.pythonPath` | `python` | 系统里装了多个 Python、或 `python` 命令不可用时，填绝对路径 |
| `matlabc.crossLanguage` | `true` | 是否扫描工程内的 C/C++ 源与 mex/DLL，把解析不到的调用接到实现上；关掉可省 IO |
| `matlabc.docLang` | `both` | 想让内置函数说明只显示中文或只显示英文时 |

其余设置一般不需要改动。

---

## 已知边界

- 只分析静态代码，**不执行** MATLAB，因此无法推断运行时才确定的值
- 动态调用（`feval`、字符串拼出的函数名）无法跟踪，会单独计数提示
- 超大工程（数千文件）首次索引较慢，属于一次性成本
- 不支持 `.mlx`、`.mat`、Simulink 模型文件
